## 2. 视觉和交互原则

页面必须围绕“用户先看懂什么、点哪里继续”组织。统一视觉令牌和组件，不靠每个模块各加一层大圆角面板。每个首页只有一个主要视觉和少量必要摘要；有内容的对象直接可点，操作出现在对应对象详情。

- 排版：清楚的标题、主数值、说明三级；金额使用等宽数字，币种/单位可见；间距按现有令牌收敛到 8/12/16/24 等一致节奏。
- 标准字号正文约 15–16px，行高约 1.5；不靠缩小字号挤满长文。关怀大字模式允许增高和合理换行。
- 默认浅色/深色保持统一。颜色体现类别、盈亏和状态，同时保留文字、符号和单位；不要把青蓝色边框等同于“金融专业感”。
- 普通查询结果：简短结论 + 一个受信展示 + 就近明细。重要业务限制/待确认条件保留可见，计算细节和来源按需展开。
- 新交互基于“点选对象 → 关联高亮 → 就近详情 → 可编辑追问 → 必要时明确确认”。滑动、动画、鼠标悬停只用于浏览；不能触发资金操作、自动提问或自动保存正式记忆。
- 触摸目标约 44px；键盘、焦点、关闭、低动态、390px 窄屏可用。选中态有一致样式，不用随机黑边/绿边。
- 不新建 WebGL 大动画、平行账本、画像库、目标库、回复协议或路由。复用既有服务、NavrenViews、FinancialMetric、navren.presentation/1 和审核边界。

## 3. 对话：这条“可投资资金”必须真正图文结合

### 3.1 默认显示

该问题采用“资金拆解卡”，不是继续输出四段长文。以下只示意截图中这一结果的阅读顺序，不重算金额、不规定所有账户返回同一数值：

> 目前可安排 **10,276 元**。先留好应急资金和近期付款，再决定怎么用。
>
> 资金拆解：已结算现金 → 应急保留 → 近期付款/已生效预留 → 可安排资金。
>
> 30 天内已知付款：显示总额和事项数量，点击进入同范围完整明细。
>
> 底部：查看资金依据 ｜ 收藏 ｜ 朗读

- 主数值、每个拆解项、范围、规则模式、币种和时点全部来自同一服务计算与审核投影，UI 不做减法、不造比例。
- 可采用横向瀑布/阶梯图或紧凑条形结构；只有服务提供受信拆解和几何依据时才画长度。缺比例则先用金额块与明确箭头，不临时拿总额做分母。
- 备用账户/其他账户用受信对象行展开；锁定本金、待到账款、信用额度单独标明状态。到期不等于已到账，信用额度不计现金。
- 展示中重要范围与模拟身份用短标签，不输出“后端精确计算，不是简单减一减”之类工程解释。
- 资金口径摘要必须说明整体/分账户保留规则。截图账户首页 11,776 与对话 10,276 是否来自不同规则，由 Finance/Base 核实；不能简单选一个覆盖另一个。相同规则与时点应一致，不同规则必须直观可解释并能回查。
- 默认文字目标约 80–120 字，先回答问题。该目标不允许硬截重要条件。必要条件过多时分层；草稿核对和异常解释可更长。
- 保留完整的审核证据、所有资金条件、金额位置和限制在依据面板；缩短的是默认阅读负担，不能把安全字段删出协议。
- 普通理财浏览结果不能标“已独立校验”除非该结果有真正审核回执；审核待接线/失败就给准确状态。

### 3.2 模板选择与真实接线

- 现有日卡/月格/柱图/折线图继续使用；新增加资金拆解视图，复用当前 funds.current_budget 与原计算，不另建预算方法。
- 一周/短日期范围按日卡；一个月月历或受信柱图；多月/多年时间图；构成问题仅在非负、明确分母和完整覆盖合格时用饼/环图。未知不补零。
- 明确响应仅有一个正式结构：presentation 与 metric_batch 的位置/形状由 Base/Agent/UI共同确认，在一个边界适配；禁止三方各猜一次。
- 页面、回复正文、图、语音、建议和历史存储绑定同一身份、版本、语言、范围、审核回执。下钻必须重发行相应范围，并原子替换已核验正文/图；不能只换图不换结论。
- 图形点选打开真实对象详情或生成可编辑追问；未确认不创建业务草稿，不自动发模型请求。
- 原 24 个金额位置门保留；展示占用按实际注册投影验收，不能为塞更多金额静默扩容。

### 3.3 工具行和建议问题

- 桌面标准字号，详情链接在左、收藏和朗读在右，三者同一条水平工具行；正常文档流，无绝对定位，无巨大底部留白。窄屏优先短标签/图标，极小屏或大字号允许合理换行。
- 普通查询使用“查看资金依据/明细”，不要强塞无关的“查看账户与操作记录”。执行回执才提供同一操作记录。
- 建议问题放在最新完成的主回复后，默认 2 条简短可点的自然问题；能力满足且已有 3 条合同则兼容，不制造一墙按钮。不是收藏/语音工具按钮。
- 保存建议描述符和主回复 ID，不把 HTML 当权威状态。跨页、刷新、前进后退重新按当前身份、授权和工具可用性校验；同账号且有效则恢复，不能永远删除。
- 示例建议只在真实工具可用时出现：“看看未来30天的付款”“这笔钱怎么安排？”点击可编辑草稿；执行意图仍要本人发送和确认。
- 账号切换、授权撤回、范围失效时不恢复旧建议；给紧凑准确状态，不以持久化为由复活旧签名。
- 历史图表也要恢复：当前 IA 候选保存时删除主展示，仅保留文字，没有 presentation/message_state/receipt 描述符和回查路径。Base 保存或定位已审核原件，UI 在当前身份/来源/语言核验后恢复只读历史组件，并标原日期。历史读取与重新查询当前数据分开，旧批准不能重新签成当前结论。
- 普通知识回答的建议允许没有 view_id；使用独立只读历史合同核验，不能强求每个建议都关联金融图表，也不能凭缓存恢复审核状态。
- 验收必须覆盖“对话 → 账户/发现/我的 → 返回对话”，不能只在第一次新回复下检查。

## 4. 账户首页：从混合清单改成财务概览

### 4.1 页面结构

1. 头部轻量展示当前账户身份、参考时点和来源，首屏不留大段空白。
2. 主摘要保留账本资产/负债/可安排资金，名称准确；主视觉用服务已发行的资产构成条或分类金额。缺估值时写“账本资产（本金）”，净资产未覆盖则不显示伪完整财富数字。
3. 资产分现金、投资；负债单独一组。主视觉点击分类直接定位对象，不再把借记卡、信用卡、存款和贷款混列为“资金9项”。
4. 近期安排只显示最需关注的 2–3 个具体日期事项，状态只出现一次；已确认、候选、待核实可辨。入口进入完整财务日历并保留筛选。
5. 银行卡使用有真实对象内容的小型卡面预览，可进入银行卡详情；不抢占资产首屏，也不重复计金额。
6. 持仓收益有资格时提供一个受信趋势/金额入口；资料不足时明确缺项，不能把净值涨幅冒充本人收益。全部资产/负债/卡片/流水通过归属入口展开，不恢复旧按钮墙。

桌面可用主视觉左、近期安排右的平衡布局；移动按摘要 → 资产结构 → 近期事项顺序。取消同一整卡里连续重复“有效/待核实”，金额、标题、状态对齐。

### 4.2 银行卡设计

- 卡面接近实体卡比例约 1.6:1；克制的渐变、细纹理、轻阴影，不铺大幅照片和无意义亮光。
- 只显示来源可信的发卡行/演示机构名、卡类型、脱敏尾号与状态。无可信尾号不制造完整卡号，不造 CVV、银行卡网络 Logo、发卡/银行合作暗示。
- 借记卡展示关联账户，信用卡展示本期待还/可用额度；额度明确不是资产。卡面与账户余额不是两份钱。
- 点击整张卡进入就近详情，展示账单、关联账户和本卡可用操作。挂失、解挂、还款走现有核对确认链。
- 卡片滑动只浏览；不设计“翻面显示敏感信息”或划一下付款。低动态与键盘可替代。
- 参考的是银行产品的对象进入和层级模式，不宣称复制官方 App 当前实机画面。Navren 自行设计品牌外观。

参考：[DBS 收支分析](https://www.dbs.com.sg/personal/articles/nav/financial-planning/track-your-saving-and-spending-with-NAV-planner)支持收支对照与分类下钻；[DBS 组合说明](https://www.dbs.com.sg/ibanking/pdf/faq-retail.pdf)支持组合概览、配置/持仓与交易记录分层。本轮采用阅读组织，不把来源产品表现或建议移植给用户。

## 5. 我的：个人账户资料正式归位

我的首页顶部是当前登录/选中的账户资料摘要，四种演示账户的稳定身份与可编辑显示名分开。保留目标/四领域图谱/收藏入口，不把这里又扩成多个无关领域。

### 5.1 资料管理

“账户资料”入口集中三组内容：

| 组 | 内容 | 来源与编辑边界 |
| --- | --- | --- |
| 账户资料 | 稳定演示身份、头像/显示名、来源、实际数据覆盖与参考日 | 身份/合成来源只读；头像昵称按当前工作区绑定；未知生日/联系方式保持未知 |
| 资金与风险条件 | 现有风险等级、期限、应急保留等业务条件 | 非正式银行测评；沿用本人确认，增加旧版本比较和变更预览 |
| 偏好与授权 | 本人已确认陈述、金融兴趣/认知、记忆读取状态 | 复用现有个人资料与记忆服务；能看来源、确认/改正/删除，不静默推断成事实 |

- 从设置移入头像/昵称/账户身份与账户切换，移除设置中的重复“本机身份与视角”大卡；顾问演示视角不作为普通个人资料项。
- 选择既有演示账户使用已完成目录与真实选择链，不继续调用 session/reset 当作“切号”。退出登录接真实认证退出，不能只 toast。
- 全局 qingzhou_userInfo 和 assembleProfile 旧值不自动映射给所选人物；绑定 account/workspace/privacy_revision 后才用。业务姓名不授权工作区。
- 头像/昵称如果跨浏览器保存，由 Base 扩展既有个人资料允许字段和版本；设备显示偏好可本地保存并标明范围，不能另建画像库。
- 风险/资金保存检查 expected_version。跨标签页、旧页面、账号切换后的迟到请求不得覆盖新条件；失败保留用户编辑草稿并说明需重新核对。
- 欢迎认证身份与当前业务账户身份由欢迎 owner + Base 明确同步协议。欢迎视觉不重做，避免身份文字互相矛盾。
- 长期目标继续使用 GoalService；目标金额不代表冻结现金。四领域图谱不重复维护资料或账本。

## 6. 设置：分组明确、紧凑、看得见改动

设置是应用辅助入口，不承担个人账户名片和资金条件。保留现有可用能力，不为简化直接删掉关怀/青春模式。

### 6.1 页面布局

正文宽度收敛，采用 3 组短标题与设置行；不把每个选项都画成 150px 高的大卡：

1. **外观与阅读**：主题/界面模式、语言、字号。名称在左，当前选项与控件在右；模式用紧凑分段选择或单选列表。
2. **声音与提醒**：自动朗读开关、当前音色。选音色展开紧凑列表；只保留当前音色的明确试听操作，不把三张巨型声音卡常驻首屏。
3. **隐私与数据**：实际可用的读取授权、存储范围和数据管理入口。资料编辑归“我的”；授权在此设置、在“我的”显示同一服务状态，不产生第二个独立开关。

桌面可在外观组旁放小型阅读预览（示意文本，不用真实资金数据）；窄屏预览就近展开。选择字号/主题应当看得见效果，但不播放大动画。空态和不可用选项明确显示，不造通知、导出或删除功能。

### 6.2 细节与行为

- 所有选项使用统一 selected/disabled/focus 样式，选中态不是随机粗黑边。
- 字号、主题、声音偏好与记忆授权注明“本设备/当前账户”等实际作用范围；不是每行都加一段重复小字。
- 必要说明放问号/短弹层；授权后果、自动朗读和删除等重要边界就近可见。
- 试听只在用户点击时调用既有允许路线；不因进入设置触发新的收费请求。无预置样音或可用语音服务时给准确状态。
- 开关保存期间禁重复操作，失败回显真实服务状态；退出/换号后停用旧账户的请求和预览。
- 中英、深浅色、关怀大字均覆盖；不会先中文闪一下再变英文。

## 7. 热点与周报：封面流保留，内容和运行链补齐

### 7.1 真实日版

- 首页只展示某一明确日版最多 6 项，不把不带版次的旧全集合叫“今日精选”。不足 6 项展示真实数量；0 项紧凑空态。
- 明确版次日期/revision、北京时间和来源日期。今天未更新可显示最近已发布日版并标出实际日期；无档、更新中、部分失败与服务失败分别说明。
- 当前运行接口旧包已有实测证据。由实际市场 owner 核对 server 加载合同与日版发行，再按既有发布合同交接；根因未定位前不靠刷新缓存、重启或新抓取掩盖。
- 近 30 天历史按日期/类型选择，历史入口保持在轮播分页水平右侧；历史版本不可被最新摘要偷偷替换。
- “每天最热”需要既有可解释排序依据，来源权威不等于事件热度；无法核实最热则准确称“每日精选”，不得发明热度数值。

### 7.2 内容与视觉

- 中央卡：分类 + 来源/日期 → 简短可读标题（通常 2 行） → 一个核实事实或一句要点 → 紧凑原文/解读入口。
- 标准桌面中央卡参考宽 520–620px、高 300–360px；整体组参考高约 380–440px，最终以长标题/大字/窄屏验证，不强裁内容。不是一张长文章壳。
- 左右卡以可识别封面参与切换，至少看清短标题和来源；露出约 160–220px 作为初始几何目标，侧卡 3 行左右预览，避免 148px 全标题窄柱。缩放、位移、层级与主卡连续关联。
- 真正支持鼠标/触摸左右拖动、侧卡点击、键盘与低动态；首尾处理明确，无自动播放。0/1/2 项不伪造邻卡。
- 类型颜色克制区分主题，主标题对比够，卡背景与正文色匹配；不是所有卡同一个浅蓝大面板。
- 事件/文章/内容版本一致的审核短稿才能展示；新事件必须进入短稿合同。缺短稿时展示来源原标题与“阅读原文”，限制封面标题的阅读行数可查看完整原题，但不能把截断摘要冒充完整解释。
- 数字必须来源可核实，条件/适用范围不靠截字省略。已修订标识只说明事件版本，不能代替短稿审核状态。
- 周报首页仅放紧凑封面、周次、短标题、2–3 个要点及阅读入口；完整解释在详情中。空周报不占巨型卡，历史修订保持可定位。

## 8. 比赛展示：技术必须能被实际操作看见

设计约三分钟可重复任务链：选择种粮大户 → “我的”核对资料/来源覆盖 → 账户图形下钻 → 问未来30天可安排资金 → 点具体日/事项看依据 → 换A市首富问同题观察数据差异 → 查看一条规则拒绝/允许草稿 → 本人确认一笔已验收模拟操作并看真实回执。

- 这条链使用实际已验收能力；数据覆盖、个人收益、实时来源、审核、Agent协作尚未通过的内容不能靠动画表现成完成。
- 结果旁“查看依据”展示来源和时点、计算口径、本人条件、规则/真实审核状态、同一操作回执。UI 控制阅读密度，不把调试日志/原始提示词放进首页。
- 提供可定位的数据版本与可重复证据；回放演示明确标记，与实时调用成绩分开。
- 演示导航可帮助定位，但不改变身份、审核、资金或确认边界；无比赛专用绕过。
- 不承诺奖项，不捏造比赛评分标准；基本功由财务一致、数据隔离、来源可查、缺项诚实、确认前零执行体现。

## 10. 本轮联合验收与完成条件

桌面 1440×900，移动390×844；补一轮用户当前桌面宽度与标准字号。关怀大字允许必要换行，不强迫保持一条超窄行。

1. **消息资金**：真实同范围服务结果生成资金展示与自然短结论；核对所有金额/规则/来源/缺项、正文与图一致，普通查询三工具同排、卡尾无大空白。
2. **消息返回**：已有主回复 → 账户/发现/我的 → 返回、刷新、前进后退，建议重新验证后恢复且仍归主回复；同账号有效、换号失效、授权变更、迟到响应和无桥失败分别验证。
3. **可视化下钻**：资金/日卡/柱/折线各已有真实合同样例，点对象/日 → 明细分页 → 返回父范围；未知≠0，不能保留旧正文配新图；资金图不靠前端相减。
4. **账户首页**：现金/投资/负债分开；卡附属不重复；账户首页与对话同规则结果一致，不同规则明确；完整列表/日历往返保留位置。适用的新标签“经济净消费”增加专门断言。
5. **账户资料**：四选一 → 当前资料 → A切B → 返回A，姓名头像陈述/条件不串号；跨标签/旧编辑版本拒绝，真正退出阻止旧请求；身份资料不再属于设置。
6. **设置**：3组紧凑行、选中态/预览一致；语言无闪烁，字号/主题/音色/授权范围真实；失败回显，试听用户主动；大字/窄屏无溢出或控件遮挡。
7. **市场**：实际接口有日版身份且每日上限6；0/1/2/5/6各检查，缺短稿与版本失效清楚；左右拖动/邻卡点击及键盘、近30日日期+类型、指定原文、周报版本/返回原卡。归档缺日不填造。
8. **比赛任务链**：只有已经接线验收的步骤参与3分钟流程；确认前零金融写入，确认后真回执，重放不追加；缺少能力就标为未完成。

每项交付包含输入hash、候选manifest、真实wire样例、检查命令/退出码、屏幕截图/viewport和实际未解决项。夹具、浏览器展示、真实链路、运行页更新分开报告。保留旧六项 exit1 并归因，不改预期遮掩回归。

完成必须同时满足：候选实现、实际接口一致、联合验证、按原发布合同到达用户运行页。仅打开18767旧页面、HTTP200、源码修改、模型审过计划均不算完成。本规划窗口将追踪收口，不要求用户逐条转发。

## 11. 用户最新要求：按页面逐一收口

用户明确要求“一页一页修改，不符合逻辑的慢慢处理”，并希望数小时后看到高完成度。这个要求调整实施节奏，不撤销此前业务任务，不以时间到达替代验证。

| 顺序 | 页面 | 该页收口必须可见 |
| --- | --- | --- |
| 1 | 对话 | 可投资资金有真正图文、短结论、统一工具行；跨页返回/刷新建议和可用历史图能恢复；协议与真实审核接线闭合 |
| 2 | 账户 | 资产主视觉、现金/投资/负债归组、银行卡对象、近期事项、资金口径；消除混排和重复状态 |
| 3 | 我的 | 当前账户资料归位、切号/退出真实有效、条件和偏好有来源，头像/陈述隔离 |
| 4 | 设置 | 紧凑三组设置、选中态/预览/字号/语言/语音一致，作用范围清楚 |
| 5 | 发现 | 正确日版、短卡封面流和紧凑周报、历史筛选/原文/返回闭环 |

- UI 一次推进一个主页面，形成“问题清单 → 精确候选 → 实屏复核 → 该页报告”后进入下一页；仅因该页业务桥暂缺时，明确缺口并完成可独立验证的视觉部分，不把该页标完成，随后可推进下一页独立部分。
- Base/Agent/RAG/Finance 接口修复并行；实际 owner 协商不中断原 G1/G2 修复。集成按页面递增验证，不要求等五页全完才发现第一处问题。
- 每页报告列用户当前运行页、候选版本、已经可见/仍缺什么、问题对应 owner、下一个动作。旧版本未放行发布时不得打开旧页称“新UI展示”。
- 共享组件在第一页面建立后复用。标准桌面无溢出、关键结论首屏可见、金额与状态对齐、控件不浪费大块区域、返回不丢有效状态，是最低阅读要求。
- 每页将成功、空态、失败、加载、长文字、换账号和中文/英文纳入实际适用检查；控件精简不能把错误反馈删除。
