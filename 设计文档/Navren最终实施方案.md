# Navren 最终实施方案

日期：2026-10-04。本文件记录本轮确定的实施范围、落地顺序、实际交付边界与验收证据；状态不代表比赛得分或真实银行服务效果。其他创意文档保留为备选。

## 产品定位与范围

Navren 是能理解用户长期需求、代表用户准备银行业务方案，并让用户掌握最终决定权的金融助手。目标是有证据、有规则、有确认边界的动态多智能体工作流。

必须完成六项业务：智能转账、账单分析、理财操作、卡片管理、订阅/代扣、跨场景联动。六项是能力目录，Agent 数量由任务需要决定。

个人记忆层覆盖消费习惯摘要、财务目标、资金承诺、知识兴趣、产品兴趣与说明偏好。用户可查看、纠正、删除、关闭；记忆注明来源、时间、是否明确确认与有效期。正式风险测评和银行账户事实保持独立，不由推断画像替代。

额外服务亮点只选一条：**用户利益代理与银行服务协商**。用户表达条件与底线，用户代理提出要求，银行代理从预先批准的费用减免/服务优惠菜单中形成可行方案，独立审核核对依据与条件，用户接受后才准备对应申请。首版限模拟银行费用与服务优惠，不扩展到贷款议价、外部商家或真实签约。

该服务需要新增明确标记为合成数据的活动规则、有效期、资格条件、优惠成本、适用对象和申请状态，不能声称现有模拟档案已经包含全部协商数据。优惠与资格必须由规则代码核验，模型不得发明政策。

演示示例：用户愿意迁入工资账户，但不接受购买理财作为优惠条件。系统结合用户授权的记忆与账户证据，提出两种银行允许的服务安排；用户修改条件后重新计算；无可行方案时明确说明。最终展示具体代价、条件、期限、申请状态和模拟回执。

家庭协商、照护接力、隐私证明、平行生活试验场不进入本轮主线，不同时建设。新增服务属于设计增量，未证明行业首创或经营效果。

交互同时支持文字与语音：语音输入经流式识别形成可见文本后，复用同一聊天工作流；回复文字先在对话中展示，并按用户设置用流式语音播报。录音和播报均可取消；麦克风使用浏览器权限，百炼密钥只保存在服务端。

## 工作流与模型分工

用户目标 → 模拟银行事实与获准记忆 → 动态任务图 → 按需调用能力 → 确定性校验 → 独立模型审核 → 依据与操作草案 → 用户确认 → 后端模拟执行 → 查询回执 → 获准的记忆更新。

- 主模型采用 DeepSeek-V4.1-Flash（DeepSeek API 模型 ID：`deepseek-flash`），承担目标理解、任务规划、领域分析和综合表达；通过独立上下文与工具权限形成不同角色，单个模型可以支撑多个 Agent。
- 审核模型采用 GLM-5.3-Flash，核对事实支持、遗漏条件、推荐冲突和越权；不能调用交易工具，不能覆盖代码规则的拒绝结论。
- 余额、金额、资格、适当性、权限、幂等与状态核验由代码和银行服务处理。主模型与审核模型均不持有用户确认、验证码或交易执行工具。
- 简单只读查询可以直接返回工具结果；综合建议、协商结果与操作草案须经独立审核。最多一次定向修订，仍不满足则澄清、阻断或转交。
- 审核接收可见证据、工具结果和草案，不接收模型隐藏推理。事实校验既核对证据 ID，也核对证据是否支持所述内容。
- 用户代理与银行代理分别使用自己的目标、授权数据与优惠权限。银行代理不能看到用户未允许披露的记忆；两者均不能修改真实优惠规则。
- 语音交互使用百炼 `qwen-audio-3.1-asr-flash-streaming` 与 `qwen-audio-3.1-tts-flash`。ASR 转写进入标准聊天入口，TTS 与屏幕文字共用同一回复内容；网页只拿一次性语音会话票据，不接触模型密钥。

## 模型接入顺序

### 第一交付：真实模型进入真实聊天

1. 增加可配置供应商适配层。主模型优先用 DeepSeek 官方接口的 `deepseek-flash`；审核模型用已配置 AI Ping 的 `GLM-5.3-Flash`。请求超时、有限重试、合同解析与回退状态明确区分。
2. 实现主模型的主管规划/综合适配器和 GLM 独立审核适配器，先替换现金流路径中的本地主管、审核器；账户查询、现金流计算和规则门继续复用现有代码。
3. 经现有 `/api/agent` 和实际聊天页打通完整通路。响应记录实际模型、阶段、审核结论、耗时和回退原因。不能只修改旧 `agent_core.py` 中的模型名，因为银行意图先由 `finance_agent` 分流。
4. 修正旧入口中模型失败却仍返回 `isFallback: False` 的状态问题。页面不得把离线模板或确定性输出标为外部模型协作。

这一步不等待六项全部迁移或完整知识图谱建成。

### 第二交付：六项能力统一进入编排

把六项读数、分析和准备操作能力接入统一目录；保留既有独立确认与执行接口。先确保每项正常路径和失败路径成立，再覆盖复合目标。避免并存两套互相绕过审核的银行聊天链路。

### 第三交付：个人记忆与唯一额外亮点

复用现有本地记忆存储，补齐来源/关系、相关片段检索、对话记忆候选和确认流程；纠正记忆后，依赖旧值的未执行草案需要失效并重新确认。随后建设银行服务协商的合成规则、双角色流程和结果卡。

### 已落地范围

- 真实 DeepSeek 主模型与 AI Ping GLM 独立审核器已接入资金时间轴聊天通路；模型适配层有 JSON 合同校验、超时/重试边界和只含脱敏元数据的调用日志。DeepSeek-V4.1-Flash 的 API 模型 ID 为 `deepseek-flash`，以 DeepSeek 官方模型说明为准；GLM-5.3-Flash 强制开启思考，审核请求设置 `reasoning_effort=low`、单次 40 秒超时、不自动重试，避免重复审核调用拉长等待。[DeepSeek 模型说明](https://api-docs.deepseek.com/zh-cn/news/news260910/)、[AI Ping GLM 参数说明](https://aiping.cn/docs/API/glm-series-params)
- 六项必做业务已进入同一 `WORKFLOW_CAPABILITIES` 目录，并由统一只读能力注册表提供账户、账单、产品、预算和现金流依据；写操作仍经独立的准备、确认、验证和账本回执接口。第七项服务协商明确标记为差异化能力，不混入六项必做范围。
- 个人记忆支持按模拟工作区隔离、显式授权后读取、来源/确认状态/有效期/关系记录、用户查看纠正删除与候选确认；默认关闭，不替代正式风险测评、账户事实或授信判断。
- 用户利益代理与模拟银行协商已使用版本化合成优惠规则；资格与优惠由代码核验，用户可控制有限记忆的披露并须明确接受方案，最终只生成模拟申请与回执。
- 前端文字/语音输入、文本展示与语音播报已接入同一聊天页；语音支持连接中、聆听、整理、播报状态及取消，个人设置控制自动朗读。

### 实际验收证据

- 本轮复核的自动化检查：Python `unittest` 173 项通过；Node.js 测试 5 项通过（含语音前端 4 项、API 响应归一化 1 项）；Python/JavaScript 语法检查与 `git diff --check` 通过。
- 本轮固定合成数据评测：财务集 12/12 场景通过（15 项唯一回归断言）；安全故障集 16/16 场景通过（26 项唯一回归断言）。报告写入 `/tmp/navren-financial-eval-20261004.json` 与 `/tmp/navren-security-eval-20261004.json`，未覆盖项目原有报告；两套集合都只验证预设模拟条件下的工程断言。
- 真实聊天页验收：在青春版发送“请展示未来30天资金时间轴”，实际完成 `supervisor.route`、`supervisor.synthesize` 与 `reviewer.review`。脱敏日志显示 DeepSeek 三阶段中的前两阶段分别为 1.346 秒、3.518 秒，GLM 审核为 2.385 秒；页面显示“独立复核通过 · 主模型 deepseek-flash · 综合 deepseek-flash · 复核 GLM-5.3-Flash”，并展示来源引用及按币种分开的资金时间轴。该请求是只读分析，页面账本版本仍为 1。
- 主模型合同错误、超时、审核失败等路径会隐藏未通过审核的金额、产品和操作草案；相关测试验证失败时不改变模拟账户。模型日志不保存密钥、提示词、答复正文或账户明细。
- 语音端到端复核：青春版页面成功调用真实百炼 TTS，生成 8 段、约 3.25 秒的语音；将这段模型音频通过隔离的虚拟麦克风流送入页面 ASR 后，真实流式识别得到“请展示未来30天资金时间轴。”，随后页面经 `/api/agent` 完成 DeepSeek 综合、GLM 独立复核和资金时间轴展示。回复 TTS 播报进入播放态并正常结束；浏览器控制台无错误。复核后模拟账户账本版本仍为 1、现金仍为 2,439,000 分、订单数为 0。

- 动态任务图和真实双模型复核目前在现金流/资金时间轴路径完成了真实端到端验收。其余五项仍通过统一业务目录、确定性银行规则和既有独立操作接口处理；它们具备测试覆盖，但当前不能表述为已全部由 DeepSeek 动态规划、GLM 逐项复核。

模型目录查询只是可用性检查；只有上面的实际生成调用与聊天页面结果才构成接入证据。模型命名依据：[DeepSeek 官方发布](https://api-docs.deepseek.com/zh-cn/news/news260910/)、[AI Ping 文本模型目录](https://aiping.cn/docs/API/text-models)。

第一交付的完成标准：

1. 实际网页请求产生真实主模型调用、真实 GLM 审核和同一请求的最终展示；保存脱敏调用记录，不只做终端问候测试。
2. 金额可由固定模拟档案独立复算；伪造证据、越权计划与遗漏重要条件能被拦截。
3. 主模型/审核超时、无效输出、审核拒绝时页面如实反馈，不展示未审核草案，不报告执行成功，账户不因模型调用改变。
4. 写操作在用户确认前不改变账户；确认后通过账本和回执核验终态，重复请求不重复扣款。
5. 文字和语音输入复用同一聊天工作流；真实 ASR/TTS 模型端到端运行，屏幕文字与播报内容对应，失败、取消和播放控制状态可见。
