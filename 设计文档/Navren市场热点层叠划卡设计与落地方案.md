## 1. 必须实现的画面与动作

**中间一张主卡，左边是真实上一条，右边是真实下一条。用户直接在卡片上左右拖动，所有可见卡片同步移动、缩放、转向，左右卡片连续接替中间的位置。**

```text
静止在第 2 条：
    第 1 条                  第 2 条                  第 3 条
  左侧预览                  中间主卡                 右侧预览
  较小、向内倾斜             完整、正面                较小、向内倾斜

手指向左拖动时，以下三件事同时发生：
    第 1 条向左退场 ←     第 2 条向左缩小 ←     第 3 条向中间放大 ←
                                              第 4 条从右侧进入

松手切换完成：
    第 2 条                  第 3 条                  第 4 条
  左侧预览                  中间主卡                 右侧预览
```

这段示意表示顺序关系，不是新闻内容。左滑下一条，右滑上一条；拖动过程跟手，松手后按距离/速度判定，共同吸附到相邻位置或原位。侧卡点击后先到中间，用户再选择原文或解读。

以下四条是不可省略的验收条件：

1. 至少三条热点时，静止及吸附完成后的中间卡左右可看见真实相邻卡片，桌面能够辨认侧卡主题和标题；三条队列过渡中允许远端卡短暂透明重定位。
2. 拖动到一半时，中间卡与邻卡已经在交接位置，邻卡不能等松手后才出现。
3. 同一条新闻从右侧到中间、再到左侧，有连续的身份与位置关系。
4. 任意一条作为中间卡时都成立，包括最后一条；三条及以上默认首尾循环，不自动播放。

参考仍是用户提供的[卡片滑动展示视频](https://www.xiaohongshu.com/explore/68ca5576000000000702b60a)。Navren 使用自己的浅色纸面、主题色和文字排版，借鉴左右卡片共同换位的视觉关系。

## 2. 当前实现需要改变什么

本轮只读核对的现状：

| 位置 | 当前行为 | 本次实施要求 |

范围限于市场热点呈现。权威来源、真实日期、事实审核、具体报道链接、收藏版本、对话对象、周报与产品推荐继续复用现有能力。

## 3. 版面、尺寸和卡片关系

### 3.1 模块结构

```text
市场热点 [?]                                      全部热点 · 深读原文

 ┌── 上一条 ──┐      ╭──────── 当前热点 ────────╮      ┌── 下一条 ──┐
 │ 主题        ╲     │ 主题 · 数据/政策/观点  日期 ☆│     ╱        主题 │
 │ 真实短标题   ╲    │                          │    ╱   真实短标题 │
 │ 发布机构      ╲   │ 短标题       一个事实重点 │   ╱      发布机构 │
 └───────────────╲  │ 短说明       数值/单位/期间│  ╱───────────────┘
                     │                          │
                     │ 来源     原文 ↗   解读    │
                     ╰──────────────────────────╯

                         ‹       2 / 6       ›
```

侧卡是真实内容的预览。桌面露出的部分须让用户知道下一条大致是什么；手机空间较小时至少显示真实主题和清晰卡面，完整阅读由中间卡承担。模块不套额外大面板，不在轮播下默认展开长列表。

### 3.2 设计初值

参数是实现起点，须按实际浏览器画面校准。`S` 为舞台可用宽度，`C` 为未变换的主卡宽度，`D` 为相邻卡中心的横向距离。

| 项目 | 桌面：舞台宽度不少于 760px | 紧凑/手机：舞台宽度小于 760px |
|---|---|---|
| 舞台 | 最大 1040px，居中；裁切舞台两侧溢出，页面本身不横向滚动 | 占容器可用宽度 |
| 主卡宽 `C` | `min(620px, S × 0.64)` | 初值 `S × 0.74`，两侧各留约 13% 舞台；根据标题可读性微调 |
| 相邻中心距离 `D` | `C × 0.60` | `C × 0.60` |
| 中间卡 | 缩放 1，Y 轴角度 0° | 同左 |
| 左/右侧卡 | 缩放约 0.82，分别 Y 轴 +22° / −22° | 缩放约 0.86，角度约 ±12° |
| 景深 | `perspective` 约 1200px；侧卡后退约 100px | 约 1000px；后退约 60px |
| 主卡高度 | 标准字号约 270—310px，内边距 22—24px | 由内容决定，内边距 16—18px |
| 圆角 | 20—22px | 18—20px |
| 控制区 | 一行左右箭头和序号，点击区至少 44px | 同左；关怀模式至少 48px |

桌面在 `S=1040px` 时，中间卡宽约 620px，左右各有约 200px 的舞台空间。必须在实际透视、重叠、裁切后检查侧卡露出面积；不能用变换前的数值证明最终效果。

阴影要有内侧留白，容器裁切不能把中间卡阴影和焦点框切断。舞台高度按未变换的内容测量，并容纳侧卡下移和阴影；卡片定位不能让容器高度坍塌。

标准字号时整个模块优先控制在约 370—420px 高。超长标题、大字号或 200% 缩放允许自然增高，不以固定高度截掉条件、来源或按钮。关怀模式减少倾角，保留清晰的左右空间。

### 3.3 侧卡内容怎样露出来

一张卡始终绑定同一个事件 ID。卡片内可有两种展示层：中间的完整卡面，以及靠外缘的紧凑预览。预览使用同一事件的主题、审核短标题和发布机构，不另造新闻文案。

左侧预览靠左外缘，右侧预览靠右外缘，避免标题全部被中间卡压住。桌面外缘预览建议宽约 110—150px，标题 15—17px、两至四行，来源一行；手机露边很窄时保留主题/符号即可，不能挤成竖排碎字。

完整卡面和紧凑预览随相对位置平滑交叉淡入，不能在松手的一瞬间整体替换内容。一次拖动中卡宽、字体、正文布局固定，两种展示层独立定位；不能随进度改宽、重排文字或突然切换 `display`。卡片主容器与事件 ID 保持稳定。重复视觉文字仅作为呈现，不让屏幕阅读器重复朗读；侧卡的可访问名称包含真实标题。

舞台高度取未变换的布局高度，不能逐帧根据已缩放卡片的 `getBoundingClientRect()` 高度重新计算，否则舞台会跟着拖动上下抖动。

不用模糊滤镜。减弱的是侧卡阴影和装饰，预览文字保持清晰。侧卡常态不通过整体低透明度让文字变淡。

## 4. 跟手运动与首尾循环合同

### 4.1 所有卡片由同一个连续位置驱动

保存已提交的 `activeIndex` 与连续的 `virtualPosition`，数据按原排序不变。拖动中后者可以是 2.35 这样的分数，界面根据它绘制全部参与卡片。

```text
pointerDx = 当前横坐标 − 开始横坐标
拖动进度 = clamp(−pointerDx / D, −1, 1)
virtualPosition = 拖动开始位置 + 拖动进度
相对位置 r = 该卡的虚拟序号 − virtualPosition
```

因此向左拖动会使进度增加，当前卡的 `r` 逐渐从 0 到 −1，下一卡从 +1 到 0。位移映射中的 `D` 必须取实际相邻中心距离，不能用主卡全宽作为一格，避免卡片明显不跟手。

统一变换函数示意：

```text
a = abs(r)
X = r × D
Y = 10px × min(a, 1)
scale = 1 − 0.18 × min(a, 1)
rotateY = −sign(r) × 22° × min(a, 1)
Z = −100px × min(a, 1.5)
fadeEnd = N >= 3 ? min(2, N / 2) : 2
opacity = a <= 1 ? 1 : max(0, 1 − (a − 1) / (fadeEnd − 1))
```

手机与关怀模式替换对应缩放、角度和景深参数，仍使用同一个相对位置。三条时在距离 1 至 1.5 之间淡出，四条以上在距离 1 至 2 之间淡出，使旧远端卡和新进入的卡在半程仍有露边。常态只显示三张，过渡中可以短暂显示四张真实卡片。

层级按距离中心远近计算，两张距离相同时按本次运动方向作固定判定，不能来回闪烁。变换顺序、透视投影与指针位移需实测校准；以上不是可直接粘贴的完整 CSS。

每个动画帧只更新变换与必要的透明度，合并指针事件到一次 `requestAnimationFrame`。拖动时不能逐帧重建 DOM、读全量布局或改新闻身份。吸附中的卡内原文/收藏/解读动作暂不激活，等目标位置提交后再启用，避免在两个候选中间卡重叠时误触。

### 4.2 松手后共同吸附

达到距离阈值，或有明确同方向快速划动时，目标位置为开始位置的上一格/下一格；否则目标仍为原位。

提交阈值初值为 `D × 0.28`；快速划动可使用末尾约 100ms 的有效采样，速度约 0.45px/ms 且横移至少 30px作为辅助。短到不能可靠估算速度的采样只按距离判定。

**全部卡片从松手时的连续位置共同吸附到目标位置**，建议 240—300ms、缓动 `cubic-bezier(.22,1,.36,1)`；回弹约 160—220ms。一次拖动最多切换一条，超出一格的位移做柔和阻尼。

中间卡不能先飞出、消失，再从背后生成新卡。箭头、键盘和侧卡点击调用相同的吸附流程，不能各做一套动画。

只在吸附成功后一次性提交活动索引、序号、活动事件 ID 和可访问播报。取消时所有卡片一起回原位。动画中合并为至多一个后续导航意图，避免连续点击导致多个未完成动画争夺状态。

### 4.3 循环与少量内容

| 热点数 | 行为 |
|---|---|
| 0 | 紧凑空态和原有重试/来源状态；不制造卡片 |
| 1 | 一张真实主卡；隐藏切换箭头、关闭拖动，无虚假邻卡 |
| 2 | 两张真实卡，有限往返，另一张位于对应侧；到边界回弹，不复制同一条凑三张 |
| 3 及以上 | 首尾循环；静止及吸附后末条右边是首条，首条左边是末条；左右均有真实邻卡 |

三条及以上不显示“已到最后一条”，没有自动播放。序号表示原队列位置，例如从 `6 / 6` 左滑到 `1 / 6`，排序本身不变。

循环使用连续虚拟序号与取模映射，不能最后一条到第一条时横跨整个列表。每个事件最多一个真实卡片容器；参与窗口可以含邻卡缓冲，但常态只显示左、中、右三张。

三条及以上可按以下距离计算每张真实卡的位置；两条使用有限索引，不套用循环公式：

```text
delta = 事件在原排序中的索引 − virtualPosition
r = delta − N × floor((delta + N / 2) / N)
```

吸附完成后可将连续位置减去整圈数作数值归一化，归一化前后画面必须等价。不能在开始从末条切换到首条时直接把位置设为 0。

三条内容尤其要验证：退到远端的同一张卡必须先在 `|r| >= 1.5` 的不可见区域完成虚拟位置调整，再从另一侧进入。透明区域同时不可点击、不进入焦点。不能让一张可见卡突然从左跳到右，也不能同一新闻同时出现在两侧。循环距离的边界调整必须发生在透明区，不得仅靠整数索引刷新掩盖。

滑动只改变阅读位置；不删除新闻、不写“不感兴趣”、不改变画像、收藏和推荐权重。

## 5. 直接拖动、点击和可访问性

### 5.1 哪些位置可以拖

中间卡的正文、非操作区域、侧卡与舞台空白均可发起横拖。鼠标使用按下拖动，触摸使用左右划动；不能只在页眉/页脚设置狭窄拖动把手。

状态机采用 `idle → pending → dragging → settling → idle`。按下只进入待判定；横移约 12—16px、且明显大于纵移（初值约 1.35 倍）时才锁定横拖。纵向趋势交还页面滚动，`touch-action: pan-y pinch-zoom`，不劫持纵向滚轮。

链接、原文、解读、收藏、输入框等实际动作控件不启动拖拽。它们记录是否发生明显移动，移动取消本次点击，避免在手机上误开原文。横拖成立后抑制该手势结束产生的合成 click，不能让滑动变成点击。

鼠标正文的普通横拖默认用于轮播；明确的文本选择路径为按住 Shift 拖选，或长按/双击后选择。已有选择时不启动轮播。非拖动状态不全局禁用文本选择，详情中的正文始终正常选择。须在真实浏览器验证拖动判定不留下意外选区。

侧卡短按只切换该条到中间，不直接跳报道。一次点击不能既居中又打开原文。舞台空白不会打开任何链接。

### 5.2 焦点与辅助操作

中间卡提供正常的原文、解读与收藏动作。侧卡提供独立的“切换到：真实标题”入口，侧卡内部动作暂不可用。

不能把可点击侧卡整体设为 `inert/aria-hidden` 后又声称支持键盘。可采用独立预览按钮承接侧卡切换，卡片内部视觉内容与中间动作分别管理；不得出现按钮包按钮、按钮包链接。

在轮播导航区域，左右键和可见箭头切换；在输入框、文本选择、详情面板内不截获方向键。Enter/Space 激活预览或动作，Tab 顺序稳定。

切换完成播报“第 3 条，共 6 条：标题”，拖动过程中不连续播报分数进度。切换焦点中的原文/解读按钮时，焦点保留在新中间卡的等价位置；不能落在已隐藏侧卡或页面开头。

`prefers-reduced-motion` 下保留左右布局和直接拖动能力，取消景深/倾角的动态变化，吸附改为立即完成或不超过约 80ms；不用飞出动画。关怀模式保留箭头和足够大的点击区，不通过删除来源解决空间问题。

### 5.3 中断与异常

处理 `pointercancel`、意外丢失捕获、窗口失焦、页面退出、双指缩放、尺寸变化、显示模式切换与组件销毁。取消旧动画和旧指针，所有卡片恢复同一个有效位置，不遗留半张居中状态。

刷新数据时按事件 ID 保留当前条；当前条撤下则取消手势、移除失效对象，定位最近有效条。回调始终绑定事件 ID 和版本，不能因当前数组索引变化让旧按钮打开另一条报道。

## 6. 简约卡面与主题色

### 6.1 中间卡的信息顺序

| 位置 | 内容 | 标准字号初值 |
|---|---|---|
| 顶部 | 主题、内容身份、日期、收藏；修订/订阅状态按需可见 | 13—14px |
| 主标题 | 一件事的审核短标题，通常两行以内 | 桌面 23—26px；手机 21—23px |
| 短说明 | 一至两行，回答变化或适用对象 | 15—16px，行高约 1.5 |
| 事实重点 | 最多一个指标或关键条件，单位、期间与数字贴近 | 数值 32—40px；条件使用正文大小 |
| 底部 | 发布机构、阅读原文、Navren 解读 | 14—15px |

正文左对齐，数字用等宽数字特性。宽卡可以正文与事实重点分列，手机改成紧凑事实条。没有合格重点时正文占满，不保留空的右侧装饰栏。

侧卡显示相同事件的简版。中间卡最多两处视觉强调；标题、数字、按钮、徽章不能全部抢眼。没有必要的长说明删除；问号解释放在模块标题附近，关键状态和限定条件直接可见。

短标题约 18—32 个中文字、短说明约 30—55 字属于编辑目标，不是机械截断规则。无法合格缩短时允许卡片自然增高，详情保留完整标题与摘要。

### 6.2 颜色与质感

| 主题 | 卡面底色 | 细边框 | 强调色 |
|---|---|---|---|
| 宏观数据 | `#EDF4FF` | `#D5E3F8` | `#2E61A0` |
| 利率政策 | `#EAF5F3` | `#CEE5E0` | `#246B67` |
| 民生金融 | `#FFF3E4` | `#E8DAC6` | `#825E2E` |
| 国际市场 | `#F2EEFA` | `#DDD5ED` | `#66528E` |
