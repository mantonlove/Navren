# Navren 基础业务演示主线

日期：2026-10-04。性质：产品设计与验收提案，不等于已实现或评委认可。

修订：用户指出“资金承诺记忆 + 可动用金额推演”仍属于六项赛题中的跨场景联动。此判断成立：下文作为基础业务的连贯演示，撤回其作为额外创新主亮点的定位。真正额外机制另见[差异化机制候选与竞品核对](差异化机制候选与竞品核对.md)。

## 把比赛任务串成用户真正要办的事

当前赛题是“银行 AI 智能体”：通过自然语言理解金融意图，规划并执行银行业务；官网列出智能转账、账单分析、理财操作、卡片管理、订阅/代扣和跨场景联动六个场景。任务完成、安全、创新交互必须一起成立。比赛规则还把真实银行数据/API 与参赛模拟环境区分开，Navren 要清楚标注模拟账户与真实账户边界。[赛事官网与赛题](https://fintechathon.g-ican.com/)、[国内赛道规则](https://fintechathon.g-ican.com/#/rule)

因此，产品故事不应是“我们做了六个菜单”，而应是：“用户说一个真实生活目标，Navren 读懂其明确授权的资金承诺，跨场景查数、推演、准备动作；每一步都能看证据并由用户控制。”这是一条可演示、可审计的工作流，不依赖固定六个 Agent。

## 用户问题与依据

1. **复杂信息难以转化为长期决策。** 2025 年消费者金融素养调查覆盖 255,668 份有效样本，报告指出消费者资产配置策略仍有提升空间，对需要深度理解、复杂计算或跨期决策的金融知识掌握相对薄弱。[清华五道口发布的调查摘要](https://www.pbcsf.tsinghua.edu.cn/info/1154/10151.htm)
2. **金融产品的关键条款需要被说明清楚。** 人民银行《金融消费者权益保护实施办法》要求银行评估产品/消费者适合度，并以有利于理解的方式披露重要信息、解释关键专业术语并留存确认资料。[办法第十二、十六至十八条](https://fgw.sh.gov.cn/ys-hqjrfw-1.3.4.1/20240821/239cf294b8c647ab8802c07334e1cf59.html)
3. **银行 Agent 的体验关键在跨功能完成任务且保留控制权。** 赛事目标是自然语言输入后规划、执行银行业务；Navren 已有模拟账户、账单、代扣、卡片、转账、资金预留、服务预约和理财操作，适合用一个跨场景用户目标演示这些能力如何协作。[赛事官网](https://fintechathon.g-ican.com/)

前两条是外部证据，第三条是赛事要求与 Navren 现有模拟能力的匹配判断。它们支持产品方向，不证明客户已经采用，也不证明 Navren 已经提升银行经营指标。

## 基础演示主线：资金承诺记忆与“可动用金额”推演

让用户可选择建立一份自己的“资金承诺记忆”：近期目标（学费、旅行、装修等）、固定承诺、流动性期限偏好、关注的产品/知识。图谱节点保留用户表达或确认、账单/账户来源、观察时间、置信度和失效时间，并以关系连接目标、周期扣费、资金预留和金融产品。

用户问“我现在拿出多少钱做 30 天左右的理财比较合适？”系统展示三层数字：

- **账户当前可用余额**：仅引用模拟银行核心的余额快照。
- **已识别但尚未确认的近期待付**：列出对应账单/周期扣费与日期，标为候选，不能悄悄算成确定事实。
- **扣除用户确认承诺/预留后的推演金额**：由确定性现金流服务依照明示公式计算，附时间窗口、数据覆盖范围和缺失项。此数是辅助决策的情景值，不是银行余额，也不是自动授信/适当性结论。

之后才动态调用适用的能力：读取账单和余额、核对代扣与预留、匹配产品风险/期限/流动性、准备可撤回的模拟订单草案、独立审核。操作对象和金额最终由用户逐项确认，后端查询回执后再显示完成。

### 用户记忆设计边界

- 默认先记用户明确表达的目标/偏好；从消费行为总结的习惯需独立授权，并清晰标注为“根据某时间范围流水整理”，等待用户确认后才进入长期记忆。
- 记忆与正式风险测评分库分权。不得由购物、消费品类、问过某理财产品推断风险承受能力或信用水平。
- 用户可在“我的财务记忆”中查看、纠正、逐条删除、关闭；关闭后不读取也不写入。
- 只存必要摘要和证据定位，不复制原始流水，不存身份凭证。记忆过期、数据范围不足或用户纠正时，下游推演明确降级并提示。
- 竞赛原型使用模拟工作区 ID 做隔离；不伪装成银行真实实名身份或生产级授权。

## 演示脚本：从一句话到有边界的结果

以下是拟定的合成演示任务，金额和日期应由固定测试夹具提供，不预填宣传结论：

> “我两个月后有一笔已确认的大额支出，平时还会自动扣几项订阅。我现在有多少资金适合放进期限不超过一个月的产品？先给我看依据，不要直接买。”

演示按屏幕顺序展现：

1. 用户目标和记忆来源卡片：哪些是用户说的，哪些来自已导入流水，哪些仍待确认。
2. 动态任务计划：本次为什么调用账单、代扣、资金推演和产品筛选能力；若直接查卡则展示只需一个 Agent 的对照任务。
3. 资金时间轴：余额、已确认承诺、疑似周期扣费、预留及扣除后的推演结果分层显示；每笔可展开到来源记录。
4. 产品比较卡：期限、风险级别、赎回限制、费用和数据来源，以适合/不适合的确定性规则说明原因。
5. 用户改变目标日期/金额后的影响预览：重新计算并指出结果变化来自哪一项，展示可解释的“假设情景重放”。
6. 独立审核结果与操作草案：确认前清楚呈现对象、金额、有效期与模拟环境；不确认就不执行。
7. 用户确认后查询订单、余额、持仓和审计状态；另演示超时/重复点击时不重复扣款，以及状态未知时先查证。

这条演示证明跨场景任务完成度。它与图谱可视化、Agent 名称数量和模型型号均不能单独作为新增创新成果；额外机制需要竞品对照、明确的设计增量和独立效果验证。

## 验收与路演证据

先用合成模拟客户建立固定测试集，至少覆盖收入/账单、退款/转账口径、重复订阅、候选误判、用户目标变化、过期记忆、无授权、产品期限不匹配、余额不足、操作取消、重复确认和模拟服务超时。

每次运行生成可以现场核验的结果：

- 账单分类、余额、预留和业务回执逐笔/逐项对账；差错目标为零，除非明确标为输入数据缺失。
- “疑似周期扣费”报告精确率、召回率及错误样例，不只展示挑好的命中案例。
- 每条事实陈述的证据覆盖率；无引用事实应被规则门拦下。
- 资金推演公式、时间窗口、样本数据版本及情景差异可复算。
- 每类高风险动作的拒绝/确认/强验证测试，重复确认幂等，失败不误报成功。
- 若做用户测试，记录任务完成率、完成时间、理解率及样本量；未做测试前不声称“提升效率/满意度”。

路演建议将这条跨场景主线放在第一演示，其余场景作为能力矩阵和快速补充；六项赛题覆盖列表、模拟真实性和安全证据单独展示。比赛评分与获奖结果不可由内部功能清单推断。

## 近期实现顺序

1. 先固定一条跨场景演示用合成数据和可复算的资金时间轴/“可动用金额”服务；明确余额、账单、预留、待处理交易的口径。
2. 把当前动态能力目录和工作流接入现有模拟银行查询端口；模型保留可替换适配器。
3. 做本地记忆图谱存储/接口，先实现用户明确目标和偏好，再实现需确认的行为摘要；提供查看、纠正、删除、关闭操作。
4. 将任务图、证据卡、推演卡、确认卡和结果状态接入演示 UI。
5. 建固定评测集和回归脚本，生成真实结果后再写路演数字。

本设计依赖用户模拟记忆授权、模拟银行工作区隔离及既有操作确认链；任何模型或记忆服务都不能绕过它们。

### 阶段路线实施状态（2026-10-04）

第 1 项的现金流服务已接入模拟银行档案：默认展示 90 天，也可查询 1 至 365 天；只读账户、贷款分期、已出账信用卡账单、已启用定时转账、待结算赎回和生效资金预留。已确认现金流与周期续费／代扣候选分开，草案、未确认操作、未来未确认收入及未录入支出不进入推演；每条事件保留到账本来源记录的引用。周期记录滞后时只追补最近一期，避免将历史多期重复堆到今天；最低可用金额按日终净额计算，不假设同日交易先后。

接口为 `GET /api/finance/cashflow-timeline?days=90`，并随 `/api/finance/overview` 返回。金额以对应账户币种的账本整数单位分币种汇总，绝不把不同币种相加；客户应急金仅在唯一人民币主账户可识别时分配，否则单独返回未分配金额。4 项纯计算测试与银行 HTTP 集成测试已覆盖周期追补、账单与预留、同日净额、币种隔离、会话范围及时间范围校验。该项仍是确定性后台推演，不代表资金已冻结、扣款承诺或投资建议。

第 2 项已接入一条端到端样例：`finance_agent` 通过只读能力目录调用账户摘要、账单、异常、周期扣费、产品和现金流服务；能力清单可从银行能力接口发现，未知能力和写入类名称不会注册。“资金时间轴”已进入 `agent_runtime`，按“账户快照 → 现金流推演”的有向任务图执行；模拟账户与时间轴事件形成带来源的证据项，证据门验证引用，确定性规则门禁止生成银行操作，独立审核器检查任务图和引用后才放行数字答复。该路径使用本地确定性适配器，尚未接入供应商模型；账单、产品等其他查询当前仍走原确定性处理链，尚未纳入该任务图。

资金时间轴工作流专项测试覆盖任务依赖与审核轨迹、证据引用、工作区隔离、跨币种分开展示、未分配应急保留额引用、起止日期核验，以及禁止操作草案。HTTP 集成测试还验证了审核未通过时不会向答复或时间轴字段泄露未审核金额。浏览器端实测“未来 30 天资金时间轴”返回 `approved`，执行两项依赖任务、引用 10 条证据，规则门和审核器均通过，`bank_actions` 为空；完整回归共 144 项通过。以上属于隔离模拟账户与本地确定性适配器的验证结果。

第 3 项的本地记忆 MVP 已完成：`user_memories` 按模拟工作区隔离，默认关闭；五类可选记忆只接受用户手动填写，支持查看、纠正、逐条删除和启停。密码、验证码、证件号、手机号及银行卡号会被拒绝；审计仅记录节点标识、类别和可选有效期，不复制记忆值。用户可设置参考有效期；期限按模拟业务日期判断，到期记忆仍可查看但不进入分析。启用后仅资金时间轴查询会读取目标、已确认支出和流动性偏好，答复绑定 `user_memory:<origin>` 证据并显示来源卡片；这些内容只作背景，不改变余额和推演计算。没有接入流水行为摘要或自动记忆，也不把记忆用于正式风险测评。核心 API 为 `GET/POST /api/finance/memories`、`POST /api/finance/memories/settings`、`POST /api/finance/memories/{id}/correct` 和 `POST /api/finance/memories/{id}/delete`。

第 4 项演示 UI 基线已完成：对话卡片呈现逐日资金事项、账户推演指标、来源记录、任务步骤和审核状态；申购等写操作仍通过独立确认表单和模拟回执完成。经典版、关怀版、青春版共用浅雾蓝、浅蓝灰、帆船蓝与少量海青主题，模式通过字号、间距和密度区分；组件颜色使用语义令牌，供后续深色版复用。浏览器实测确认三个模式下卡片全宽排列、来源展开控件可达。聊天页支持文字输入、麦克风流式识别、文字回复及 TTS 朗读；当前浏览器中已验证文字回复可启动真实 TTS，自动播报打开时回复文字与语音同时呈现；合成语音也经同源 ASR WebSocket 得到正确最终转写。实际设备麦克风权限、环境噪声和不同设备兼容性尚未验收。尚未将周期扣费候选纳入产品配置建议计算，因此推荐阶段不会将候选扣费伪装成确定承诺。

第 5 项固定合成评测已建立：`evaluation/financial_eval_set.json` 固定 12 个场景，`scripts/run_financial_eval.py` 运行 15 个唯一回归测试并生成机器可读报告；2026-10-04 结果为 12/12 通过。另增加 `evaluation/security_eval_set.json`，固定覆盖提示词注入、越权确认、伪造权限、确认篡改、强验证重放/锁定、跨工作区、并发幂等、事务回滚、提交后断连/客户端超时、CSRF/Origin 和语音票据/取消等 16 个场景；2026-10-04 运行 26 个唯一回归测试，16/16 通过，报告为 `evaluation/results/latest_security.json`。两套评测仅证明其合成环境内列出的工程断言通过，不代表真实客户效果、模型准确率、绝对安全或比赛分数；人工处理回执及整套审计复核仍待完成。

记忆测试另覆盖默认关闭、类别范围、敏感字段拒绝、工作区隔离、纠正/删除、启停、到期后不再进入工作流，以及旧数据库表升级时保留既有行。
