## 2. 全站组织：四个入口，各有明确职责

一级业务导航严格保持：**对话 → 账户 → 发现 → 我的**。设置是辅助入口；不新增第五个业务入口，不重新铺一排十余个二级按钮。

| 入口 | 用户在这里做什么 | 首页优先显示 | 详情归属 |
| --- | --- | --- | --- |
| 对话 | 提问、看结果、继续当前任务 | 最新主回复、一个主要可视化、相关建议问题 | 对象可在回复内展开或进入所属页面，保留对话返回位置 |
| 账户 | 看已有资金、持仓、负债和近期事项 | 资金摘要、最近需要关注的事项、现金/投资/负债入口 | 账户、持仓、负债、银行卡、扣款、流水、服务安排 |
| 发现 | 读市场、研究和比较产品 | 市场精选及研究产品入口 | 报道、周报、历史热点、产品资料、比较结果、研究方案 |
| 我的 | 管理长期目标、本人条件与偏好，理解财务关系 | 目标进度、四个关系领域、确需本人核实的陈述 | 目标与责任、金融认知与记忆、关系图谱、收藏和设置 |

页面不再把所有能力当作同级按钮展示。首页用简短对象行和有内容的摘要引导，常用对象点击进入详情；操作集中到对应对象和当前任务上。

### 2.1 账户

1. 顶部保留现有服务计算的核心资金摘要，紧凑展示，不在浏览器重算总资产、结余或可投资资金。
2. 主体分为现金、投资、负债三个对象组。现金账户可以关联借记卡；信用卡应还属于负债；存款合同、贷款合同保留真实类型与稳定 ID，不能只换一个通用“资金”标签。
3. 银行卡管理、订阅与代扣、流水和操作记录从对应对象、近期事项或简短辅助入口进入。服务安排仍在账户维护。
4. “可安排资金”说明现金中的约束后子集，不能和现金、资产相加。资金保留来源、时点、币种、计算依据与版本。
5. 投资详情是收益的主要归属页：本金/份额、已披露收益区间、估值或缺项、产品原件、相关流水。日历是按日期观察收益的入口，图谱是关系入口。
6. 当前模拟银行持仓与历史模拟组合分开。复用既有 `wealth-product`/权益法和 NAV 原件；公共历史净值不自动成为该用户的实际收益，跨月收益区间不摊到每天。

### 2.2 财务日历

1. 桌面主结构为“月历 + 选中日详情”；窄屏为月历，选中日后打开可关闭的详情抽屉。完整日期详情深链接保留，不能只能依赖抽屉打开。
2. 顶部只保留月份导航、当前月份/参考时钟、必要的来源选择。类型等筛选渐进展开，取消与月份导航重复的日期控制。
3. 月格先看日期、事项数量、关键状态；有服务端真实日数据时才显示对应金额或收益语义。收入、支出、投资盈亏不能共用一个模糊颜色含义，正负同时保留符号和标签。
4. 选中日详情先展示当天摘要，再列事项。每项直接显示名称、金额或未知、时间、已确认/候选/目标截止等性质，并可打开原对象。
5. 重复的“未披露/覆盖不足”合成范围级说明，具体有缺口的日仍可定位。**未知保持未知，真实计算出的零才显示零**；未来候选事项不冒充已发生流水。
6. 详情必须能读取全部事项；首批 8 条不能写成“全部”。分页继承原来源、组合、时钟、范围和版本，支持返回原选中日。
7. 目标截止日只投影为目标日程，不能变成已扣款、应付债务或现金冻结。

### 2.3 发现

1. 市场阅读与产品研究形成两条清楚路径，不增加一排同级导航。可用页面内区段与少量主入口，布局由 UI 在候选中验证。
2. 市场热点继续采用用户要求的**左右滑动封面流**：中心主卡与左右邻卡同步切换；保留已批准的每日最多六条、历史热点及日期/类别筛选方案。有多少已核实报道就展示多少，不补造六条。
3. 新闻卡保留标题、一个核心事实、必要日期、权威来源和原文链接；解释与收藏采用紧凑工具，不写长摘要挤满封面。
4. 周报采用紧凑封面和阅读入口。无已发布周报时给出简短状态，不占据大块固定高度空卡；不能悄悄用其他周次或修订替代选中版本。
5. 产品研究路径为：资料目录 → 选 2–3 项比较 → 产品详情 → 保存研究方案 → 明确进入后续业务核对。普通浏览、收藏、比较和保存研究不自动创建申购单。
6. 首页预览依据实际最近查看/本人选取，或提供清楚的产品类型入口。不能把目录 ID 排序前三条包装成热门、适合本人或推荐产品。
7. 公共产品资料与可执行模拟产品必须可辨认；微众银行公开资料、基金份额、销售状态、净值日期分别保留，目录命中不等于当前可买或银行授权。

### 2.4 我的与知识图谱

1. 图谱固定四个领域：**日常收支、财富结构、目标与责任、偏好与认知**。我的首页领域卡直接进入对应图，不再先经过重复的四领域总览；总览仍可作为可选返回入口。
2. 首屏优先放一个有依据的关键关系摘要、图及选中对象详情。期间/来源轻量展示，更多筛选折叠；节点计数等工程信息移到辅助位置。
3. 从目标、持仓、收支类别进入时，直接选中相应节点并展示关联，而不是每次重新从“我”展开。
4. 节点大小、边粗细、颜色必须对应明确且同口径的量或类别。库存与流量、不同币种、资产金额与偏好置信度不能共用一套数值大小排序；负值、未知与候选不藏在绝对值里。
5. 摘要和排序由服务端已有事实/指标供给。前端不从标签猜钱，不在“按金额排序”的标题下展示未排序数据；无法形成合理排序时改为准确的阅读提示。
6. 选中节点时突出直接邻居与边的名称/依据，其余弱化；避免全图文字同时出现。详情可以查看期间、原件与关系解释，金融档案修改仍走既有确认流程。
7. 长期目标复用既有 GoalService；财务关系图是读取和理解已有对象的界面，不建第二套可编辑财务账本或目标库。

## 3. 阅读与交互组件

| 内容 | 默认形式 | 展开后 |
| --- | --- | --- |
| 普通短回答 | 简短结论，少量正文，不套多层面板 | 按需查看依据 |
| 财务查询结果 | 结论 + 关键指标 + 一个合适的主展示 | 原范围明细、来源与缺项 |
| 账户/产品/事项 | 有内容的对象行或摘要卡，标题可进入详情 | 完整对象及与任务相关的操作 |
| 待执行变化 | 独立核对面板，完整显示重要字段和条件 | 明确本人确认、取消或核查同一回执 |
| 无数据/失败 | 紧凑状态，有需要才提供重试 | 指向具体缺口，不虚构完整内容 |

- 卡片高度跟内容走。工具行采用正常文档流，禁止绝对定位制造大块底部留白；整卡作为链接时避免嵌套可交互元素。
- 结论先出现，金额、期间和单位容易扫描；同一结果的重复说明只解释一次。必要解释用标题旁的小问号/可展开依据，支持键盘、触摸及关闭；重要风险和确认条件不能藏进去。
- 正文口语自然、直接回答问题；不用括号里的“最大头”等空泛评语。突出程度优先用已审核数值或图形，比例必须有受信分母，不能由 UI 临时算一个百分比。
- 对话延续既有候选的内容宽度、紧凑工具行和最多两条建议问题。建议放在最新完成的主回复后，辅助消息不能抢走归属；接受字符串与既有结构描述符，刷新后重新核验。
- 图文结合复用现有日卡、月历、柱状图、折线图。短日期范围可逐日显示；多月、多年用受控汇总。完整月格遵守现有合同，不为了填满 31 天金额而突破 24 个金额位置门。
- 环图/饼图只有在非负构成、明确分母、完整覆盖、金融比例合同和审核均闭合后启用；当前候选未闭合时保持禁用，不以视觉需要放开。
- 读图可选择日期/点、打开事项、下钻类别或区间、返回父视图；选择来自服务端稳定引用。范围变化时同步替换对应已审核正文与展示，不能只换图保留旧结论。
- 回复结束仅在用户接近底部且正在跟随时滚动；用户正在阅读历史时不强制拉到底。新长回复要能看到结论，输入框不能遮住结果和建议。
- 保留现有浅色/深色外观设置、国际化初始化和语言切换。新标题、状态、缺项及详情同样覆盖中英；不能用浏览器翻译改写审核绑定字段。无法翻译的正式原题保留原文并说明来源。

## 4. 对象路径与返回合同

复用 `NavrenViews` 和既有 `/page-contexts`，不新建第二套路由或上下文系统。具体 route/view 名先核对现有注册表；新增只补缺口，保持旧链接兼容。

| 入口 | 必须到达 | 必须保留 |
| --- | --- | --- |
| 本人条件中的业务资金/风险入口 | 与名称一致的现有资金/风险位置 | 本人条件来源、返回位置；修调用点，不能粗暴改变全部 `wealth→holdings` 兼容别名 |
| 日历某日或事项 | 对应日详情/原对象 | 月份、选中日、类型筛选、来源、组合、参考时钟；已有“返回账户”实际可回月历，应改为准确标签 |
| 持仓收益 | 同一持仓的可用收益资料 | 当前/历史组合、份额、区间、原件和缺项 |
| 产品/比较结果 | 同一版本产品详情/研究结果 | 已选比较项、目录筛选、列表位置、原件版本 |
| 报道/周报/历史热点 | 指定事件或日版次/周报版本 | 日版日期与 revision、事件 version、分类、阅读位置；缺版本失败关闭 |
| 我的领域/目标/对象 | 对应领域及选中节点/目标 | 期间、来源、原对象 ID、返回列表位置 |
| 对象“问 Navren” | 带已核验引用的可编辑提问草稿 | 原视图和位置；用户主动发送后才发起问题，不自动调用模型或执行业务 |

上下文至少继承现有对象 kind/id、source_scope、portfolio_id、object_version、as_of、date/period、filters、selected、listposition、scrollposition、focustarget 和 return_context_id。账号/授权变化时重新核验，旧对象不能在新账号复活；刷新、前进后退与跨页返回均验证。

## 5. 数据与审核边界

- 基座发出只读对象、金额、期间、来源/覆盖、状态和稳定引用；金融方法负责口径；RAG 负责公共原件；Agent 负责有证据的解释与最终审核；UI 只做几何、排版和只读选择。
- 复用 `navren.presentation/1`、现有 FinancialMetric、原 24 个金额位置门与历史保存守卫。不新增财务注册表，不用浏览器缓存签名当作永久授权。
- 真实 `NavrenPresentationBridge` 必须闭合当前身份与请求绑定、回执验证、正文金额位置、detail/item_page 区分、子范围重发行、原子正文/语音/历史切换、建议问题重核验和 openView。
- 标题、来源、重要状态、缺项、事项与建议问题也进入同轮审核投影。不能先审核长文，再截短为未经审核的新结论；中文/英文财务解释切换同样绑定正确语言投影。
- 纯页面浏览与普通选中不产生支付、正式目标变化、预留或正式记忆写入；明确创建/编辑仍沿用既有 prepare → 核对 → 本人确认 → 回执流程。
- 原收费模型预算和失败关闭规则保留。本轮先完成候选、只读接线和本地/浏览器检查；不为排版额外付费，不以删条件、减事实或改预期掩盖预算拒绝。

## 6. 窗口分工与交付

所有窗口先核对已有任务、合同和协作 ledger。已完成的部分只提交可核验证据，不重复实施。修改需要跨 owner 的文件时先交接，角色职责不能代替实际文件授权。

### UI：页面与前端总负责

- 输入：本方案、旧页面组织方案、已有 `outputs/window-progress/ui/chat-presentation/` 及其真实依赖缺口。
- 执行：先修 P0 产品列表列布局、错位入口及返回文案；再做账户分组、发现阅读路径、我的领域直达、日历侧详情及内容层次；复用对话候选，配合原 owner 接通真实 bridge。
- 写入：复用当前 UI 精确登记范围；新增全站候选放 `outputs/window-progress/ui/information-architecture/`，不得覆盖旧候选及原冻结包。跨 owner 的 discover/view_context 等文件只在新候选复制件处理，主源码待确切 owner 交接。
- 交付：候选、逐文件来源/差异与哈希、route 表、依赖清单、before/after 浏览器截图及 viewport、检查命令/退出码；区分夹具、真实页面与接线后状态。
- 验收重点：正常/比较模式都无窄列；四入口职责清楚；对象、详情和返回形成闭环；短内容无巨型空白，长结果可扫描。

### 基座：对象与展示接口

- 输入：现有 `chat-presentation/contract.md`、当前 `object-reissue` 候选与金融口径；保持原 G1/S10 交付独立。
- 执行：补齐只读对象分组/引用所需语义，禁止仅为 UI 再建资金账本；复用当前对象重发行工作，完成 detail/item_page 全量分页、source/version/currentness、history/followups 回查及 bridge 所需回执。确认收益归属使用现有服务与原件。
- 写入：沿用 `outputs/window-progress/base/object-reissue/` 及已有精确范围；需要主源码落地时登记具体文件并交接，不静默扩大 scope。
- 交付：实际 schema/接口样例、字段可用/未知表、完整分页与父子范围规则、回执绑定和失败路径证据。路由或标题值若需改语义，说明旧兼容行为。
- 验收重点：现金/投资/债务不重复，缺项不补零，跨账号/版本漂移拒绝，首 8 条之外仍可读取，图/正文/语音/历史绑定一致。

### Agent构建：内容组织与任务衔接

- 输入：既有 presentation consumer、基座正式投影和本轮对象路径，不新建一套回答协议。
- 执行：按用户问题先给简短结论，再展示必要证据/图；选择适合的已有模板；金额、标题、条件、建议均同轮审核；范围变化产生对应新正文。建议问题基于当前真实工具可用性，最多两条，保持主回复归属。
- 写入：已有 Agent 精确范围及 `outputs/window-progress/agent/` 下本轮子目录；不得修改 UI、公共来源与金融计算。
- 交付：短/长回答及下钻示例、完整投影消费与历史证据、预算拒绝的真实状态；不用新收费模型生成第二遍“简化稿”。
- 验收重点：自然、先回答问题、不重复小字；不偷删资金条件；问对象先给可编辑草稿；事实查询与执行确认分开。

### 金融方法与计算：语义核验

- 输入：现有资金/收益/聚合方法，以及基座本轮字段合同。继续原同候选验收，不能被本轮替换。
- 执行：核验现金/投资/负债归组、卡与账户重复边界、结余与可安排资金含义、收益区间归属、图谱金额排序和构成分母资格。只复用或修正必要方法，不另建收益/资产引擎。
- 写入：现有金融候选精确范围；本轮补充放 `outputs/window-progress/finance/implementation/information-architecture/`。
- 交付：可给 UI/Base 的口径表及独立预期，至少包含未知/真零、退款/转账/本金、负值排序、跨月净值、现金与信用卡重复的反例；标明哪些复用已有证据。
- 验收重点：图形易读不改变资金含义，不能把公共产品表现说成用户已实现收益，不能通过删条件修掉失败。

### RAG构建：来源与版本衔接

- 输入：已完成公共产品/NAV、热点/周报证据及本轮阅读路径；不另起全量抓取。
- 执行：确认原文链接、机构、发布日期、抓取/披露时点、事件/日版次/周报/份额版本与缺项怎样交给 UI/Base；对空周报、旧版次和失效原文给出准确状态。已有合同满足时只回复字段映射和证据。
- 写入：已有 RAG 精确范围；补充放 `outputs/window-progress/rag/information-architecture/`；公共市场主流水线和 discover JS 不因角色划分而被接管。
- 交付：字段映射/真实原件样例、公共资料与模拟产品边界、缺项/旧版次核验；每日精选/历史热点已登记 owner 的问题走原 owner 交接。
- 验收重点：原文可追溯、版本不被悄悄换掉、不同日期概念不混用；已有 NAV 覆盖不冒充完整企业行为或个人收益。

### 集成验收：联合候选与浏览器任务链

- 输入：上述逐文件交付与当前原 G1 的独立冻结状态。
- 执行：原 G1 同候选完整轮继续运行，不改其问题、预期、冻结包；新全站候选另编号。汇合只接受已交接具体文件，不能复制整个 outputs 或把不同哈希的成绩拼起来。
- 写入：既有集成精确范围；本轮证据放 `outputs/window-progress/integration/information-architecture/`。真实浏览器使用隔离测试实例/明确演示 workspace，记录读取与正常初始化的边界，不重启共享现役服务或清理共享数据来抹掉失败。
- 交付：联合 manifest、接口缺口、八条任务链结果、截图和版本；原 G1、本轮 UI 与新对话展示分别报告。模型预算受阻、浏览器不可用或接口未接线时明确列出未验收项。

## 7. 最小浏览器验收：八条任务链

桌面基准 1440×900，移动基准 390×844。共享导航与对话在两者验证；日历、图谱、比较补移动窄屏检查，不做无意义的全排列。

1. **四入口与布局**：按对话、账户、发现、我的切换；设置辅助；当前页明确，隐藏区/抽屉焦点合理，无溢出和误切页。
2. **账户对象**：现金、投资、债务 → 一个具体对象 → 原列表。服务金额/币种/来源/版本保持一致，卡不重复计资产；核对收益当前位置。
3. **日历**：选择月份/来源/类型 → 某日 → 全部事项分页 → 一项详情 → 返回。月份、筛选、组合、选中日保留，未知/零/候选/目标性质可辨。
4. **发现**：滑动精选 → 指定原文/周报/历史 → 产品研究 → 选两项比较 → 详情 → 返回比较。正常模式不占 36px 列，比较模式选择列正确；不自动准备金融交易。
5. **我的**：目标、本人条件、收藏、设置进入并返回。业务风险入口确实到相应位置；目标只有既有权威对象，不要求测试创建/删除来证明导航。
6. **图谱**：四个领域直达 → 选中对象 → 看关系依据 → 返回。期间/币种/金额口径清楚，图不是被摘要挤出首屏，移动端详情可用。
7. **对话排版**：使用已有获审核回复或明确标注的隔离回放，检查短答、长答、日卡、月格和柱/折线。结论可见，工具紧凑，阅读历史不被强拉，建议在最新主回复下。回放只能证明展示，不能证明真实模型/接线通过。
8. **对象与对话衔接**：对象引用 → 可编辑提问草稿 → 按现有允许条件发送/回放 → 下钻及返回 → 刷新/前进后退。错误账号、撤回、漂移或旧签名拒绝，不自动收费、不复活旧执行动作。

日历、账户与产品路径使用真实隔离服务对象；夹具检查另列。旧 chat 候选 36/36、31/31 等本地成绩仅作为输入证据，不计为本轮联合浏览器通过；原 task-chat 24/25 的已知预期冲突保留并明确处理。

## 8. 推进顺序与完成条件

1. **P0**：UI 隔离候选先修研究列表错位、入口与返回承诺不一致；同步提交简短 route 表，核验不影响旧兼容入口。
2. **P1**：UI 完成四页对象归属与首屏层次；Base/金融/RAG 复用现有合同补精确字段缺口，Agent 复用现有展示消费链。
3. **P2**：闭合真实 bridge、事项分页、收益归属、语言投影和返回上下文；保留已做好的日卡/图表，不另写平行渲染器。
4. **P3**：集成从精确交付构造新联合候选，完成八条任务链，回归金额/授权/版本守卫；原 G1 单独得出自己的完整结论。

每窗报告统一写：本次输入版本、实际写入文件、复用项、新增项、命令和退出码、可见证据、接口缺口与下一 owner。`accepted` 是消息投递；本地检查、浏览器通过、整链通过、用户可用分别陈述。工具限制不绕过，失败不改预期伪装通过。

完成条件：上述八类问题有逐项证据，重要对象及返回路径闭环，联合版本明确且无未解决的关键接口；真实运行页的更新另按既有发布合同交接。方案与分发完成不代表代码已经落地或正式验收完成。
