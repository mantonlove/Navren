## 1. 本阶段目标与边界

用户已确定先考虑账单分析、理财操作、卡片管理、订阅／代扣管理四个方向。目前优先做不依赖官方银行 API 的能力，或先完成共用底座。2026 第一场公开课 1:35:48—1:36:26、1:37:20—1:38:20 已明确：AI 赛道不提供银行数据和业务接口，允许自建模拟数据及接口，要求功能流程完整。[视频](https://www.bilibili.com/video/BV1Z1hk68Esc/)

因此本地金融底座可以独立推进，无须等待官方 API。公开课没有提供统一模拟接口规范、逐项验收标准或强验证实现细则；Navren 按自建模拟数据与业务状态推进，并在界面和材料中标明模拟边界。精确金额由数据库及确定性程序处理，也与第二场 1:28:25—1:29:20 的技术建议一致。[视频](https://www.bilibili.com/video/BV1Eyhk6wEUk/)

本阶段交付：

1. 独立于大模型的本地账户与流水数据服务，支持持久化、来源区分、严格金额计算。
2. CSV 账单预览、确认导入、重复处理和错误反馈。
3. 月度收支、消费分类、可追溯的异常交易提示。
4. 疑似周期扣费识别、预计日期提示、用户确认／忽略本地识别结果。
5. 共用的操作权限、确认状态和审计记录；接入账户页与对话入口。

本阶段不实现银行转账、理财申购赎回、卡申请／授信额度调整／挂失、银行侧扣款拦截、商户订阅取消。不得以提示消息、修改前端数组或大模型回复冒充这些业务已执行。四个方向共用数据结构先建立，业务写入能力按实际接入状态声明。

本阶段完成后仍不能声称已满足国内赛道的全部参赛要求：至少三个业务场景、业务执行环境和强验证等要求，需要后续补齐与核实。[官方赛题](https://fintechathon.g-ican.com/)、[国内参赛规则](https://fintechathon.g-ican.com/#/rule)

## 3. 底座设计

采用现有 Python 服务＋标准库 SQLite，前端通过同源接口读取。不引入新的 Web 框架、外部金融服务或模型依赖。模块拆分建议为：数据存储、确定性分析、操作服务、HTTP 路由、前端呈现；具体文件名由实施者按仓库结构决定。

### 数据对象

| 对象 | 必要字段及约束 |
|---|---|
| 本地工作区 | 服务端生成的工作区标识；隔离不同浏览器会话的数据 |
| 数据集 | 数据集 ID、所属工作区、来源 `demo/imported`、币种、数据版本、创建时间、已记录时间范围 |
| 账户 | 账户 ID、数据集 ID、币种、可用余额（可空）、余额日期；导入流水时余额默认未知 |
| 流水 | 稳定流水号、账户／数据集 ID、交易日期／时间、时间精度、商户、正值金额（分）、类型、分类、备注、来源 |
| 持仓 | 账户关联、产品标识、数量／金额、估值日期、来源；本阶段只允许明确标注的演示持仓展示 |
| 卡片 | 账户关联、脱敏卡标识、类型、状态、消费限额、来源；本阶段只读演示数据，不存完整卡号 |
| 周期扣费候选 | 候选 ID、商户、周期、近似金额、证据流水号、规则版本、预计日期、用户标记 |
| 操作 | 操作 ID、请求幂等键、动作、对象、权限、确认详情快照、数据版本、状态、时间和结果 |
| 审计 | 事件 ID、操作 ID、动作、关键判断、执行状态、数据来源、时间；避免保存完整原始 CSV 或无关个人资料 |

金额全程使用整数分或严格十进制转换；统计过程中不用二进制浮点。当前只支持人民币，其他币种明确拒绝，不能直接相加。日期按北京时间处理，只有日期的记录保留“无精确时间”标记。

演示与导入账单必须使用独立数据集，可切换查看，不能混合统计。演示数据采用明确的模拟商户、卡片和产品，不包装成真实银行账户。工作区重开浏览器后可以续用，但该标识仅服务于本机演示隔离，不等同于正式用户认证。

数据库放在静态目录不可访问的位置，加入 Git 忽略规则。新金融接口与包含本地金融数据的对话查询仅限本机访问，检查请求来源及会话归属、不使用通配 CORS、响应禁止缓存。不得沿用现有代理的开放跨域策略来暴露账单。公开部署及正式身份认证另行设计。

### 能力声明与接口边界

服务返回明确的能力列表。首版启用账单导入、账单分析、周期扣费分析和本地标记；银行转账、投资订单、卡片控制和商户取消均为未接入。

外部银行数据接入预留适配边界；业务分析只处理规范化的数据对象，不依赖某家银行的返回格式。首版使用本地数据提供者即可，不提前建立多家银行 SDK，不为未开放的业务编造执行实现。

建议接口职责：

| 接口 | 职责 |
|---|---|
| `GET /api/finance/snapshot?month=YYYY-MM` | 返回来源、可用月份、账户已知字段、月报、异常提示和周期扣费候选 |
| `POST /api/finance/statements/preview` | 校验 CSV，返回批次 ID、有效期、摘要、示例记录及错误；尚未进入正式账单 |
| `POST /api/finance/statements/commit` | 用户确认后提交预览批次，幂等且整批原子写入 |
| `POST /api/finance/source` | 切换已有演示／导入数据集，不删除数据 |
| `POST /api/finance/operations/prepare` | 为允许的本地标记动作生成待确认操作 |
| `POST /api/finance/operations/{id}/confirm` | 明确确认或取消，校验归属、有效期和数据版本 |
| `GET /api/finance/audit` | 查询当前工作区关键事件与操作结果 |

接口形状可调整，但职责、权限和状态不能由前端自行决定。输入校验错误应返回中文说明，不能在产品界面暴露堆栈、数据库路径或模型代理信息。

## 4. 首版功能范围

### 4.1 CSV 账单导入

模板必填列：流水号、日期、商户、金额、类型；选填列：分类、币种、备注。类型支持收入、支出、退款、转账；金额为正数，方向由类型定义。分类留空时按透明规则分类，无法识别归入其他。

流程为选择文件／粘贴 CSV → 校验预览 → 查看数据来源、记录数、期间及错误 → 明确确认 → 提交 → 刷新统计与审计。预览不得修改正式数据；取消或预览过期均不导入。

每批建议限制为 1.5 MB、5000 行。检查表头、日期、金额精度、币种、列数及字段长度，异常行标明行号。任意无效记录均阻止整批提交。相同流水号且内容相同可跳过；相同流水号但内容不同必须冲突报错，不能静默覆盖。幂等重试不能重复记账。

用户输入只作为数据。商户名和备注即使包含 HTML、公式或“忽略规则”等文字，也不能被执行或作为智能体指令；渲染须转义，导出表格须处理公式注入。

### 4.2 月度收支与分类

展示已记录笔数、收入、退款前支出、当期退款、收支结余、转账金额及消费分类。转账不计入消费或收入；退款单列，结余按收入－支出＋退款计算，不回写账户余额。分类总额与支出总额必须相符。

报告注明数据来源、月份、已记录日期范围和统计口径。无流水显示“该月暂无已记录流水”，不能据此断言用户本月没有消费；数据覆盖不足时也不能当成完整月账单。首版只做单月，年度、多月比较后续扩展。

支持查看原始流水和下载报告；报告含统计口径、数据来源、规则版本及关联流水号，便于复现。

### 4.3 异常交易提示

先做两条规则，分别保留证据与解释：

- 疑似重复扣费：同账户、同商户、同额支出，精确时间相差不超过五分钟。只有日期而无时间的记录不触发这条规则。
- 金额偏高：超过固定门槛，并显著高于此前同类消费基线。基线只用该笔之前的数据，设置最少样本数，阈值及规则版本可查；示例门槛为 3000 元且超过此前同类中位数三倍，最少五条历史样本。

这些是演示用规则，未经过真实反欺诈数据验证。界面用“待核实”表述，并展示关联流水；没有提示不能解释为已经证明安全。具体阈值可以在实现中集中配置，但必须在报告中一致披露。

### 4.4 周期扣费识别与提醒

首版只识别疑似月度扣费：同账户／币种／商户，在至少三个连续月份各出现一次，间隔约 25—35 天，金额偏差不超过 10% 或 1 元。住房租金等明显固定生活支出应分开处理，避免直接称为商户订阅。

结果展示扣费依据、近似金额、预计下次日期和用户标记。预计日期采用日历月计算并处理月末，不固定加 30 天。缺失后续记录时提示核实，不能假定已经续费或取消。提醒首版在页面展示，外部通知和后台定时任务暂不建设。

用户可以确认“这是周期扣费”或忽略识别结果。必须展示确认详情并由用户明确操作，刷新后标记保留。操作结果写明“仅更新Navren本地识别标记”，不能显示“已取消订阅”或“已停止银行扣款”。年度／周度扣费识别后续扩展。

这里的周期分析是本地流水统计，不宣称已经对接银行订阅服务；后续银行订阅查询／取消须按官方黄色权限设计，不用本地分析的权限安排替代赛题规则。

## 5. 权限、状态和审计

后端使用动作白名单，客户端不能传入“绿色”覆盖服务端判断。查询和本地统计为只读；导入正式数据、本地候选标记等写入必须明确确认。未接入的银行动作直接返回能力不可用，不进入成功状态。

可确认操作状态：待确认 → 完成／取消／失败／过期。准备操作时冻结对象、来源、金额或标记内容、证据与数据版本。确认时检查工作区归属、预览／确认有效期和对象是否变化；变化后要求重新准备。

同一操作重复确认不能重复写入。幂等键对应不同内容必须报冲突。多个页面同时导入或标记时不能相互覆盖。审计至少覆盖导入确认及结果、标记准备／确认／取消、能力拒绝和版本冲突；普通页面自动刷新无需无限追加日志。

本阶段的本地确认流程为后续权限体系提供基础，不等同于正式银行多因子认证。红色业务的验证和授权凭证必须在接入环境确定后设计。

## 6. 前端与对话接入

账户页先展示清晰的“内置模拟账户”或“本地导入账单”来源，再展示月份选择、统计、分类、待核实提示、周期扣费和操作记录。保留现有三种模式与视觉风格，新增局部样式即可，不进行整站重构。

原资产展示从共用服务获取；导入账单缺少余额／持仓时显示未知，不回退到默认模拟数字。读取失败显示错误及重试，不能静默展示旧来源。导入或切换数据集后，所有模块同步读取同一版本；旧的确认弹窗在版本冲突时失效。

对话入口首版支持明确意图：分析上月账单、分析指定月份账单、查看消费分类、查看疑似重复扣费、查看疑似周期扣费。账单计算和回复事实来自本地工具，不需要模型 API，不将原始流水发送给第三方模型。

月份以服务端北京时间解析；“上月”采用日历月。缺省使用最新有数据月份时必须在回复中说明。年份不明、多个期间、年度范围和复杂混合任务均需说明当前范围或追问，不忽略一部分任务后声称全任务完成。含取消、申购、转账等动作的请求不得在只读查询路径中执行。

回复沿用现有 `reply/intent/agent_chain` 结构，返回来源、期间、实际工具步骤和证据，避免虚构执行过程。本地金融意图不得落入通用理财推荐兜底，服务失败也不得编造账户事实。

## 7. 实施顺序与交接检查点

| 顺序 | 工作 | 该步完成的可验证结果 |
|---|---|---|
| 1 | 数据模型、持久化、独立演示数据和来源切换 | 重启服务后数据保留；演示和导入隔离；未知余额显示未知 |
| 2 | CSV 预览／确认导入、幂等、权限及操作审计 | 取消不导入；错误整批回滚；重复提交不重复记账 |
| 3 | 月报、分类和异常规则 | 金额可对账；每项提示能回到对应流水 |
| 4 | 周期扣费识别、预计日期和本地标记 | 证据可查；确认／忽略持久化；未改变银行业务 |
| 5 | 账户页和对话查询接入 | 浏览器中跑通从导入到查询、查看证据和操作日志的流程 |

优先逐步交付，底座验收通过后再接功能。不要在此阶段增加银行订单、花式大模型分析、新的多智能体编排或大规模产品库更新。

## 8. 验收要求

针对真实边界写有意义的测试，并运行既有相关回归，不重复启动无关全量评测：

- 金额精度、退款／转账口径、分类合计与报告一致；零数据不推断真实余额。
- CSV 无效行、冲突流水、同内容重复导入、确认取消与过期、原子回滚。
- 演示／导入隔离、不同工作区隔离、同一请求重放和并发确认。
- 月末预测、缺失月份、同月多次普通消费、金额波动和无精确时间记录。
- 数据变化后旧确认被拒绝；跨工作区操作、未知动作和自报权限被拒绝。
- 注入型商户文本按普通数据显示；静态服务不能下载数据库；新金融接口不能跨站读取账单。
- 本地账单对话不触发外部模型、不会改投资画像；不支持的期间／混合动作说明准确。
- 既有理财推荐、产品比较、画像和页面跳转没有因本次接入损坏。

必须做真实浏览器验收：演示数据 → 切换月份 → 查看证据 → 导入预览并取消 → 确认导入 → 重复导入 → 对话查询 → 本地标记确认／取消 → 刷新及重启核查。覆盖桌面与手机宽度、三种模式，检查加载／失败／空数据状态、横向溢出及控制台错误。

交付时说明实际实现项、测试结果、未接入业务与剩余问题，附页面截图和可运行入口。第一场允许自建模拟接口不等于当前首版已完成这些业务；通过本地底座验收也不等于完成第二阶段模拟执行或生产银行接入。

## 9. 实施与验收记录（2026-10-04）
