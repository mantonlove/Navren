# Navren 每日六条精选与历史热点实施验收

记录日期：2026-10-06。实施依据为《Navren每日六条精选与历史热点落地方案》。

**当前状态：归档后端、历史页面和引用校验已实现，首次真实公共资讯更新已完成；主服务 API、Agent 工具及个人收藏返回链接的接线尚待并发 owner 完成。本文件不作为全链路完成证明。**

## 一、已实现的合同

- 每日最多六个不同事件，由服务端从已审核、原文可核验且版本绑定的候选中选出。当天不足六条保留真实数量；不以复制、改日期或测试夹具补足。
- 每日清单、位置、事件版本、主报道及原文版本、分类、颜色主题、已审核短文案和排序依据在公共资讯库原子保存。相同日版次幂等；跨日有效检查产生新日版次，不受事件指纹未变的影响。
- 历史窗口为北京时间今天及此前 29 天。实际精选为 observed，首次按真实报道日期补录为 reconstructed；未采集缺档与已检查但无合格内容分别表示。补录不覆盖实际版次，事后修订材料单独标记。
- 历史读取保留当日位置与原始数量。源文修订、撤回或暂不可访问时屏蔽失效摘要、事实及中英文解读，不自动替换为当前版本；最新版本须通过明确入口另选。
- 401、403、阅读权限与网络失败表示暂不可访问，保留缓存身份，不冒充撤稿；确认 404/410 才按撤下处理。
- 按日期与类型交集筛选，单一分类菜单。历史页面复用发现子视图与阅读面板；首页保留现有封面流，导航居中、历史入口靠右。日期/分类更新替换当前历史节点，避免大量筛选节点。
- `PageContexts` 校验归档日期、日版次、事件版本和实际成员关系。字段不齐、版本冲突或内容失效受控拒绝；旧普通事件引用兼容。页面转对话仍是可编辑草稿，无执行授权。
- 复用已有 08:30、12:30、18:30 检查与互斥锁。首次更新仅刷新热点，不重新发布市场周报。GET 读取不补造归档。

选稿权重是可解释的产品参数，未宣称经实证校准；事件合并要求同报道、经审核事件组或可靠原始发布身份，机构相同或一句通用引用相同不构成合并依据。

## 四、待完成的接线及交付边界

同一文件已有其它活动 owner；共享协作规则要求一个文件同时只有一个写入者。具体接线合同已保存为 `outputs/daily-market/integration-handoff.md`：

1. `server.py` 将热点与历史路径交给 `MarketStore.route`，保留空参数校验和 400/404/409/503；消费页面票据后保留权威归档参数，不能让旧客户端 market_context 覆盖。
2. `agent_runtime/bank_tools.py` 的 market_event 工具接收并强制遵循 edition_date/revision/event_version；绑定本轮已校验身份，缺省补齐、冲突拒绝，禁止静默读取最新。
3. `agent_runtime/conversation.py` 传递并绑定相同归档引用，工具证据与回答来源匹配。
4. `js/mine.js` 与 `js/mine_workspace.js` 的收藏/继续阅读链接保留已有 archive，不丢失归档日期和版次。
5. owner 完成后，在隔离库验证 HTTP 状态码与真实工具身份，再协调重启持久本地服务、读取新 release 及实际历史 API。现有本地服务仍运行旧后端，历史 HTTP 路径尚未开通。

用户已授权并已向「RAG构建」和「Agent构建」发送接线合同。RAG随后按多窗口分工释放前端，由UI登记接手；基座持有服务接线与发布，Agent持有归档引用及最终证据门。源码已有历史路由，但现役服务仍需集成窗口冻结后复验发布，不能将源码存在当成已上线。
