## 1. 本次交付目标

发现首页的市场热点每天展示最多6条精选，保留现有真正的左右滑动封面流。轮播下方的上一张、页码、下一张整体居中，同一行右侧新增轻量“历史热点”入口。

点击入口进入发现内的历史热点子页面：桌面左侧紧凑月历，右侧两列新闻卡片，按日期与类型共同筛选最近30天的每日精选。历史保留当日的顺序、内容版本和出处。

主页面承担轻松浏览，历史页面承担查找。第一版不增加搜索框、排序菜单、日期范围拖拽、第二套轮播或新的顶部栏目。

## 3. 首页布局与封面流

```text
市场热点  ?                                      10月05日精选

       左侧真实邻卡       中央完整卡片       右侧真实邻卡

                         ‹   2 / 6   ›           ◷ 历史热点
```

### 底部布局

- 以整个轮播舞台的宽度为基准，导航组在舞台中轴居中；历史入口在同一行靠右。
- 推荐三列网格：左右两列等宽，中间为导航组；左列留空，右列放历史入口。不要把入口直接接在导航组后面，否则导航整体会左移。
- 历史入口使用时钟线条图标和文字，背景透明，悬停有浅色反馈；普通模式点击区至少44px高，关怀模式至少48px。
- 箭头保持现有点击区，页码使用等宽数字。历史入口的鼠标、触摸与键盘事件不触发轮播拖动。
- 普通手机在空间允许时保留同行；英文长文字、大字号或极窄宽度放不下时，历史入口换至下一行靠右，导航仍居中。禁止缩字、裁字或重叠来强行同行。

### 卡片与刷新

- 有6条显示 `1 / 6`；不足6条显示实际数量，不复制、不补虚构新闻。
- 2条时只有两个独立事件，不能伪造第三张；1条时不切换；0条用简洁空状态，历史入口仍可进入。
- 保留现有左右拖动、侧卡点击居中、键盘切换、首尾循环与减少动态模式，不新增自动播放。
- 导航只改变阅读位置，不发请求；后台刷新先保留当前事件ID。拖动中或解读面板打开时暂缓应用新清单，结束后再更新。
- 默认标题仍为“市场热点”，日期使用服务端精选日期。最近一次成功内容来自前一天时显示“最近精选 · 10月04日”，不把旧内容标为今日。
- 原文发布时间继续留在卡片中，日期和来源不能为了简洁全部删除。

## 4. 历史热点页面

### 桌面组织

```text
‹ 返回今日热点          历史热点  ?

┌──────────────────┐   10月04日 · 6条精选        类型：全部 ▾
│     2026年10月    │
│ 一 二 三 四 五 六 日│  ┌──────────────────┐ ┌──────────────────┐
│      紧凑月历     │  │ 类型 · 报道时间  │ │ 类型 · 报道时间  │
│  有内容日期带圆点 │  │ 两行新闻标题     │ │ 两行新闻标题     │
│  当前日期有选中底色│  │ 一句摘要         │ │ 一句摘要         │
│                  │  │ 来源   阅读原文 ↗│ │ 来源   阅读原文 ↗│
└──────────────────┘  └──────────────────┘ └──────────────────┘
```

- 内容区与现有发现页对齐，最大宽度约1120px；月历宽度约240—264px，栏间距24—28px。
- 可用内容宽度约980px以上采用“左月历＋右两列”；中等宽度保留左月历，右侧改一列。判断实际内容宽度，而非只看屏幕宽度。
- 月历顶端显示月份和标准上／下月箭头，只能浏览与最近30天相交的月份。相邻月日期在窗口内的仍可选择，窗口外日期禁用。
- 第一版每次只展示所选一天的最多6条，不把180张卡片一次铺开，不需要无限滚动或分页。

### 手机组织

月历收进“10月04日 ▾”日期入口，点击在入口附近展开月历；选中后收起。日期入口与一个类型菜单组成紧凑筛选行，新闻单列排列。保留明显的返回入口，不通过左右滑动新闻来切日期。

### 日期与类型

- “近一个月”统一定义为北京时间今天及此前29天，包含今天，共30个自然日。公开资讯时钟独立于用户模拟银行的业务日期。
- 默认选最近一个有可展示精选的日期，并在标题明确显示日期；有今天的数据时默认今天。
- 进入指定日期的深链接时保留该日期，即使没有数据，也不能跳到其他日期。
- 日期和类型为交集筛选。选择类型后再换日期保留类型；某日无匹配结果时不偷偷换日期或改回全部。
- 切换筛选只更新右侧标题、数量和卡片，月历与筛选控件保持稳定。
- 月历日期圆点表示当天有归档；选中日期有独立底色，今天用细描边。类型筛选后可显示该类是否有内容，但不抹掉当天存在其他类型归档这一事实。
- 有数据日、当天确实没有合格精选、尚未建立档案，是不同状态。缺档日期允许点击查看原因，不能把“未采集”写成“没有新闻”。

### 分类合同

展示“全部”加下列分类，只使用一个选择菜单：

| 稳定ID | 中文名称 | 主要内容 |
|---|---|---|
| `household` | 民生金融 | 缴费、消费信贷、住房资金、养老与个人金融权益 |
| `macro_policy` | 宏观政策 | 宏观数据、利率与货币政策、财政及监管政策 |
| `investment` | 投资市场 | 股票、债券、基金等投资市场事件 |
| `fintech` | 金融科技 | 数字支付、银行技术、金融AI等金融应用事件 |
| `international` | 国际市场 | 跨境金融、汇率、海外市场及国际金融事件 |
| `general` | 综合金融 | 经审核但不适合前述类型的材料 |

每条精选只保存一个主要筛选分类，可以有辅助标签，辅助标签不造成重复卡片。重叠情形以事件主要对象和既定分类规则判定：宏观政策公告优先归宏观政策，个人住房缴费权益优先归民生金融，跨境或汇率变化优先归国际市场。不能仅凭机构名称推断。

分类是内容字段，由服务端提供稳定ID并审核。颜色主题与筛选分类分别保存：现有“利率政策”的浅绿、民生的暖米、国际的浅紫等可继续使用，不必因为合并筛选类型就重画全部卡片。无该类资料时允许分类为空，不为每类硬凑新闻。

2026-10-19 配色补齐：宏观雾蓝、利率浅绿、民生暖米、国际浅紫继续保留；投资市场使用柔玫色、金融科技使用浅青色、综合金融使用雾灰色。首页主卡和侧边预览、历史卡片、解读面板共用主题变量，深色模式对应调整亮度并保留颜色区分。展示优先按已审核的分类映射主题；宏观分类的既有利率子主题仍保留浅绿，缺少分类的历史对象继续兼容原主题。不修改服务端分类、原文、版本或筛选条件，也不为展示颜色补造某类报道。

### 历史卡片

- 轻量纸面卡片，圆角16—18px，内边距20—24px，列间距16—20px；沿用主题语义颜色，淡背景、细边框、轻阴影。
- 顶行：类型标签与报道日期；中间：标题最多两行、一句摘要最多两行；底部：来源与“阅读原文”。普通模式标题约18—20px，摘要约14—16px，关怀模式服从全站字号。
- 标题与摘要按列对齐，来源行落在同一基线；不塞入大数字面板、长篇分析或多排按钮。卡片高度随阅读字号自然增高，不截掉操作区。
- 标题是明确的“查看解读”入口，卡片空白处也可打开同一详情；阅读原文是独立链接。避免在一个链接内部再嵌套另一个链接，原文操作不能连带打开解读。
- 卡片正文只用经过审核的短文案；没有匹配版本时使用原事件已审核的标题与摘要，不在前端凭标题生成分析。
- 详情复用已有阅读面板，补充归档日、当时的事件版本、报道日期和具体原文来源。关闭后回到原卡片位置。

## 5. 每日六条的产生与保存

### 选稿规则

“每天最热”在这一版落为“每日6条重要精选”。当前没有全网点击量或转发量数据，不能生成虚假的热度值、阅读量或“全网第几名”。可在标题问号中简短解释选稿依据，不在正文堆说明。

1. 先沿用原文白名单、可读全文、事实与数字证据、独立审核等发布条件。只从已批准事件中选择，不能把采集成功当作发布成功。
2. 同一事件的公告、解读和转述合并为一个事件组；保留多个有效原文，不因为发布机构相同就合并不同事件。
3. 优先近72小时的新信息。最近7天的重要事件仅在仍有明确时效与关注理由时进入候选；报道日期始终如实显示。不能把旧文改日期填满今日。
4. 以事件影响范围、与个人金融的关系、新信息程度和新近程度形成可解释的选稿优先级。记录排序理由、使用的证据和规则版本；初始权重只是产品参数，不宣称经实证校准。
5. 排序后取最多6个不同事件，避免同一机构、同一题材长期包揽全部卡片；多样性用于相近优先级的取舍，不能为了配色或分类完整降低证据质量。
6. 同分采用固定的时间与事件ID规则，保证重复运行结果稳定。展示层不再另行排序或筛掉后自动补一条未经选稿的新闻。

### 当天更新与跨日封存

- 08:30、12:30、18:30的有效检查完成后计算当天精选，与现有任务共用互斥锁，写入必须原子化、可幂等重跑。每天第一次有效检查必须建立当日日版次，即使事件指纹、清单与昨天相同；同一天后续清单或绑定版本变化时才增加版次。
- 有效检查确认没有合格候选时建立0条日版次，这是“当日无合格精选”。任务未运行、核验失败且没有成功版次时属于缺档。旧的审核事件因指纹未变而跳过再次发布，不能阻止正常日归档；局部来源失败记录覆盖不足，不能冒称全量核验后0条。
- 每个版次最多6条。当天历史页读取当前日版次，日期标题用小标识“更新中”；已结束日期读取最后一个有效版次。
- 跨日只封存已经实际生成的前一天版次，可在现有定时检查或恢复运行时完成，不新增一套每分钟唤醒的任务。
- 某时段失败保留当日上一成功版次，记录最后成功时间；一天没有运行，标为缺档，不能次日把当前新闻回填成昨天的实际精选。
- 归档和首页读取同一清单。重启、浏览器刷新和用户切换不会导致同一归档日重新按当前热度排序。

### 初次启用时的一个月历史

目前不存在30天每日精选快照，不能凭已有事件版本声称已经完整覆盖。

第一版可对最近30天可核验的真实材料做一次按报道日期补录，逐日去重、审核、最多6条。这种资料标记为 `reconstructed`，页面日期标题显示“历史补录”；问号说明“按真实报道日期整理，不代表系统当日实际选稿”。补录发生时间另存，不能回写成过去的采集时间。

实际日精选标记为 `observed`。过去某日已有实际日精选时，不用补录清单覆盖。无可靠材料的日期保留缺档，不编造180条新闻、不复制相同6条填满一个月。测试夹具放在隔离测试库，不进入正式归档。

补录归属日取事件主报道的北京时间发表日期，并保存主报道ID；不能直接沿用当前事件“所有来源中最早的日期”。附加材料若发表于该日24:00之后，不纳入该日事实与摘要，可以单独形成其真实日期的后续事件。原文时间只有日期精度时保留这一精度，不虚构具体时刻。只能获取事后修订版本的材料另标“事后修订资料”，记录可确认的修订时间与实际补录时间，不呈现为当日已知信息，也不声称重建出当日原始版本。

## 6. 数据、接口与版本合同

在独立公共资讯库 `market.sqlite3` 增加每日归档表，不放进四个用户的财务数据库。

建议两张表；名称可按现有规范调整，语义必须保留：

| 表 | 必需内容 |
|---|---|
| `market_daily_editions` | `edition_date`、`revision`、时区、`origin`（实际／补录）、`period_state`（更新中／已封存）、`selected_at`、`created_at`、`run_id`、选稿规则版本、条数、内容指纹 |
| `market_daily_items` | 日期与版次、位置1—6、事件ID及版本、原文ID及版本映射、筛选分类、颜色主题、已审核展示文案及版本、选稿理由、必要的事件与出处快照 |

约束：日期＋版次唯一；同版事件ID唯一；同版位置唯一；原文与事件版本存在且一致；表头与条目同一事务提交。后续修订或撤稿的可用状态单独解析，不覆盖原始快照内容。快照存已有获准展示的短文案和证据引用，不把新闻全文复制到前端。

拟增加／调整接口：

| 接口 | 合同 |
|---|---|
| `GET /api/market/hotspots` | 保留原入口及兼容字段；返回当前有效日精选，附 `server_today`、`edition_date`、`revision`、`origin`、`period_state`、`selected_at`、最多6条事件 |
| `GET /api/market/hotspots/history?from=…&to=…&category=…` | 返回近30天日期索引、各日归档／缺档状态、总条数和类型匹配数、分类定义；不一次返回180份详情 |
| `GET /api/market/hotspots/history/YYYY-MM-DD?category=…` | 返回所选日的版次、当日总数、筛选后数量与卡片；缺档和有归档但0条分开表示 |
| `GET /api/market/hotspots/history/YYYY-MM-DD/events/ID?revision=N` | 读取该日该版的具体事件，核对当前修订／撤稿状态，并提供可用的新版本指针 |

所有日期按北京时间解释，最近30天窗口由服务端确定。非法日期、未知类型、未来日期、超窗口日期和非法版次返回受控400；不存在的详情返回404；真实服务故障返回503，不能统一伪装成“没有新闻”。

### 历史事实与后续更正

归档保存“当时选过什么”，不意味着错误或已撤回的事实可以继续传播。

- 未修订且原文仍可用：展示绑定的历史版本，不能经现有默认详情接口悄悄取最新版。
- 原文或事件修订：保留归档位置及标题元信息，标记“内容已修订”，停止展示失效摘要／事实。由用户明确选择“查看最新修订”，再显示当前版本及其日期。
- 撤稿：保留一张简洁的撤下记录，不展示失效正文，不补进另一条新闻改变当天顺序。
- 链接临时不可用：明确说明原文暂不可访问，区别于撤稿；不把失败当作已核验。
- 历史清单的原始条数、当前可读条数分别保存。更正处理不能让归档偷偷恢复成看似完整的6条。
- 从详情问Navren时传递日版次、事件版本及来源身份；后端沿用现有证据有效性核验，不把已经失效的历史内容当作当前事实。

这一步必须贯通跨页上下文与市场工具：现有 `server.py` 的 `market_context` 只接受 `{kind,id}`，`view_context.py` 与 `market_event` 工具也默认解析最新事件。执行时扩展可校验的归档日期、日版次和事件版本；由服务端查库确认该事件确实属于指定日版次，确认后才交给Agent。通过页面上下文票据传递稳定引用与返回位置，不依赖前端附带的新闻正文。工具读取同一历史对象时必须遵循已确认的版本身份；参数缺失／冲突或版本失效要明确处理，禁止静默降级到最新版。用户明确选择最新修订后，才建立对应的新引用。保留旧 `{kind,id}` 普通提问兼容性。

## 7. 返回、状态与国际化

新增 `market_history` 发现子视图。推荐可分享地址：

```text
recommend.html?view=market_history&date=2026-10-04&category=household
```

复用 `NavrenViews`。内部使用 `date`、`filters.category`、`listposition`、`scrollposition`、`focustarget`，为本视图补齐URL解析与序列化；不要另写第二套路由。

- 首次进入历史页建立一个浏览器历史节点；日历与类型变更更新当前节点，避免用户后退要逐个倒放几十次筛选。
- “返回今日热点”和浏览器后退恢复原封面流事件ID、页码、滚动位置及入口焦点。入口直达的页面返回发现首页。
- 原文默认新标签打开，历史页保持日期、类型与滚动；同页返回或浏览器页面恢复也保存这些状态。
- 历史解读关闭后恢复原标题入口；若原卡撤下，焦点回到所选日期标题，而不是跳到首页轮播。
- 快速连续换日期／类型时取消或忽略旧请求，只允许最新请求更新画面。开始加载时保留筛选控件，卡片区给轻量骨架，不显示旧日期下的新闻冒充新结果。
- 缓存按日期、版次和类型区分；语言变化重画界面文案。公共新闻可共用缓存，收藏及阅读记录继续按现有个人数据边界处理。
- 所有新增控件、类型名称、空状态、修订提示、月份星期、工具提示及可访问名称进入全站中英词典，初次渲染直接用已选语言，避免中文闪现。
- 来源原名、报道原始标题与原文保持其实际语言；若提供英文短标题／摘要，必须属于同一审核版本。不能把缺失翻译伪装成已审核英文内容。

空状态文案分别处理：近30天尚无归档、所选日尚未建立档案、当日没有合格精选、该类型没有匹配项、服务读取失败。只有服务失败提供重试；类型无匹配提供轻量“显示全部类型”，不新增大按钮区。

## 9. 可操作验收

| 检查 | 通过条件 |
|---|---|
| 数量 | 9个合格候选只展示6个不同事件；5／2／1／0条时数量与交互真实，无重复填充 |
| 横向关系 | 慢拖时左右卡片连续进入／离开；第6条与第1条循环正确，原文与历史入口不会误触拖动 |
| 入口位置 | 桌面导航中点距舞台中轴不超过2px，历史入口在同一行靠右；英文及关怀版同样检查 |
| 归档 | 当日多次更新有版次；封存后重复运行、重启不改变清单；同一次更新不产生重复条目 |
| 正常无新增 | 事件无新增、同昨日清单仍产生当天首版；有效检查0条与未运行缺档可区分 |
