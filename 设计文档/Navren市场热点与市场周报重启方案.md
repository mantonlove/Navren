# Navren 市场热点与市场周报重启方案

日期：2026-10-04。交付性质：实施方案，供另一个窗口执行。本轮仅检查代码、核实来源和编写文档，没有重新启用页面、采集任务或发布真实周报。

执行目录：`/Users/manton/CC/projects/Navren`。以执行时最新代码为准，不在历史 `qingzhou` 目录重复实现。

## 1. 最终定位

采用“权威原始发布 + 专业原创报道 + 有依据的 Navren 解读”的内容体系。

- **市场热点**：精选近期 3—6 件值得关注的变化，帮助用户在约两分钟内了解发生了什么、影响通过什么路径传导、哪些判断仍有条件。
- **市场周报**：一份约五分钟的完整阅读，解释本周最重要的三项变化，提供可核验的数据对照与下周已公告日程。不是七天新闻标题拼接。
- **原文阅读**：热点标题/“阅读原文”直接打开对应报道；周报各段分别链接其支撑报道。付费原文明确标识。
- **对话联动**：“问 Navren”传递新闻/周报对象 ID，后端加载对应证据，再回答用户的问题。只传标题不足以让模型了解原文。

内容首先服务银行客户的存款、借贷、理财、资金期限和风险理解。热点发现范围包括宏观政策、利率/债券、权益、汇率、黄金及与金融相关的重要产业变化；不按标题刺激程度或点击量排序。

本轮不增加自动交易或新闻驱动的买卖信号，不估算没有真实估值依据的用户组合收益。

## 3. 来源白名单与真实接入方式

来源分层表示职责，不代表任一来源的任何文章都自动通过事实审核。

### 3.1 原始事实层：默认优先

国内优先：中国人民银行、国家统计局、财政部、金融监管总局、证监会、外汇局、交易所及相关指标的原始发布机构。国际优先：美联储、欧洲央行、IMF、BIS 等。

政策/数据卡片应优先附发布机构原文；采访、背景和观点用专业报道补充。实际发布日期、数据所属期间、政策生效日分别记录。

### 3.2 专业报道层：重点选择

优先纳入 Reuters（路透）、财新、Financial Times（金融时报）、Bloomberg（彭博）、The Wall Street Journal（华尔街日报）。新华社经济报道可作为公开内容的重要补充。

这些媒体的公开发现入口、全文可读性、自动采集能力和产品内使用范围必须分开核验。可读取元数据不等于已获全文或转载许可；没有完整可读取材料时，提供核验过的标题/原文入口，不编写深入摘要。不要为了填满栏位降级到匿名自媒体、营销号或无原始来源的转载。

## 4. 热点怎样做到有用

### 内容结构

每个事件卡片包含：

1. **发生了什么**：准确中文标题，60—120 字摘要；数值保留期间、单位和事实性质。
2. **为什么值得关注**：一条具体传导路径，例如利率政策如何影响融资成本或资产估值，并写清适用条件。
3. **仍有哪些不确定性**：只写与事件有关的边界，避免每条重复整段通用风险提示。
4. **原文与身份**：发布者、原始发布时间、内容类型、是否需要订阅；有官方发布和专业报道时提供两个独立入口。
5. **相关解释**：与用户授权兴趣/真实资产类别相符时才显示“与你相关”及依据；无资料时提供公共版，不默认猜风险等级或持仓。

默认首页展示 3—6 个事件，完整列表最多 12 个；合格内容不足时少展示。近 72 小时优先，仍具重要影响的事件可保留到 7 天并注明首次发布日期；再旧的内容进入历史/背景阅读。假期无新披露时显示最近已核验内容的实际日期，不能更改为今天。

### 筛选与排序

先经过硬门：白名单发布者、可核验具体原文、明确时间、可用材料、没有撤稿或未解决的关键冲突。之后按以下设计初值排序：

```text
重要性 35% + 新增事实 25% + 事实支持质量 20% + 时效 10% + 授权相关性 10%
```

权重是待验证的设计参数，不是实测效果。保留排序理由；不能仅让模型给一个“热度分”。重大公共风险/制度变化保留公共位置，不因用户只关注黄金而完全隐藏。

按事件聚类，转载和同源改写不算多个独立证据。模型可以辅助识别同一事件，但来源和证据绑定由代码核对；官方原始发布通常一份即可支持对应事实，争议解释需分别显示来源与分歧。

## 5. 周报怎样做到值得读

标准周报包含：

- **本周三项变化**：每项解释“新信息改变了什么认识”，每段有原文引用。
- **关键数据对照**：仅展示已核验指标，例如政策利率、某个明确股指、汇率或国债收益率；不使用笼统“固收类 +X%”。
- **传导与分歧**：影响哪类资金需求/资产、需要什么条件、哪些因素可能抵消；明确区分事实、媒体观点和 Navren 分析。
- **下周关注**：来自发布机构已公告的会议/统计日程，附官方日程链接；未核实的不填。
- **原文书架**：3—5 篇值得继续阅读的原始发布或专业报道，注明推荐理由和付费状态。

阅读总量控制在约 1000—1500 个中文字，首页只展示 150—250 字摘要和三项重点。每段重要论断均有证据，不为了字数扩写空泛判断。

周报周期默认周一 00:00 至下周一 00:00（Asia/Shanghai，结束时点不计入），下周一 08:30 生成上一周完整报告；如周日 18:00 提供预览，必须标为“本周进展”并显示截至时间。报告包含期间、数据截至时间、发布和修订时间。按各市场真实交易日/时区取值，休市注明实际最后交易日。

数值运算由代码完成：价格/指数变化以明确的期初期末值计算；利率变化用基点，不能将基点与百分比混用；汇率写清报价方向；价格指数与总收益指数不能混用。缺值显示暂无可核验数据，不用旧值或模型猜测补齐。

市场行情数据与报道证据分开保存。报道中仅有某日数值时，不能据此计算整周收益。没有真实持仓估值和产品透视数据，不写“你的组合本周预计涨了 X%”。

## 6. 数据、采集、生成和发布

新增独立的市场内容服务与存储，例如 `market_content.py`、`market_sources.py`、`market_editor.py`。市场资讯是公共数据，不改变模拟账户日期、余额、订单或财务记忆。

建议表/实体：

| 实体 | 必须记录 |
|---|---|
| `market_sources` | 来源 ID、发布者、允许域名、栏目/订阅地址、接入模式、启用状态、内容使用范围、最近成功/失败检查 |
| `market_articles` | 原文标题/中文标题、canonical URL、来源、原始发布时间/时区、事件时间、数据期间、读取范围、指纹、正文/证据版本、链接状态 |
| `market_events` | 事件聚类、关联文章、事实、Navren 分析、待解决冲突、排序依据、当前状态 |
| `market_claims` | 具体论断、来源/证据 ID、数值与单位、支持材料、审核结果 |
| `market_observations` | 指标身份、期间、观测时间、单位、原始值、来源 URL、修订与覆盖状态 |
| `market_weeklies` | 周期、截至时间、论点、数据表、日程、引用、审核、发布/修订版本 |
| `market_ingest_runs` | 本轮检查时间、各源状态、新增/变更/拒绝条目、生成/审核/发布结果、耗时 |

采集流程：

```text
官方订阅/允许的栏目/授权媒体接口
→ 条目与具体原文校验
→ 去重、修订检测与事件聚类
→ 事实和数值提取
→ DeepSeek 草拟精选摘要/周报
→ 确定性校验 + GLM 独立核验
→ 发布不可变版本
→ 页面和聊天读取缓存
```

模型不承担凭空发现新闻或创造 URL；解读只能基于实际读取范围。材料分为 `full_text / permitted_excerpt / metadata_only / unavailable`，深度解读不能从 `metadata_only` 推断整篇报道内容。原始文章内容进入模型时作为不可信资料，不可成为工具指令。

保存短事实证据、必要摘录及指纹，全文保存与展示按来源使用范围处理。报道正文不整篇搬进 Navren。双模型通过不替代数值/日期/链接的程序核对，也不证明绝无错误。

热点与周报分别发布；审核拒绝、解析失败或部分来源超时不能覆盖最近合格版本。允许发布注明覆盖不足的降级内容，但不允许遗漏标记后冒充完整覆盖。更正/撤稿触发撤下受影响热点和周报修订，保留修订记录。

## 7. 更新和失效处理

实施时设置可配置后台刷新，建议热点每天 08:30、12:30、18:30，完整周报每周一 08:30 生成上一周期；周日 18:00 可选生成“本周进展”预览。本方案不创建用户的 Codex 定时任务。应用未运行时是否继续刷新，必须依据真正安装和验证的后台任务说明，不能只在文档写时间。

页面直接读缓存，不在每次打开时重新抓全网或调用两个模型。服务启动可异步检查缓存；任务有锁、总超时、单源超时、限流和有限重试。RSS 下载上限建议 10 MB，先读响应限额再解析，避免统计局合法大订阅被截断；只增量处理新内容/修订，不重新总结 500 条存量。

时间字段严格分开：`published_at` 原始发表、`content_updated_at` 来源修订、`fetched_at` 成功读取、`checked_at` 最近检查、`generated_at` Navren 生成、`released_at` Navren 发布。检查成功但无新文章，不改文章日期，不重发同一摘要。

市场日期使用真实时钟和市场日历，不沿用模拟银行的固定业务日期。固定样例只能在独立 demo 模式，且界面显著注明。

失败规则：

- HTTP 200 后仍检查 RSS/XML、标题、日期、文章正文/元数据；验证码、登录页、软 404 不当作全文。
- 失效链接标记原报道不可用；若同一事件还有已核验的具体原始发布，新增带正确发布者与日期的替代阅读入口，保留原链接与修订记录。找不到则撤下当前入口，不改跳机构首页，也不覆盖原报道的身份。
- 付费墙标明原文需要订阅；没有全文时保留合法元数据入口，不生成深入解读。
- 没有新数据可以显示“已检查，暂无新增”；采集故障显示“更新暂不可用，截至某时”。
- 过期/撤稿内容不进入当前热点；旧周报留在历史档案，不能只改周期标签冒充本周。

## 8. 页面、点击、收藏与对话

### 热点

- 标题使用真实 `<a>` 链接，在新标签页打开对应报道；设置 `noopener noreferrer`，允许键盘、复制链接和浏览器正常行为。
- “Navren 解读”单独展开事实、分析和引用；“问 Navren”“收藏”是独立按钮，点击不触发卡片跳转。
- 明确显示发布者、日期、报道/原始发布/观点身份；付费入口标记“原文可能需要订阅”。
- 有双来源时：“官方发布”“专业报道”分别指向具体页面。

### 周报

- 点击周报标题打开 Navren 的完整周报视图（自编综合内容没有单一外部原文）。
- 三项重点及每个实质段落提供“查看对应原文”；数据表与下周日程也有各自来源。
- 提供历史期号和更正提示；不以当前时间覆盖旧报告日期。

### 模块开关

两模块默认可见。保留用户显式关闭模块的选择；“提醒订阅”单独配置，不用推送开关控制页面内容。

迁移 `weeklyReport=false` 等旧偏好时保留原关闭意图，不强行重开。新用户按新版默认展示；旧用户可通过页面入口重新启用。移除“始终可见”与实际行为不一致的注释/提示。首版没有提醒服务时不能显示“已订阅推送成功”。

### 收藏与对话

收藏保存稳定对象 ID、标题、来源、原文 URL、发表日期与收藏时版本。再次打开时核验最新状态，撤稿/失效有提示。

增加只读工具 `market_hotspots`、`market_article`、`market_weekly`，返回实际内容及证据；聊天附对应来源卡片。前端传递对象 ID，后端核验，不能只把标题拼成问句让模型自己猜。

个性化依据当前账户的授权兴趣/已确认资产类别，不能用浏览器旧持仓或未经确认的名称推断当事实。公共新闻采集不上传个人账户数据；解释用户影响时再读取最少必要本地资料。关闭记忆时仍可阅读公共版。

下周已核验发布日程可提供“加入财务日历提醒”，复用已有事件确认卡；不会自动写入私人日历或产生资金安排。

## 9. 接口与安全渲染

建议接口：

| 接口 | 功能 |
|---|---|
| `GET /api/market/hotspots` | 当前合格热点、覆盖范围、更新时间和可用状态 |
| `GET /api/market/events/{id}` | 事实、解读、引用和对应文章 |
| `GET /api/market/articles/{id}` | 原文元数据、链接状态和允许展示的摘要 |
| `GET /api/market/weeklies/latest` | 最近已发布完整周报，不把草稿当成完整期刊 |
| `GET /api/market/weeklies/{period}` | 指定期号、修订版本和引用 |
| `GET /api/market/status` | 精简来源/更新时间状态；不暴露凭据或内部地址 |

市场内容可为公共只读，个人排序和对话解读遵循现有会话权限。管理员刷新不暴露为任何用户都能调用的无鉴权 GET。

每个响应带 schema/content 版本、实际截至时间、状态与限制。URI 只允许白名单 HTTP(S) 文章路径；验证最终跳转域名和具体文章身份，拒绝脚本 URL、机构首页、搜索结果和伪造发布者。采集器不接受任意用户 URL，避免把服务器当抓取代理。

前端使用安全 DOM、标准链接与独立按钮，不能把新闻标题/摘要插入未转义的 HTML 或内联事件。新内容使用版本/ETag 及受控缓存；核对实际加载的资源版本，避免旧静态 JS 覆盖新 API。

## 10. 实施顺序

1. 重新核对现有页面/脚本和运行版本，声明精确写入范围；停用“只改时间”的发布路径，将旧样例隔离。
2. 建来源注册表与探测报告，先打通统计局 RSS、央行文章、国际官方订阅；核实一批具体原文。
3. 完成元数据、事实、指标、来源版本和链接校验，接口先返回真实数据；资金/账户模块不变。
4. 接 DeepSeek 生成与 GLM 审核，产出首批合格热点及一份对应完整期间的周报；不足则明确降级。
5. 重做两个模块的内容渲染、原文跳转、收藏与对话证据接入；迁移旧偏好。
6. 验证定时/重启更新、故障保留、修订撤稿和权限，随后加入财务日历日程入口。

首版至少交付两个中国官方来源、一个国际官方来源，以及实际核验的专业媒体原文阅读入口。专业媒体自动全文接入没有完成时，交付记录写清是人工精选/元数据发现，不声称已实现全自动媒体资讯源。

## 11. “效果好”的验收定义

### 硬条件

- 当前热点没有旧样例、虚假更新时间或机构首页充当原文。
- 每条卡片有具体报道链接、来源、原始日期、读取范围和事实依据；重要论断/数值均能追溯。
- 周报没有硬编码市场数字、笼统资产类别涨幅或无依据组合收益；时期、单位、基点和汇率方向正确。
- 标题点击确实到对应报道；点击解读/收藏/提问不误跳。付费页按实际状态标记，不谎称免费阅读全文。
- 同一事件不因转载占满列表；不能读取全文的材料不产生假深度摘要。
- 修订、撤稿、刷新失败和节假日无新增均显示真实状态，最近合格内容不被坏批次覆盖。
- 页面刷新、旧收藏、三种界面模式和手机宽度均可正常使用；不会加载旧静态池冒充 API 结果。
- 实际聊天调用对应市场工具并引用正确报道，能区分报道观点与自己的推论。

### 内容与体验评估

上线前抽查至少 10 条实际文章、2 个完整报告期间，覆盖官方原始发布、专业报道和付费/元数据受限情况；核对标题/日期/关键数字/引用/跳转一致性。

让少量目标用户比较“原始新闻列表”和“Navren 精选/周报”，检查能否说出关键变化、理解一个传导条件、找到原文，以及阅读负担。记录真实样本数与反馈，不把小样本写成普遍提升或比赛保证。

工程记录缓存接口与页面加载耗时、链接失效率、更新延迟、审核拒绝率、错误更正和模型成本。建议缓存接口 P95 不超过 1 秒、首屏主要内容约 2 秒可读，作为待测目标，不是当前已实现指标。

### 必须做的反例

旧文章改抓取时间、链接跳首页、200 登录页、截断 RSS、同源转载重复、付费墙、错误单位、跨时区日期、指标修订、季度数据当本周数据、来源超时、模型无效 JSON、审核拒绝、恶意 URL/文章指令，以及被删除文章的历史收藏。
