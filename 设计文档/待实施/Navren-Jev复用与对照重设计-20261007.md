## 结论

Jev 应承担有明确答案集合的语义判断，结果由代码直接消费。公共检索证据筛选是优先的产品候选；当前原件题的现有召回已覆盖、独立相关性标签不足，暂不能评价重排收益。因此本轮先准备两个有限只读启动计划，验证是否真正减少主模型规划；资讯批量预筛安排在后台。旧的“每轮先选一个 skill”不足以证明收益，必须具体减少一次主模型规划、减少无关上下文，或者改善证据选择。

金额、日期、对象身份、来源版本、权限和业务执行继续由后端负责。主模型解释方案，GLM 保留现有独立审核。模型渠道沿用用户已明确的分工：DeepSeek、GLM 经 AiPing；Jev 经 TypeSafe 官方。不会引入第四种模型。

## 黑客松实践的可用经验

[Jevolution](https://github.com/utkarshg20-org/jevolution) 的一等奖有作者声明和场地主办 CodeRabbit 官方转发支持，尚未取得完整官方榜单。其 MIT 源码由代码枚举合法动作 ID，Jev 只从中选择，执行前再次校验状态。Navren 可借这个结构选择已有只读计划，真正省去首轮自由工具规划；金额、权限和业务操作留给代码。其现有实现不提供通用的低置信强模型级联，这部分需要单独适配和校准。

[Tideline](https://github.com/edsonayllon/jev-prototype) 同为 MIT，但未核实获奖。它让 Jev 对资讯做有限分类和评分，代码组合结果并排序；调整权重可以复用已有判断。适合借到 Navren 的后台资讯预筛，不照搬其加密资产语料或阈值。

[GC AI 的内部黑客松原作者复盘](https://gc.ai/blog/what-we-learned-building-38-projects-with-jev-in-12-hours)展示了条款分段筛查、引用核对以及语义分类后由代码更新状态的用法。最有用的经验是：一个具体属性对应一个问题；对同一材料的独立判断可合并，不同材料分别并发；从已标注数据选阈值。其演示指标属于该团队的样本，不能写成 Navren 的收益。

JEVATHON 的项目、奖项依据、实际公开代码与许可分别核验，详见 [获奖项目证据](/Users/manton/CC/projects/Navren/outputs/jev-research-20261007/award-findings.md)。没有公开代码或许可的参赛项目仅用于借鉴；获奖、代码可读和可直接复用是三件不同的事。

## Navren 的三个接入点

### 公共检索：召回后、组装回答上下文前

正式源码的 [search_public](/Users/manton/CC/projects/Navren/local_knowledge/store.py:682)目前用 SQLite FTS/BM25，并保证产品、份额、渠道、时点和维度覆盖。[消费层](/Users/manton/CC/projects/Navren/agent_runtime/knowledge_retrieval.py:340)逐引用回查原文和许可。Jev 应只看到已经通过这些确定性检查的公共片段及已净化查询。

每个 query–passage 对判断“是否回答具体问题”“是否提供必要证据”“是否与问句前提冲突”。同一片段的这些判断合并一次请求；不同片段采用有上限的并发。排序与上下文压缩由代码完成，保留原文、原引用和缺项。不因某段评分低就丢掉唯一的费用、赎回或冲突证据；先评估重排，再决定是否启用过滤。

候选为空、只有一个确定匹配，或已能由规则解决时可以跳过 Jev。超时、低置信或未覆盖关键维度时沿用原检索结果或原澄清路径，计入回退成本；不能制造成功分数。现有最大候选数为八，不扩大接口只为让重排显得有用。

官方 [RAG passage cookbook](https://docs.typesafe.ai/cookbooks/classifying_rag_passages)和 [rerank cookbook](https://docs.typesafe.ai/cookbooks/rerank_typesafe)提供了相关模式。它们的示例阈值、其他语料结果不能直接成为 Navren 的设置或实验结论。

### Agent：选择受限只读计划，实际减少规划轮次

候选设计只使用 Navren 已有能力及“不匹配/需要原流程”。最新 v3 隔离实现限定为 `public_evidence_status`、`bank_service_entry` 和 `none`。前者固定读取公共知识状态；后者仅加载维护者注册的 `bank-service` 方法，参数由后端固定为 `load_skill({"name":"bank-service"})`，不让 Jev 生成技能名、工具名或参数。原加载成功后才扩展工具范围。没有将账户、预算、日历或操作计划扩入 Jev 选择；金额、账户选择、日期计算和权限仍由原后端控制。

只有任务、对象和参数已明确的请求才走受限计划。纯规则可识别的问题直接走既有规则；不额外调用 Jev。自由目标规划、歧义和复合任务回退主模型。选定计划必须真正改变调度或工具视图，已经加载的技能由运行时状态去重，不能只增加一段提示。

收益指标是原本的一轮自由选工具是否被替掉，而不是“Jev 选中了一个技能”。[官方 function calling 示例](https://docs.typesafe.ai/cookbooks/function_calling)可借有限参数与分派结构，示例中的金融动作不进入 Navren 交易执行。

### 市场资讯：后台处理，不增加聊天串行等待

[市场管线](/Users/manton/CC/projects/Navren/market_pipeline.py:20)已有来源覆盖与候选选择，[市场编辑](/Users/manton/CC/projects/Navren/market_editor.py:44)才进入主模型写作与审核。可在候选正文已经准入后判断“是否同一事件”“是否与用户关注主题相关”“是否含实际新增信息”，再由原代码决定哪些进入编辑阶段。

候选 ID 和原文版本不能变化，缓存键包含正文哈希、问题定义哈希、模型版本。按来源、事件和日期拆分调参集与评价集，防止同一新闻转载泄漏。既有来源多样性和原文准入继续生效。只有确实减少编辑请求、又保留必要事件时才可能节省费用。

接着分别评价三个问题：

1. **路由**：正确计划、必要参数来源、拒绝与回退覆盖率；用原有直接规则和主模型路径作实际基线。
2. **证据**：固定原始候选集合和 query，独立标注哪些原文支持问题；比较原排序与 Jev 排序的前列命中、关键证据保留和生成正确性。若已有词法题全命中、候选过少或没有标签，先标“无法评价收益”，不打乱候选制造改善。
3. **完整任务**：冻结同题同数据、模型、发布版本和限额，只改变一个 Jev 功能。保留失败在分母，同时报告成功配对耗时、总调用数、主模型上下文、回退率、用量和完整费用；未知费用不填零。

阈值在独立调参集上决定，评价集固定。金融原文题按文档/产品/来源分组，资讯按事件/时间分组，避免改写同题落入两边。不能拿 Jev 或 GLM 的批准作为黄金答案；高影响结论由确定性原件和独立逐项检查支持。

首批候选用于基础能力确认，不是足以宣传收益的统计样本。基础任务重复失败时先停止扩样定位问题。组件收益和整轮收益都验证后，才能决定是否默认启用或进入参赛 PPT。

v1 方法及指标已由 AiPing 的 DeepSeek-V4.1-Flash 与 GLM-5.3-Flash 实际双审，聚合 PASS；这只覆盖该方法包。候选 hook 位于隔离 overlay，正式 `conversation.py` 未被本轮替换。余额最新基线实际耗时 5.988 秒、两次主模型请求、8,695 tokens，固定单价完整估算及已匹配账单均为 0.008834 元；所问两个账户余额与同币种现金合计 24,390 元正确。审核者未读取采集结果或旧轮结论，但路径和继承背景暴露了基线身份，因此称独立语义核查，不冒称完全未知分组盲审。

新计划 A/B 的第一项 P08 基线在读规则后，被共用预算预留提前切到终结；终结请求又在 AiPing 35 秒超时，未取得 usage。该项共发出三次主模型请求、没有审核或 Jev 请求；完整费用未知，已停止后续收费。此次不能归因于 Jev，也不能生成配对改善百分比。已在本人登录的 AiPing 明细匹配成功请求；刷新后仍未见超时那笔，未见账单不等于没有扣费。

v2 只调整两组共用的银行服务方法：普通规则解释只读规则；明确条件协商时，将规则与预览请求放在同一条主模型消息中；本轮已有规则成功收据则只补预览。预览由既有代码自行读规则与核验原话，仍须独立审核及本人申请确认。它可写本地条件草案和审计，不能称完全无副作用的读取。

v2 免费脚本流程可以完成，但该 fixture 模式会跳过付费探索准入，不能据此判断真实模式可完成。新增请求前探针保留原付费准入和实际序列化；在主模型发送前明确失败，未读取凭据或联网。它确认 Jev 先读规则后，探索可预留审核输入只有 11,351，低于原最低要求 14,414，仍只暴露终结工具；此时 token 消耗为零、剩余约 104.8 秒。这证明本候选依旧有结构性阻断，不是 Jev 推理耗时所致。证据见 [请求前探针](/Users/manton/CC/projects/Navren/outputs/jev-iteration-20261007/v2-admission-probe.json)。
