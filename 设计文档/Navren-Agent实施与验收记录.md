# Navren Agent 实施与验收记录

2026-10-04。本次将本地正常对话切换为 Agent 主导架构；运行环境为本机合成模拟银行。没有接入真实银行交易接口，也没有重建客户数据库。

## 已落地

- 文字与语音转写统一进入 `/api/agent`。后端与聊天前端均撤出关键词分流、自动问卷和旧模板降级；旧 `/api/chat` 返回停用状态。
- DeepSeek 通过供应商原生工具协议决定查询、补证、计算、澄清或准备草案，支持连续工具调用和对话指代。
- 余额、预算与留款去重、月度/年度账单、异常/周期扣费、现金流、产品匹配、银行卡、转账/定时转账/AA、订阅/代扣、任务/预留/服务预约、服务优惠规则均通过限定工具访问。
- 六类银行业务的操作统一准备待审草案；模型不持有确认、验证码、执行、任意SQL/HTTP/文件或修改正式画像的工具。
- 单纯查询可引用真实事实ID，由后端生成金额和币种；解释、建议、产品比较及操作草案由 GLM 独立核验。
- 金额文字要求对应本轮工具的数值和币种；历史金额不能直接作为新证据。假设示例用整数计算工具，并与真实余额区分。金额集合不验证实体语义，语义与来源仍由审核核验。
- Agent 来源标记在准备操作的同一银行事务内写入。审核绑定对象/参数哈希、账本版本、关键数据修订、规则版本、证据哈希与有效期；实际确认时在执行事务内重验。
- 改金额或对象，新草案在同一事务内使旧确认卡失效；撤回可使尚未执行的草案失效。复合请求每轮至多准备一项，下一项须依实际执行回执重新计算、审核和确认。
- 同工作区的可见对话保存于本机SQLite，客户端伪造的历史/画像不能覆盖正式账户数据。隐藏推理只在一次供应商协议链的内存中续传，不保存、不送审核器。
- 初始预算为8轮、12次工具调用、105秒，审核至多一次修订；技术失败明确说明，不编造状态、不切回旧产品推荐。

## 实现位置

| 文件 | 职责 |
|---|---|
| `agent_runtime/conversation.py` | 对话、工具循环、输出合同、GLM审核、历史与预算 |
| `agent_runtime/native_client.py` | DeepSeek原生协议与不含内容/密钥的调用日志 |
| `agent_runtime/bank_tools.py` | 白名单工具、整数金额、受限事实、精确对象集合 |
| `simulated_bank/agent_guard.py` | Agent草案审核绑定与执行门禁 |
| `server.py` / `finance_gateway.py` | 会话、CSRF、统一入口及既有用户确认 |
| `js/api.js` / `js/chat.js` / `js/bank_ui.js` | 去掉前端语义分流、同一草案确认卡与回执 |

银行客户表和原账户数据保持不变。新增的 `agent_dialogues` 和 `agent_draft_reviews` 是内部对话/审核表。重启前SQLite备份在 `outputs/native-agent/local-bank-before-agent.sqlite3`；启动前后账户、订单、工作区行数及哈希一致，证明未重置原账户。

## 当前范围和限制

这些是本地实现、开发冒烟和受限代码复核证据。尚未运行方案提出的200条语料、80条冻结留出重复3轮及配置对照，不能宣称普遍95%任务完成率、零语义错误或真实银行生产合规。审核模型也可能共同犯错；实际金融权限由代码与用户确认控制。

主架构和增量复核都是代码文本复核，审稿模型未复跑测试或查看截图；凭据相关行经脱敏，因此不构成全仓安全审计。金额文字校验仅覆盖明确识别的数字及币种写法，不覆盖单独¥/$符号、没有单位或全部中文数字，不验证对象/期间/用途语义；仍需独立全文核验。`primary_tokens`只统计主模型，尚未报告两模型合计成本。定时转账在到期时重查银行规则；临时留款方案不等于持久化的自动授权。图片附件当前明确标记未解析，不沿用已停用的旧对话代理猜图。独立风险问卷/模拟画像设置仍由用户界面管理，不由模型擅自更新。
