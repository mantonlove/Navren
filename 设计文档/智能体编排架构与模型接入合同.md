# Navren 智能体编排架构与模型接入合同

## 目标

Navren 采用模型无关、按任务动态组装的协同工作流：主管识别目标并生成有界任务图，领域 Agent 调用各自获准的查询/分析能力，规则门执行确定性校验，独立审核器检查证据与结果，用户确认界面承接资金或账户变更。六个赛题场景是能力目录，不是六个固定 Agent；Agent 数量由任务决定，一个 Agent 可承接多项能力。

智能体只生成和审核业务草案，不能执行用户资金操作。执行仍走现有模拟银行服务与确认凭证。模型供应商可以更换；本次交付是模型无关的协议和本地测试，不表示 DeepSeek、GLM 或持久化记忆图谱已经接入现有聊天路由。

## 编排链路

1. 现有业务层从模拟银行账户、账单、产品与用户明确授权的记忆图谱中准备最小必要上下文，并为可核验材料分配证据 ID。
2. 主管读取 Agent 能力目录，返回追问或有向无环任务图。每个节点声明 Agent、能力、目标与上游依赖；任务数有上限，依赖只能引用已完成节点。
3. 领域 Agent 只拿到请求上下文及其显式依赖结果。禁止的确认、验证码、银行变更工具不注册给 Agent。
4. 每个子任务输出先经证据引用检查和确定性政策门。主管综合时不能新增无来源事实；综合稿再次经规则门检查。
5. 独立审核器读取最终稿及子任务结果，可批准、阻断、要求补证/人工处理，或指定一组任务在次数上限内修订。审核器没有写入与交易工具。
6. 获批答案可生成需要用户审阅的业务操作草案。具体对象、金额、规则版本或数据摘要发生变化、草案过期或授权不足时，必须重新准备和确认。
7. 执行继续由既有后端确认链处理。只有重新查询并核对模拟银行回执后，界面才报告完成；失败、未知状态和待处理状态各自保留。

一条典型动态任务图可以是“读取账单与未来代扣 → 汇总用户已确认的资金目标 → 后端计算可用资金情景 → 产品筛选/对比 → 汇总解释 → 审核”。单纯查询卡片时则可能只调用一个能力 Agent，不必启动多个 Agent。

## 用户记忆图谱

用户记忆是横跨场景的个性化数据层，不单独算一个业务 Agent，也不取代银行账户、实时余额、正式风险测评或产品适当性规则。建议首先覆盖用户明确表达的近期目标、固定资金承诺、流动性偏好与金融知识/产品兴趣；经授权后，再保存经用户确认的消费习惯摘要。

每条节点记录类别、值、来源、证据、置信度、观察时间、过期时间和是否由用户确认。关系只表达可解释联系，例如“该周期扣费用于某项服务”“该笔预留对应某个近期目标”。显式表达、用户反馈、聚合行为与模型推断必须区分标记，不能将推断伪装成用户说过的话。

- 读取按不透明 `subject_id` 隔离，并按用户同意的类别和当前任务相关性取最少图谱片段；未同意、未登录到对应模拟工作区或存储不可用时不读取。
- 写入由记忆整理器提出候选，证据与确定性写入门筛选后，才可按用户开启的持久化范围保存。禁止仅凭 Agent 推断写入风险等级、风险承受能力、适当性、信用判断或身份结论。
- 不持久化原始流水、证件号、卡号、认证码或模型隐藏推理。消费特征只保存必要的汇总/用户确认结论，并带时间范围及来源。
- 用户须能查看、纠正、删除单条记忆、关闭记忆功能。关闭后停止后续读取和写入；记忆存储故障不得阻断一般业务回答，也不得让回答假称使用了个性化信息。
- 当前模拟产品尚无真实用户身份系统。原型中的 `subject_id` 必须由模拟工作区绑定，不能把用户浏览器提交的任意字符串当作授权边界，也不能宣称具备真实银行身份识别。

## 跨场景业务如何进入工作流

基础演示可采用“资金承诺感知的财务管家”，详见[Navren 基础业务演示主线](产品主线与亮点设计.md)。它串联账单、周期扣费、资金预留、跨场景预约/转账和理财决策，属于六项赛题的任务完成度，不能单独当作额外创新。新增机制另见[差异化机制候选与竞品核对](差异化机制候选与竞品核对.md)。

示例任务：用户问“我现在能拿出多少钱做一笔短期理财？”Navren 查看模拟账户可用余额、用户授权的账单/扣费范围、明确登记的近期承诺与期限偏好；确定性现金流服务计算不同时间窗口的情景金额；产品能力据此比较合格候选；审核检查来源、期限与风险约束；页面展示数据期间、扣除项、未确认候选、规则与模拟操作草案。银行可用余额与衍生的“建议预留后余额”始终分开显示。

该功能只有在样本数据中能重复演示、金额可由后端复算、交易动作需独立确认且最终状态能查证时，才作为基础任务成果展示。不能把记忆图谱或模型生成的一段个性化解释本身当成创新效果证据。

## 模型与工具接入

`agent_runtime.ports` 当前定义的适配面：

- `SupervisorAgent`：基于目录路由任务图，并综合各任务结果。
- `DomainAgent`：注册一个或多个 `capabilities`，按任务分析/准备草案，可在审核意见后有限修订。
- `CollaborativeReviewerAgent`：对全部任务输出与最终草案作独立审核。
- `PolicyGate`：纯确定性检查，包括证据、金额、风险、授权与确认边界。
- `MemoryCuratorAgent`、`MemoryWriteGate` 和 `UserMemoryGraphPort`：提议记忆、执行授权过滤、提供按用户隔离的图谱存储接口。

供应商适配层负责请求/响应序列化、超时、重试上限、速率/成本限制和结构化输出校验。未知枚举、字段缺失、超时、解析失败均报错并由编排器安全收束。不要把原始隐藏推理链作为审核材料；审计保存阶段、模型标识、耗时、规则/证据 ID 和结论即可。

## 证据与确认

- 每项可核验事实声明要引用当前请求可见的 `evidence_id`；模拟记忆作为独立来源标记，不能覆盖账户或产品事实。
- 输入仅包含当前任务必要字段。客户档案、用户确认历史和观察推断分层传递；账单备注与导入文本是数据，不能升级为工具指令。
- 每个 Agent 只能使用登记的能力、数据范围和工具范围；规划器不能通过改写任务越权。执行、用户确认、验证码和画像修改属于禁止的 Agent 工具范围。
- 决定性计算由银行服务/规则代码完成，模型解释计算结果。余额、持仓、账单结余、预留金额和预测值不能混作一个数字。
- 用户确认与操作对象、金额/规则、数据版本、授权和有效期绑定。修改后要重新确认；重复请求幂等处理；未知执行状态先查证，不报告成功。

## 失败处理

- 路由无法满足、计划越权或依赖图无效：不分发任务，要求澄清或安全转交。
- 证据缺失、规则拒绝或关键结果冲突：阻断建议或转人工；独立审核中的高危项不能被 `approve` 覆盖。
- 审核最多引起一次定向修订。仍不满足则转交，不进入无限反思循环。
- 模型、审核器或政策门出错：不展示未经核验的草稿；记忆读取/写入是可选个性化能力，故障不影响安全的一般服务。
- 操作确认和模拟验证继续走后端专用流程；Agent 只准备草案，不确认、不执行。

## 验收

1. 任务组合覆盖从单 Agent 到多个 Agent、单 Agent 多能力、同一 Agent 多任务、依赖任务及定向修订；不把 Agent 数量写死为六。
2. 测试追问、坏计划、越权能力、缺失/伪造证据、规则阻断、严重审核项、审核超时、有限修订、记忆授权隔离和记忆写门。
3. 六类赛题场景在能力注册表有覆盖映射；比赛要求的最低场景数与团队承诺的完整覆盖范围分开标注。
4. 基础业务主线至少有正常、数据缺失/过期、周期扣费误判、目标变更、操作中断/重复确认等可复现演示；展示输入数据期间、来源、计算公式、操作草案、确认门槛和最终模拟回执。
5. 使用本项目合成客户/业务数据做可复现基准，报告金额对账差错、证据支持率、异常候选精确率/召回率、规则拦截/误拦截、审核逃逸及端到端耗时。没有测出来的数据不写进路演结论。
6. 当前确定性 `finance_agent` 已通过 `finance_capabilities.ReadCapabilityRegistry` 调用模拟银行只读能力。资金时间轴查询进一步接入 `MultiAgentOrchestrator`：本地确定性主管规划“账户快照 → 现金流推演”，领域适配器仅声明模拟账户摘要与现金流只读范围；证据门校验每项事实引用，确定性规则门禁止操作草案，独立审核器核对任务图与证据后才放行。当前仅现金流路径接入该工作流，供应商模型适配器、持久化用户记忆图谱，以及 UI 上逐笔证据、推演和确认卡仍未完成；不能将本地确定性适配器描述为外部模型协作。
