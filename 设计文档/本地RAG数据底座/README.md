# Navren 本地 RAG 数据底座与建库设计

本文件补齐数据库、资料入库、分块、索引、检索和更新设计。原型最终对话和语音继续使用云端 LLM/TTS；敏感原始信息留在本地，经过字段与用途策略批准的结果可以出站。未来银行更换为自部署模型，不改变数据与证据接口。

## 当前交付范围

- `schema.sql` 是可执行的 SQLite 建库设计，包含 23 张普通表、1 张 FTS5 虚拟表、定位/引用/发布约束及查询索引。
- `verify_schema.py` 使用 Python 标准库，在内存中以合成夹具核验约束，再创建没有金融资料的独立 schema 数据库。
- `outputs/local-rag-schema/schema-validation.json` 和同目录 SQLite 文件是建库验证产物。合成夹具不会写入该持久库。
- 没有采集真实金融原件，没有生成实际 embedding，没有创建 Qdrant 集合，没有实现 RRF/重排或接入对话与语音。这些产物不能证明端到端 RAG 已完成。
- schema 已落实部分存储约束；来源授权、用户访问控制、时点适用性、JSON 条件语义、数据解析和发布检查仍需应用层实现。状态标志不是验证工作的替代品。

## 存储选型与位置

推荐原型使用一个专用 SQLite 文件保存公开产品知识、原文定位、事实和构建记录；账户、原始交易及客户档案继续由现有本地银行库管理。需要索引的私有文档使用独立数据库/索引作用域，禁止把所有客户资料混进公共集合。

业务原件和解析文件在本地应用数据目录按内容 SHA256 保存；不写进代码仓库。示意目录：

```text
本地应用数据/Navren/rag/
  raw/<sha256>.<ext>
  parsed/<parse_id>.json
  knowledge.sqlite3
  vectors/<scope>/
  releases/<release_id>/manifest.json
```

Qdrant 先使用 Python 客户端持久本地模式；上线时可迁为银行服务器内的 Qdrant。向量集合以作用域和发布 ID 区分；不使用其云服务或云端 embedding。SQLite 是权威记录，向量索引可从原文重建。Qdrant 本地模式属于原型模式，不预先承诺其并发、索引规模或延迟。

## 表与关系

| 表组 | 存储内容与必要边界 |
|---|---|
| `sources` | 发布机构、来源地址、允许全文/元数据范围、用途策略、启用状态 |
| `products`、`share_classes`、`channels` | 产品本体、份额/默认变体、渠道分别有稳定 ID；名称不作唯一标识；真实/模拟来源与身份核验状态独立保存 |
| `channel_offers` | 具体份额在具体渠道的销售、申购、赎回状态和资格条件；未知明确存 unknown，不能从产品存在推导可买 |
| `documents`、`document_versions` | 逻辑文档和原件版本；文件哈希、原件路径、发布日期、生效期、采集日期、权限、出站策略、撤回状态 |
| `document_parses` | 原件版本的解析器、解析修订、规范化修订、解析文件与完整性；重解析产生新 ID，不覆盖旧引用位置 |
| `document_subjects` | 原件版本适用的份额、渠道与关系；拒绝将 A 类资料静默用于 C 类 |
| `evidence_spans` | 章节、段落、表格、表格行、脚注；父结构、页码、原文、定位和表格结构 |
| `chunks`、`chunk_spans` | 检索片段、构建输入、文本哈希、分块修订、分词文本、原文跨度映射；一个片段可关联多个段落和脚注 |
| `chunks_fts` | 原文的中文预分词全文索引，由触发器维护；展示和引用仍用未分词原文 |
| `fact_assertions`、`fact_evidence` | 具体主体、指标、类型化值、单位、观察时间、有效期、条件、实际/假设/预测/情景属性及精确原文；允许保留冲突，不按采集时间覆盖旧值 |
| `series_observations` | 单位净值、累计净值、调整净值、分红、拆分、万份收益、七日年化分别保存；不将累计净值直接当总回报 |
| `fee_rules` | 费用类型、基数、金额/持有期/客群/渠道条件、比例/定额/阶梯、日历及舍入规则、是否已计入净值、有效期 |
| `embedding_profiles` | 模型名称、实际修订、权重哈希、分词器、向量维度、输入长度、距离、归一化和 query 前缀 |
| `releases`、`release_chunks`、`current_releases` | 物理向量集合、片段清单、原文哈希、词法/向量完成状态、检查报告及当前作用域的发布指针 |
| `ingest_jobs` | 下载、解析、身份映射、提取、核验、分块、embedding 与发布任务，记录失败和重试 |
| `retrieval_runs`、`retrieval_hits` | 一次请求固定的发布 ID、访问作用域、查询摘要、覆盖缺口、分阶段命中片段与排名；不把检索分数当事实正确率 |

十进制金额/净值/费率不得存为二进制浮点金融真值。最小币种金额用整数；其他数值保存十进制文本，由 `Decimal` 和指标定义验证。SQL 的 JSON 合法性检查不等于费用条件可执行：应用只接受允许列表中的字段和比较运算，不执行原文或模型产生的代码。

有效区间统一采用半开区间 `[effective_from, effective_to)`。空结束日期表示未知终止时间，不能自动认定当前仍有效。发布日期、采集日期、观察日期和生效日期不能互相替代。

## 本地入库与构建流程

1. 登记官方/管理人/监管来源、许可和读取范围。历史目录与模拟资料分别标识，首批建立有原件证据的小范围真实产品集。
2. 下载原件并计算哈希。相同内容不重复保存；修订产生新文档版本；元数据来源不得补写未读取的正文。
3. 本地解析 HTML/PDF。保留页、章节、表头、单位、合并单元格和脚注；失败或截断单独标记，不能默认为资料完整。
4. 核对产品本体、份额和渠道映射。真实产品身份未确认时保持 pending，不进入当前推荐。
5. 提取候选事实与费用条件。稳定来源用本地规则解析；关键费用、期限、风险和销售字段首批人工核对。不同来源有矛盾时保留断言并标冲突；审查条件差异后才裁决。
6. 按章节/条款/表格构造原文跨度，再生成检索片段。表格行附表头、单位和脚注；正文原样保留。预分词文本用于 FTS；带必要上下文的文本用于 embedding，二者都有可回查的原文映射。
7. 本地 embedding 写入新发布集合。初始候选 `bge-small-zh-v1.5` 的模型配置是 512 维、512 位置上限，分块预算须包含上下文和特殊 token，并用实际 tokenizer 核验。超长父章节保留在 SQLite，召回子片段后再补读；不能静默截断表格关键条件。
8. 核对 SQLite 清单和实际 Qdrant 点数量、ID、维度、哈希、权限载荷与模型修订。FTS 做完整性检查；关键事实和条款覆盖通过后，才将发布标记 ready 并在 SQLite 事务中切换指针。

跨 SQLite 与 Qdrant 没有一个共同事务。工作进程按确定性 UUID 点 ID 幂等写入；请求先固定 SQLite 中的发布 ID，再查询其物理集合。旧集合在没有请求引用后回收；失败的新发布不可切换指针。SQL 中的 vector_ready 只能由实际核对向量写入的受信工作进程设置。

## 查询流程

用户问题 → 本地产品/份额/渠道/日期解析 → 固定发布及权限 → 结构化事实查询与 FTS/向量召回 → RRF 融合 → 可选本地重排 → 回 SQLite 核对版本、来源和权限 → 补父章节/表格/脚注 → 按产品×维度检查覆盖 → 本地计算与出站字段选择 → 云端 LLM → 本地声明校验 → 云端 TTS/展示。

关键词召回需在限制 top-k 前参与权限、发布代次及产品过滤；向量召回也先加入作用域和产品过滤。所有向量命中回查 SQLite，不能信任缓存载荷仍为有效来源。

比较两只产品时分别查询费用、流动性、风险与策略等维度。某一格缺资料或冲突就返回缺口；不能用一个全局 top-k 为双方填满比较表。费用比较先确定持有期与渠道；配置计算先确认资产范围与数据口径。

RRF 和重排序只是检索排序方法。它们不验证来源真实性，也不证明证据足以回答问题；充分性由业务必要字段、原文条件和计算输入检查决定。

## 更新与失效

- 原件或解析改变产生新版本/解析/片段 ID；模型更换产生新 embedding profile 和集合，禁止混用不同向量空间。
- 费用、资格和在售状态更新后重建受影响发布，相关比较和计算缓存按发布 ID 与输入事实 ID 失效。
- 来源撤回/禁用即时由 SQLite 回查拦截，不能等整库重建。已发布集合可暂留，但不得把其中已撤回片段提供给模型。
- 不把失败采集变成“零值”。保留旧资料可供明确日期的历史分析，当前销售资格等关键字段须按自己的新鲜度策略降级。
- 私有资料删除需同时撤销检索准入并清理派生索引、缓存和个人证据快照；不能由历史发布恢复用户已删除的数据。

## 当前验收与未完成工作

验证脚本核验跨版本外键、原文引用、份额引用、全文插入/删除、不可变原件与解析、未完成/哈希不一致发布拦截、已发布清单冻结、来源撤回与完整性。数据均为合成测试夹具；vector_ready 在该测试内是模拟标志。

后续还必须完成：真实原件入库、解析质量核对、本地模型资源测量、实际向量集合与检索实现、费用条件解释器、访问与出站策略、对话/语音集成、人工标注金融问题的召回和回答评测。表已建成、DDL 验证通过不等于这些工作已完成。

复现建库验证（输出目录不得已有同名数据库）：

```bash
python3 设计文档/本地RAG数据底座/verify_schema.py --output-dir outputs/local-rag-schema
```

## 官方技术依据

- [SQLite FTS5](https://www.sqlite.org/fts5.html)：全文表、BM25、外部内容同步与索引检查。
- [SQLite 外键](https://www.sqlite.org/foreignkeys.html)：每连接启用、复合键与外键完整性。
- [Qdrant Python 本地模式](https://github.com/qdrant/qdrant-client)：持久本地原型与服务器迁移。
- [Qdrant 点与集合](https://qdrant.tech/documentation/manage-data/points/)：点 ID 和派生载荷；集合维度必须对应模型。
- [BGE 中文小模型配置](https://huggingface.co/BAAI/bge-small-zh-v1.5/raw/main/config.json)：初始维度/输入长度候选；不代表已完成本机质量和资源评测。
