### 2.2 RAG 产品检索（5 层过滤）

产品库：1260 只在售产品（银行理财/公募基金/保险/信托/债券/券商资管），数据来源涵盖中国理财网、中基协、中债登、金融监管总局。每只产品含 18 个结构化字段。

| 层 | 规则 | R2 用户（20 万，3 年）示例 |
|----|------|--------------------------|
| 1. 风险 | 产品风险 ≤ 用户等级 + 1 | R2 → R1/R2/R3 |
| 2. 金额 | 起购 ≤ 可投金额 | ≤ 20 万起购 |
| 3. 期限 | 封闭期 ≤ 投资期限 | ≤ 3 年 |
| 4. 排序 | 按风险距离 + 目标偏好 | 教育→债优先/增值→权益优先 |
| 5. 去重 | 同族只留最优，最多 5 只 | "安鑫短债 30 天"和"60 天"只留一个 |

**关于组合层面风险 vs 产品层面约束**：当前是产品级硬约束（单只产品风险不可超限）。更精细的做法是组合级约束——允许少量高等级产品（如 5% R4）在组合整体波动率受控的前提下进入 R2 配置。这需要在 `search_products` 和 `calculate_allocation` 之间增加一层组合风险校验。当前保持产品级约束（更安全、更易解释），后续可演进。

### 2.3 ERC 风险预算配置模型

**为什么不用均值-方差**：需要预期收益输入 → 用户不提供 → 估计误差大（Michaud 1989 "误差最大化器"）。ERC 仅需波动率，不依赖收益预测。

**理论基础**：Markowitz (1952) 均值-方差 → Qian (2005) 风险平价 → Maillard, Roncalli & Teïletche (2010) ERC 数学框架 → Roncalli (2013) 风险预算 → 中银证券/招商银行 (2024) 中国实践。详见 `outputs/Navren_资产配置模型理论基础与参考文献.docx`（18 篇）。

**核心公式**：
```
ERC 一阶权重:  w_i = (1/σ_i) / Σ_j(1/σ_j)
组合波动率:    σ_p = Σ_i w_i × σ_i
约束:         σ_p ≤ σ_max(r),  Σ_{equity} w_i ≤ equity_max(r)
```

**资产波动率估计**：

| 等级 | 类别 | 波动率 | 代表产品 |
|:---:|------|:-----:|---------|
| R1 | 货币/存款 | ~0.8% | 活期盈、大额存单 |
| R2 | 短债/信用债 | ~2.5% | 安鑫短债、地方债 |
| R3 | 混合/固收+ | ~6.5% | 固收增强、指数基金 |
| R4 | 权益指数 | ~16% | 沪深 300、中证 500 |
| R5 | 行业主题 | ~28% | 科技主题、全球配置 |

**风险预算表**：

| 等级 | 最大波动率 | 权益上限 | 预期收益 | 最大回撤 |
|:---:|:--------:|:------:|:--------:|:------:|
| R1 | 1.0% | 0% | 1.5-2.5% | <0.5% |
| R2 | 3.0% | 10% | 2.5-3.5% | <1.5% |
| R3 | 7.0% | 30% | 3.5-5.5% | <5% |
| R4 | 15.0% | 60% | 5.0-8.0% | <15% |
| R5 | 25.0% | 90% | 7.0-12.0% | <30% |

**ERC 解释策略**：初始回复默认不含方法论解释。当用户追问"为什么是这个比例""为什么固收类更多"时，AI 自然解释 ERC 原理。后端记忆追踪用户追问次数——若近 3 轮中 2 次以上追问"为什么"，后续初始回复自动附带简短解释。

### 2.4 双层合规审查

**第一层**：`classify_intent` 命中合规红线（保本保息/稳赚不赔/绝对安全等 13 类）→ 直接走合规拒绝，不调 LLM。`search_products` 风险硬约束（产品风险 ≤ 用户等级 + 1）。

**第二层**：`compliance_check()` 扫描 LLM 输出 → 命中违禁词 → 重试（temp=0.5）→ 仍命中 → `COMPLIANCE_FALLBACK` 兜底。13 类禁用词拦截率 100%（实测 10/10）。

**行为规范**：
- 合规拒绝时：解释监管规定 + 给出替代路径（大额存单/存款）+ 不调 LLM（瞬间返回）
- 交易意图时：拦截 + 引导官方 APP + 提醒可联系人工客服
- 情绪安抚时：先共情 → 再分析 → 不给恐慌决策建议

#### 2.5.1 更高收益诉求处理

不是简单拒绝，而是：**先解释风险代价 → 给出选择 → 尊重用户决策**。

用户说"我希望年化 6%"（当前 R2）：
> "年化 6% 通常需要承担更大的净值波动——比如 R4 级别产品历史上出现过 15% 以上的回撤。以您当前 R2 稳健型画像，我默认不会为您推荐这类产品。您可以选择：
> ① 如果您愿意了解——我可以展示 R4 级别的配置方案，产品名会标注为红色，提示超出您当前风险承受范围
> ② 重新做一次风险测评——如果测评结果提升，我再为您正常推荐
> ③ 查看 R2 范围内当前最优的稳健方案"

**红色标注机制**：当用户执意查看超风险等级产品时，产品名在回复和推荐页均以红色（`#C53030`）展示而非蓝色（`#1A5CDC`），并附带明确风险提示。

#### 2.5.2 交易意图处理

拦截 + 引导 + 转人工：
> "我理解您的需求。作为 AI 顾问，我不能代您进行交易操作。请您通过手机银行 APP 完成，或联系我行人工客服协助您——点击下方按钮可转接人工顾问。"

### 2.6 Follow-up 追问机制

#### 2.6.1 关键词提取范围

| 维度 | 关键词/模式 |
|------|-----------|
| 产品推荐 | 推荐、配置、筛选、产品、基金、ETF、指数、债券、理财、存单、保险 |
| 风险 | 风险、回撤、波动、亏损、下跌、R1-R5、稳健、保守、进取 |
| 收益 | 业绩、收益、回报、年化、基准、费率 |
| 市场 | 市场、行情、LPR、利率、国债、PE、估值、宏观、央行、通胀 |
| 配置 | 配置、比例、仓位、分散、组合、对冲、再平衡 |
| 交易 | 购买、申购、赎回、下单、APP、流程、到账 |
| 对比 | 对比、比较、哪个、区别、差异、优劣 |
| 期限 | 封闭期、到期、持有、流动性、赎回规则 |
| 底层资产 | 股票、债券、同业存单、国债、信用债、可转债、股指期货 |
| 客户适配 | 适合、匹配、推荐原因、替代方案、风险等级 |
| 组合管理 | 调仓、换仓、止盈、止损、定投、分批 |
| 情绪/行为 | 恐慌、担心、后悔、着急、观望、犹豫 |

#### 2.6.2 阶段机（Planner）

```
6 个话题，每个 3-4 个阶段：

allocation_plan:  overview → understand_risk → compare_options → execution_ready
market_analysis:  overview → personal_impact → allocation_response
risk_mismatch:    explain_gap → reassess_or_safe_plan → safe_plan
product_comparison: compare_core → fit_user → execution_ready
product_recommend:  overview → understand_risk → compare_options → execution_ready
emotion_comfort:  comfort → analyze → action

过滤: 已完成/已点过/已展示>2次/不属于当前 topic 的降权
排序: 推进阶段 +2.0 → 同阶段 +1.0 → senior 短标签 +0.2
```

#### 2.6.3 视觉设计

follow-up 按钮改为卡片式排布，而非简单的 inline chip：
- 每个 follow-up 是一个小型卡片（圆角 10px，微微阴影，白色底）
- hover 时整卡上浮 2px + 加深阴影 + 左边框变金色
- senior 模式下卡片更大（padding +4px），标签更短
- "动作型"follow-up（如重新测评、转人工）左侧加小图标（🔄 📞）

### 2.7 三模式差异化

三种模式仅影响表达方式，不影响合规、产品筛选、风险适配。

**prompt 结构**：
```
UNIVERSAL_COMPLIANCE_OVERLAY（6 条铁律，最高优先级）
  + MODE_STYLE_PROMPTS[mode]
  + 产品数据 + 用户画像
  + MARKDOWN_BAN
```

**风格差异**：

| 维度 | classic | senior | youth |
|------|---------|--------|-------|
| 称呼 | "您" | "叔叔/阿姨"或"您" | "你" |
| 单次回复量 | 4-8 段，800+ 字 | ≤150 字，每段 ≤2 句 | ≤200 字，结构化标签 |
| 术语策略 | 使用 + 简短括号解释 | 只用生活化比喻，禁用术语原文 | 直接使用，数据化表达 |
| 产品推荐 | 2-5 只 + 逐一说明 | 先讲 1-2 个方向，确认后再展开 | 2-5 只 + 比例 + 数据 |
| 解释方式 | "业绩比较基准 3.2%——这不是承诺收益" | "产品努力参考的目标是 3.2%，但不是保证能拿到的" | "基准 3.2%（非承诺），最大回撤 -1.5%" |
| follow-up | 8-14 字 | 4-8 字，少术语 | 6-12 字 |
| 情绪回应 | "我理解您的心情" | "叔叔/阿姨，看到亏钱谁都不好受" | "理解。市场波动是常态" |
| 风险提示 | 正式合规声明 | 完整但不吓人，"咱不着急" | 直接简洁 |
| 回复结构 | 结论→依据→方案→合规 | 回应情绪→通俗解释→1-2选择→主动询问 | 结论→数据→动作→风险 |

### 2.8 Memory 系统

#### 2.8.1 记录内容

```
会话级 memory（单次对话，不持久化）:
  - 当前话题 topic_key 和阶段
  - 已完成的 follow-up intent
  - 已点击/已展示的 follow-up
  - 用户追问"为什么"/"原因"的频率计数（用于触发 ERC 解释）
  - 最近 5 轮对话的关键词/主题

持久化 memory（跨会话，localStorage）:
  - qingzhou_userProfile: 画像字段（金额/期限/目标/收入/关注领域）
  - qingzhou_riskProfile: 风险等级/评分/最大回撤/评估时间
  - qingzhou_followupMemory: 话题阶段/已完成意图/已展示/已点击
  - qingzhou_userBehavior: {
      question_frequency: { "why_allocation": 3, "market_update": 5 },
      preferred_style: "concise" | "detailed",  // 从回复长度偏好推断
      knowledge_level: "beginner" | "intermediate" | "advanced",  // 从提问复杂度推断
      last_active_topics: ["allocation", "market"],
      total_sessions: 12,
      bookmark_categories: { "market_news": 5, "products": 3 }
    }
  - qingzhou_profileGaps: AI 识别到的有价值但用户未主动提供的字段
    [{ field: "goal", evidence: "用户多次问教育金相关产品", priority: "high" }]
```

#### 2.8.2 与个人档案联动

- AI 对话中识别到用户关心子女教育但 `goal` 为空 → 写入 `qingzhou_profileGaps` → 合适时机主动提问："我注意到您几次问到教育金相关的产品，需要我帮您按'子女教育金'这个目标来规划吗？"
- 用户频繁问市场 → 自动开启市场周报推送偏好
- 用户总是追问"为什么"→ 后续回复自动附带简短解释
- 用户偏好短回复 → 自动切换到 concise 模式（覆盖模式默认字数限制）

#### 2.8.3 主动提问策略

当以下条件同时满足时，AI 在回复末尾主动询问：
1. 画像缺失字段的 priority = "high"
2. 当前对话话题与该字段相关
3. 过去 3 轮未问过同类问题

示例：
- 用户说"想给小孩攒钱"但 `goal` 为空 → "您提到小孩，这笔钱是打算用于教育金储备吗？如果是的话，我可以按教育金规划的目标来帮您配置。"
- 用户频繁问短期产品但 `horizon` 为空 → "您似乎比较关注短期产品，这笔钱大概多久后需要用？告诉我期限我可以更精准地推荐。"

### 2.11 市场热点 & 每周市场周报

**当前问题**：信息太简略，用户看不明白，没有交互入口。

**改造方案**：

每条热点/周报条目是一个可点击的卡片，点击弹出详情面板：
- 标题（加粗）+ 摘要（2-3 句白话解释）
- 关键数据（利率/指数/涨跌幅）
- "这对你有什么影响"段落——根据用户画像/持仓/风险偏好个性化生成
- 底部按钮："发送至聊天，和Navren讨论"→ 跳转 chat 自动发送"帮我分析一下这条新闻对我的配置有什么影响"
- 收藏按钮 ⭐ → 存入 `qingzhou_bookmarks`（收藏类别标记为 `market_news`）

**个性化推送**：
- R1/R2 用户优先展示债券市场、存款利率相关新闻
- R4/R5 用户优先展示股市、行业 ETF 相关新闻
- 持仓中有某类产品 → 该类产品的相关新闻排前面并标注"与你持有的 X 相关"
- 用户画像中关注领域匹配 → 相关新闻加"为你推荐"标签

**chat 页联动**：用户可在聊天中直接问"最近有什么值得关注的市场动态"→ AI 从 market_data.js 读取并结合用户画像个性化解读。

### 2.12 个人档案与主动引导

**档案缺失时的主动提问**：

AI 在对话中识别到以下信号时，主动发起档案补全：

| 信号 | 缺失字段 | 提问方式（classic 示例） |
|------|---------|----------------------|
| 用户问教育金/孩子上学 | `goal` | "您提到孩子，这笔钱是打算用于教育金储备吗？" |
| 用户问"随时能取吗""活期" | `horizon` | "您似乎比较关注流动性——这笔钱大概多久后可能用到？" |
| 用户说"手头有点闲钱" | `amount` | "方便告诉我大概有多少吗？这样我能更精准推荐。" |
| 用户问"这个风险大吗""保本吗" | 风险评估 | "您似乎比较在意本金安全，要不要先做个风险测评？8 道题，2 分钟。" |

提问频率控制：同一字段 3 轮内不问第二次。用户明确表示"不想说"后不再追问该字段。

### 2.13 账户持仓信息利用

**原则**：账户数据只读不写（来自银行数据库）。chat AI 可以读取以辅助推荐。

**实现**：
- 聊天页 API 请求中携带 `qingzhou_holdings`（用户已有持仓）
- 后端在 system prompt 中注入："用户当前持有以下产品：[持仓列表]。推荐时避免重复推荐已持有的同类产品，可建议调整现有持仓比例。"
- 市场解读时结合持仓分析："您持有的 X 产品属于短债类，当前利率下行对该类产品有利。"
- KYP（Know Your Product）对齐：推荐产品时与用户已有持仓做对比，指出互补性或重叠风险。
