## 一 当前已经核实的事实

- 正式 Agent 报告仍写“任务03未完成”；集成报告仍写“完整集成未通过，发布不放行”。工程、局部真实模型、隔离 HTTP 通过不能替代整体验收。
- 最新服务收据指向正式 Navren 源码，运行参数为 off。off 只关闭新增意图分类，不是关闭主 Agent。该收据的 model_checks 为0，不能证明当前入口已完成真实模型验收。旧预览的模型关闭状态不能套用到这个新进程。
- 金额签发、终审与公共消费的部分成果仍是待共同采用的候选，不能把候选测试当正式入口的结果。
- 当前 Jev 对照完成32/132次，27次通过、5次失败，因短期资金题 native 与 Jev 共同失败停止。未完成完整对照，未采纳 Jev。关闭新增分流的10/10只覆盖该隔离对照样本。

- 强制安全合同仍为 REQUIRED_NOT_ACCEPTED，真实强验证和正式生成代码沙箱等尚未整体验收。缺失能力的安全拒绝不能冒充功能完成。

## 三 解决方案

当前只提出以下实施方案，未因此启动新的付费测试、跨窗口任务、业务源码修改或服务部署。各阶段只能按实际结果关闭；固定原完成标准，不靠缩范围结束。

### 阶段1 固定唯一不加入 Jev 的待验版本

确认正式服务入口、源码和技能、模型渠道和版本、数据快照与既有题集。列清正式已采用与仅在候选中存在的增量，按文件 owner 合成一套可运行的隔离待验版本。完成记录只使用同一套版本证据。

复用现有集成报告和对应 delivery.json 作为整体状态入口；runtime.json 只证明实际运行身份，不能代替验收。测试用例写全“题集名称＋题集校验值＋案例ID”；集成 G2 的公开问答 P02 与 Jev 题集中的财务日历 P02 是不同案例，不能仅凭代号交接。

### 阶段2 先免费闭合 Agent 和基座的共同阻塞

- 公开问答：精确处理正文、公开原文和 claims 引号合同，避免模型收到错误后重复提交相同结构；不扩大公开金额豁免。
- 金融建议：接齐原签发、来源与对象绑定、审核、FinalProof、历史读回和发布；在正常预算下检查完整输入和下一必要请求的预留。保留完整证据，不能通过丢字段或跳过 GLM 减少成本。
- 金额输出：正文槽与金额声明一致；非必要金额不重复；覆盖未知的定性说明避免触发金额误判；未核验赎回到账条件不作到期可用保证。
- 先复现原失败，再验证合法正例、对应拒绝负例和预算恢复。已有免费原型可按影响面采用，但不得整文件覆盖正式源码中的其他窗口改动。

Agent 负责消费与恢复，基座负责签发、事务和最终发布接线；集成验收负责联合结果。暂不同时开发新的路由、记忆、推荐算法或性能优化。

### 阶段3 补齐原强制安全依赖

沿用原14项安全合同，由对应 owner 核对真实操作绑定认证、缺失业务能力、审计与跨轮写入锁，并将已验证沙箱候选接入正式受限链路。先盘点已有认证服务和已授权测试渠道；确实缺少用户资料时只问必要项，不重复索取密钥或已给出的信息。

RAG 消费只使用其实际可用且可回查的发布；尚未完成的提供端必须列为依赖，不能用历史目录、合成原件或诚实拒答证明产品研究功能完整。不得以“演示足够”为由删掉用户已明确要求的安全门。

### 阶段4 同版真实验收

前述本地接线和正负例闭合后，沿用原题、原轮次、原预期及通过门槛，验证当前同一版本的金融任务、公共证据、四账户、确认与回执、撤回与失败恢复，再完成对应实屏和文字／语音链。

整批开始前核对调用数量、已知历史消耗、未知预留、预计本批消耗及余量。若预计不能完成，继续免费工作并明确资源缺口；不得把注定不完整的诊断轮包装成完整验收。用户明确授权阶段诊断时可以执行，但保留其诊断身份和原预算上限。

业务运行原有 GLM 审核保持；用户停止的是外部开发和结果送审，不能误删业务审核。首次整批失败后先定位原因，不对未修复的同版本、同输入反复付费。

### 阶段5 正式加载与收尾

原业务门槛、强制安全、当前入口及对应实屏链全部满足后，由基座和集成验收按已有授权完成正式加载、版本读回和发布回执。已通过部分固定；新缺陷按实际影响补验，不再自动生成新的整仓验收轮。

结束交付必须同时包含整体判定、逐项通过／失败／待验、版本与来源、实际运行路径、剩余依赖和成本状态。未通过时明确写未通过，不能把“已收尾”改写成“已验收”。

## 四 后续强制执行规则

1. 每项工作开始前明确目标、唯一 owner、写入范围、现有完成门、下一交付、预算和工期估计依据。用户明确改变优先级时按其授权执行，但保留未验收状态。
2. 主流程未整体通过，默认先关闭基线阻塞；扩展只能是用户明确知情授权的独立诊断，不取得正式采用资格。
3. 未变源码、依赖和合同的已验工程证据复用。变更只按真实影响复验；全局提示、安全边界、接口和模型变化可能影响更多案例，须解释并预算后再跑。跨不同源码的真实模型成绩不得拼成同版本结果。
4. 当前外部开发／结果送审保持停止，除非用户明确重新授权。日常源码自检和内部只读核对可以进行，不能恢复成另一种全包复审。
5. 两轮有明确假设的修复后仍出现同类阻塞，暂停追加付费和机械修改，转到该链路的根因定位及接口取舍；这是管理停点，不是缩减原验收要求或修改已有实验次数。
6. 新增范围、改变原题或门槛、提升预算及正式发布均按既有授权边界处理；普通修复不重复索取许可。需要新授权时先交具体可审查改动、影响、费用和未完成项。
7. 进度报告说明实际产物与剩余关口，不把测试数量、代码审核 PASS 或 HTTP 200 当产品完成。延迟或依赖变化及时说明；不在没有执行条件时承诺整体通过日期。
8. 规则写入项目 AGENTS.md，后续执行前必读；正文和已有报告继续承担事实记录。文档规则目前由执行者遵守，尚未实现自动化拦截脚本，不能宣称工具已经自动防止所有违规。

执行层建议：由集成验收 owner 复用现有验收执行器和 manifest，增加最小事前检查。扩展采用实验须检查基线整体状态或用户知情诊断授权；每批校验待验与实际加载版本、题集身份、改动影响面、整批预计预算和同类重复失败状态。条件不满足就拒绝该项启动，输出具体缺项，同时保留可开展的免费工作。整体通过字段只能由原业务、安全和真实入口证据满足后生成。此项是待实施方案，不在本次文档任务中改运行脚本，也不改变原试验约束。
