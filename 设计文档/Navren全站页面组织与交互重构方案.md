## 1. 总体结构与完成标准

核心路径：

```text
看见财务信息 → 进入具体对象 → 理解条件与联系 → 准备操作 → 本人确认 → 回看结果
```

用户界面以四个主页面为骨架：

| 主页面 | 负责回答 | 默认内容 | 主要深入路径 |
|---|---|---|---|
| 对话 | 帮我理解或完成这件事 | 当前问题、结论、相关组件、必要下一步 | 证据、比较、准备操作、确认与回执 |
| 账户 | 我的钱现在怎样，近期需要处理什么？ | 资金概况、资产与负债对象、近期事项 | 对象详情、财务日历、流水与报告、活动记录 |
| 发现 | 最近什么值得了解，有哪些选择？ | 热点封面流、周报封面、产品预览、最近备选方案 | 原文、研究详情、产品列表、对照、方案详情 |
| 我的 | 我的长期安排是什么，Navren了解了什么？ | 目标与责任、四域关系概览、待核实条件 | 目标详情、图谱关系、记忆与资料、收藏、设置 |

“推荐”在用户界面改称“发现”，保留 `recommend.html` 作为兼容入口。对话排在主导航第一位，并作为完成初始引导后的默认入口；显式深链接优先进入指定对象。用户选择继续尚未完成的任务时恢复该任务，系统不能擅自打开确认单或继续提交。

顾问工作台保留为独立顾问/演示视角，承担客户简报、人工交接、依据回看与演示控制。普通用户的四项主导航中不显示工作台。

完成标准是用户能找到信息、连续完成任务、返回原位置、核对结果。按钮变少、截图整洁或单页高度降低，均不足以独立证明完成。

## 2. 全站导航、首次使用与角色

### 2.1 一级导航

桌面侧栏固定显示“对话、账户、发现、我的”；手机使用同样顺序的四项底部导航。图标与文字同时存在，活动页状态清楚，子视图归属对应主页面。

账户首页、对象详情、日历、完整报告共用账户主导航状态。产品研究、产品资料、比较和备选方案共用发现主导航状态。子视图标题与返回入口说明当前位置，无需再铺一整排业务栏目。

全站头部保留品牌、当前视图名称和一个个人/设置入口。主题、语言、字体、音色与模式统一进入设置；首次引导中提供清楚的阅读模式选项。业务状态和当前来源仍位于相关数据旁。

### 2.2 首次与回访

- 初次使用：简短介绍 → 进入对话开始提问；可以选择阅读方式，必要的数据授权在实际使用对应能力前出现。账户仍可从第二项主导航直接进入。
- 回访：沿用保存的模式，默认进入对话，或恢复用户明确选择的继续任务；品牌点击回对话。返回对话保留有效会话，不自动新建会话、发送问题或提交操作。
- 未建立账户来源：展示真实连接/来源选择状态；公开资讯仍可访问，私人余额不显示假数据。
- 经典、青春、关怀模式共用页面职责与业务路径，只调整字号、密度、视觉与语音。关怀模式不删功能。
- 已完成的首次设置不反复出现，深链接不被欢迎页截断。退出、切换工作区后，先核对新身份再恢复私人视图。

### 2.3 顾问视角边界

个人入口内提供开发演示可达的“顾问视角”，进入后导航明确标识角色与当前服务对象。回用户视角恢复原页面。

导航切换不代表取得客户资料权限。现有授权决定数据可读范围；没有顾问角色能力时，标“顾问演示”，不宣称已经接入真实银行后台。模拟日期推进等演示控制移到此处，继续保留明确确认和作用范围。

## 3. 统一交互规则：少入口、清楚反馈、按任务展开

### 3.1 三种展开方式

| 内容 | 呈现方式 | 典型实例 |
|---|---|---|
| 一小段辅助信息 | 原位置展开，保持上下文 | 金额计算依据、匹配原因、图谱证据摘要 |
| 需要阅读、筛选或多步工作的内容 | 进入主内容区的完整子视图，具有返回路径 | 对象详情、日历、完整账单、周报、产品研究、比较 |
| 临时选择、简短说明、必要确认 | 一个轻量弹层或现有确认组件 | 选择来源、问号解释、确认操作 |

不把完整日历、复杂比较、全部报告塞进窄抽屉。市场原文解读已具备适当的阅读面板，可以复用；手机长文转为全屏阅读。一条流程中仅一个活动弹层，进入下一层先关闭上一层，保留返回状态。

复杂确认组件可先复用现有 BankUI 对话框，禁止为统一视觉重写确认语义。长确认单在手机采用可完整滚动的全屏形态。

### 3.2 可发现的对象入口

银行卡、持仓、贷款、目标、事项、报道与产品名称所在主体区域可点击，配合清晰的箭头/轮廓与焦点反馈。桌面悬停是补充；手机常态也能辨认入口。

对象主体用于进入详情，具体动作控件单独处理。不可用一个大链接包住内部按钮或链接；选择文字、比较勾选、滑动与点击彼此隔离。查看详情使用链接语义，执行动作使用按钮语义。

高级手势只做辅助。点击、键盘和关怀模式都能完成相同任务；不能把比较、挂失或取消藏在仅长按/滑动可发现的位置。

### 3.3 按钮与说明的分工

- 主页面突出当前最重要的任务入口，产品和内容预览以对象本身为入口。
- 对象详情出现与其有关的明确动作；不能为满足按钮数量指标藏掉确认、取消或危险操作说明。
- 账户首页常驻一个文字明确的“转账”入口，附近可进入财务日历；不恢复六项快捷操作栅格。
- 产品研究内部提供可见的“比较产品”入口；进入比较模式出现选择框，勾选后出现统一比较栏。
- 重复解释移到标题旁问号或详情。风险、身份、截至日期、待确认/失败/缺失状态直接可见。
- 问号弹窗靠近触发位置，可点击、Esc 关闭，焦点返回；不只依赖悬停。内容短而具体，不出现工程字段名。

## 4. 数据归属、来源与时间：全站一致的前提

### 4.1 同一对象只有一个维护归属

| 信息 | 维护归属 | 其他页面的职责 |
|---|---|---|
| 银行业务余额、持仓、贷款、卡片、交易与操作状态 | 当前工作区的业务服务 | 读取、引用，发起既有受限业务流程 |
| 模拟业务风险配置、资金预留与业务期限设置 | 既有业务资料与确认流程 | 我的显示实际来源/状态；聊天偏好单独呈现，有证据的正式测评另行标识 |
| 本人确认的长期目标、责任、偏好与记忆授权 | 我的所引用的对应目标/记忆服务 | 对话提出候选，日历展示关联安排，图谱读取关系 |
| 本人日历事件 | 日历服务 | 账户预览，目标按 ID 关联，对话引用 |
| 公开新闻、产品资料、净值与证据 | 原有公开资料链 | 发现/对话/图谱读取，不改写成银行账户事实 |
| 收藏与备选方案 | 当前用户的对应保存对象 | 发现、我的与对话引用同一版本 |

“唯一归属”不意味着把全部内容搬到一个数据库。先建立稳定对象引用，禁止旧档案、记忆、图谱分别维护同一事实的副本。名称相同不能自动合并产品或目标。

现有借贷、存款、目标、服务记录、授权等来自 `/financial-records`。执行窗口逐项核对其读写能力；如某项目前只读，详情提供真实只读状态。需要新增目标编辑或跨目标日历修改时，只补必要的受限接口和确认闭环，不用本地存储伪造保存成功。

### 4.2 三类来源与两种持仓视图

| 来源/视图 | 可呈现 | 操作能力 |
|---|---|---|
| 当前模拟银行账本 | 业务余额、卡片、交易、预算、现行模拟持仓 | 按现有能力准备并确认模拟操作 |
| 本地导入账单 | 该批/期间内的收支、分类、报告与可核实线索 | 导入预览/确认、分类核实；不推算银行实时余额 |
| 历史模拟组合＋真实净值 | 对应组合版本、估值、权益与历史损益 | 研究、追溯与引用；归档组合不当作当前交易账户 |
| 当前持仓的市场估值，若已具备可靠映射 | 对应持仓、行情日期和计算口径 | 交易资格仍以当前业务对象和规则为准 |

来源和组合是不同维度，不能用一个“收益”标签暗中切换到另一个账本。现行银行状态与历史权益不能相加；导入流水不能自动补成银行余额。

界面用“演示账户”“导入账单”“历史模拟组合 · 真实净值”等短身份标记说明范围，日期紧邻数据。资料页面真实产品身份与模拟交易身份清楚区分，不把产品名称中的“模拟”字样删除后就丢失身份。

### 4.3 金额、状态与日期

- 金额由已有后端结果提供，保留币种与口径；可动用金额点开查看预留、冻结、应急设置等实际计算依据。
- 本金、持仓市值、总权益、账户现金、应收、损益分开命名。已有 `holdings_only_v1` 与 `total_equity_v2` 语义原样保留，不为了统一页面换算或拼接。
- 数据缺失显示“未知/未覆盖”，有效计算为零才显示 0。局部缺失保留其余已核实数据，不补假数。
- 已记录、计划、候选、待确认、已执行、待结算、失败、状态待核实明确区分。手工完成不等于真实扣款。
- 用户界面的真实时间按 Asia/Shanghai 展示；模拟业务日期另用“参考日期”标明。净值披露日按来源日，不因浏览器时区移动一天。
- 候选扣费、本人陈述、模型推断不冒充确认交易或外部事实。已过期资料保留历史查看，但不作为当前条件。

## 5. 账户：首页与具体对象

### 5.1 首页布局

```text
我的账户                         演示账户 · 参考日期        个人入口

资金概况：当前账本资产/负债 · 可动用资金 · 有证据的收益
                     数值本身可查看口径

我的资金
账户 / 银行卡 / 持仓 / 存款 / 贷款的紧凑对象清单
名称                       金额与状态                    ›

近期安排                                      月份/财务日历 ›
近期应付、到期、需核查及本人待确认事项
日期 · 对象                金额/状态                     ›

转账                   流水与报告 ›           全部活动 ›

统一 Navren 提问输入区：可引用当前选中的对象
```

这是结构示意，不预填用户金额。桌面资金概况、对象清单与近期事项形成清楚主次；标准字号首屏能辨认资金状态、首批对象和至少一条近期事项。首页不挂全部业务表单和全量列表。

对象清单初始最多约 6 行，近期事项最多约 3 条，均有明确完整视图入口与真实总数。大字号自然增高，不以高度限制裁字。对象排序稳定，用户主动选择范围后保留选择。

“可动用资金”必须对应当前工作区/账户/规则。没有可靠市场估值时沿用准确的本金命名，不把原本金总览改名成“实时总资产”。已有收益按具体来源显示，不能借历史组合数据填当前账户首屏。

### 5.2 近期事项

优先展示需核查的执行状态、本人待确认操作、逾期应付和近期到期安排，排序规则确定且可解释。不要为了凑满三条生成建议或把生日写成支出。

同一付款、到期或草案使用稳定 ID，首页与日历只引用一次；显示来源和状态。候选事项可查看核实，不默认计入确认待付。数据不足显示缺口，不根据“没有事项”断言近期无支出。

### 5.3 对象详情

| 对象 | 主要信息 | 按能力出现的操作 |
|---|---|---|
| 现金账户 | 余额、可动用计算、近期流水、关联卡片 | 转账、收款相关流程、资金设置 |
| 银行卡 | 卡片状态、账户/账单、额度与控制 | 挂失、补卡/申请、控制设置；条件与申请状态可回查 |
| 当前持仓 | 身份、本金/份额、估值日期、收益口径、批次与可赎回部分 | 按有效业务规则准备赎回或新申购 |
| 贷款/存款 | 未偿本金/存款本金、期限、下一安排、合同 | 仅现有能力可办理的事项；其余明确只读 |
| 订阅与银行代扣 | 商户合同、代扣协议、下次安排、各自状态 | 分别取消商户订阅或银行代扣，独立确认 |
| 生活计划 | 报价、安排、预留资金、预约/履约与回执 | 现有准备、预留、释放、预约等受限流程 |
| 转账/定时转账/AA/申请单 | 对象、参与人、金额、执行条件、当前状态与轨迹 | 继续待确认、核查状态、按规则取消/登记 |
| 服务记录/账户授权 | 对应服务、授权范围、有效状态 | 现有查询或受限修改入口 |

详情占主内容区，短计算依据原位展开。读对象、进入详情、切换列表不能准备或执行交易。操作准备必须来自用户明确动作。

服务记录、授权、保障缺项与申请状态都保留真实入口。新增卡片通过卡片列表的“申请卡片”文字入口进入，不能因当前无卡而失去申请路径。

### 5.4 流水、报告与活动

流水与报告共享明确的来源和期间，默认先看到收支摘要与明细；切换到分析后呈现分类、异常和趋势。导入入口放在来源选择旁，执行既有预览 → 本人核对 → 提交，显示批次与去重结果。

当前报告通过工作区 `/source` 切换 `active_source`，随后 `/analysis`、`/annual-analysis`、`/transactions` 等请求隐式读取该来源；日历则按请求传入 `source`。实施须让报告请求绑定实际来源及版本，整组响应可以核对同一身份。接口尚未支持显式来源时，不能只恢复前端标签：核验服务端来源与每个响应的来源身份；切源、多窗口修改或身份不一致使旧整组结果失效，重新取得。响应无法证明来源时不显示成所选来源的报告，补齐最小服务端合同后再验收。

操作记录挂在对应对象详情；“全部活动”提供查询完整操作、申请、预约、资金预留与失败回执的主视图。待确认、待结算、状态未知始终能再找到；不能只显示成功交易。

## 6. 财务日历：完整时间工作区

日历为账户子视图，独立占用主内容区。默认月视图；月/周/日/待办使用一个清晰时间视图选择。年月标题可打开日期定位，上一/下一期保留可访问名称。

“收支、收益、生活”是事项类型筛选，同一时间工作区内使用；数据来源和组合另行选择。当前 `calendar_ui.js` 点“收益”会改组合、点其他类型会重置组合/日期，这条耦合需拆开。只改变筛选时保留日期、来源、组合；历史内容不可因为筛选而悄悄跳回当前账本。

来源与组合按已实现的能力配对。导入账单与历史组合等不支持的搭配显示不可用原因，可由用户明确选择另一来源；不能自动换源、填入另一账本数据，或把无覆盖日期显示为零。

- 日格显示日期、已核实金额/损益及少量事项；收益正负沿用已确定颜色与正负号、文字标签，主题色不覆盖收益语义。
- 点击日期在主内容区或原位显示当日明细；每项能继续进入关联对象。长明细分页，日期与汇总仍可见。
- 收支现金流、投资权益损益、分红到账和未来预算分开呈现，避免同一收益或付款重复计数。
- 未覆盖日期显示明确缺失状态。没有记录不等于收益/支出为零，截止日期一直可辨认。
- “回到本月”适用于当前来源；模拟视图标“回到参考月”。历史组合优先“回到最新披露月”，不跳到无行情的今天。
- 新建事件入口清楚可见；导入事件、提醒设置等低频工具放在日历工具菜单。该菜单只能承载日历工具，不能成为全站业务“更多”箱。
- 手工修改、完成或删除事件按原草案/确认规则处理，不改银行流水。银行卡挂失、取消代扣等从关联对象的业务动作进入。
- 日历与目标关联通过目标/事件 ID，并注明关联角色：目标截止日、提醒时间、生活活动日期或银行合同到期日。目标截止日由目标服务维护，日历只是投影；修改须走同一目标写入，先列明影响。提醒和生活活动日期由日历维护，不自动改目标期限；银行合同日期只读。
- 删除提醒不删除目标，删除目标不删除银行交易或合同。关联对象修改携带期望版本，冲突时重新核对，不能覆盖另一页面刚保存的内容或复制出第二个目标。

对话中的日历是相同来源的相关片段，保留当时快照身份。进入完整日历恢复月份、选中日期、事项、来源与组合；最新状态另行查询。旧快照不能当作新交易授权。

## 7. 发现：从了解信息到研究选择

### 7.1 默认内容顺序

1. **市场热点封面流**：占据内容焦点，沿用真实左右相邻卡片、共同跟手运动、首尾循环、键盘与减少动态效果。事件 ID、版本、权威具体原文、收藏与解读保持原合同。
2. **市场周报封面**：期间、标题与最多三项变化，整张封面进入完整阅读；历史期号、完整证据和提问下沉到阅读视图。
3. **产品研究预览**：少量约 2—3 项资料/产品，显示名称、身份、风险和期限，主体可进入详情；标题区域“产品研究 ›”进入完整研究视图。
4. **最近备选方案**：一份正在考虑的安排及状态；完整依据、历史版本和报告在方案详情。

某项不存在时用紧凑真实状态，不把“暂无配置方案”扩成大屏挡住新闻。阅读偏好继续生效，关闭热点/周报后保留相应恢复入口。新闻阅读不强行引向产品申购。

热点完整运动与验收继续以封面流方案为准，不另造第二套卡片组件。原有大目录、旧配置卡和历史推荐折叠列表从首页移入对应研究/方案视图。

默认浏览状态清楚可见“比较产品”文字入口，不依赖聊天、悬停或拖拽。进入比较模式才出现选择框，列表布局不大幅跳动；比较说明显示在当前任务位置，不逐卡重复。

选 2—3 款形成统一比较栏；少于 2 款时说明还需选择，满 3 款限制新增并提示当前位置。移除、清空、退出比较仍可用，离开去详情/对话后保留选择。研究列表允许查看未匹配产品的资料，明确当前筛选条件，不把默认排位解释成最适合用户。

对照按相同字段逐行展示：产品身份/管理人与销售证据、风险、期限、起购、费用、申赎与到账、收益指标的类型和期间、数据日期、来源及缺项。未知风险不能默认 R3。

不能把七日年化、历史区间回报、业绩基准、账户实际损益并排作为可排序的同一种收益率。没有同口径数据就保留各自类型并标缺项，不展示收益赢家。

手机保留对应行关系，名称/字段固定或在容器内横向对照两列；第三款可横向浏览且有清晰提示。对照容器内部滚动，页面整体不横滚。不能把比较退化为互不对应的三张长卡。

### 7.3 产品身份与操作资格

| 对象身份 | 查看与比较 | 准备申购 |
|---|---|---|
| 已核验公开产品资料/真实净值 | 可以，显示证据与日期 | 公开资料本身不具有交易资格 |
| 现行模拟业务产品 | 可以，显示模拟身份与现行条件 | 必须具备实际业务 ID、有效资料、规则放行与账户能力 |
| 当前销售状态未知/不可售/关键条件缺失 | 保留研究价值及具体缺项 | 不生成新申购草案 |
| 历史组合或旧研究方案中的产品 | 查看历史身份、条件与收益 | 不凭历史“在售”或产品名称进入当前交易 |
| 已有当前持仓 | 查询收益与既有权利 | 暂停新申购不等于禁止有效规则下的既有赎回；归档组合另属只读 |

银行 `/products` 与 `/public-products` 属于不同数据合同。展示可统一，业务映射必须显式核验，不按名字、模糊搜索或序号连接。

申购只从产品详情/比较结果的明确动作进入：选择有权限账户和金额 → 准备 → 核对条件 → 本人确认 → 回执。主页预览不逐卡摆申购按钮。条件匹配描述实际核对的维度，不写成“可以买”或完整适当性结论。

### 7.4 备选方案

保存每项产品的稳定标识、来源版本、金额/期限假设、比较条件和证据时间。研究有效状态区分“备选”“待核对”“已过期”；落实进度另从关联操作 ID、有效回执和各分项覆盖情况派生，区分“未落实”“部分落实”“全部落实”。一笔成功不能代表整套多产品方案已落实；受理或待结算继续显示实际状态，不能冒充到账。

浏览器旧研究配置按历史只读方案接入，不能凭名称映射成新基金订单。重新准备操作时重新核对当前条件和资金。查看、保存或生成研究报告不等于申购；已经执行的结果由账户里的对应操作/持仓承接，不维护第二套可独立修改的“执行成功”状态。

## 8. 对话与跨页提问

### 8.1 一个统一提问入口

非对话页面的标题下保留一条紧凑的 Navren 输入区，位置一致。输入聚焦时展开，移动端键盘出现后暂收起底部导航，内容可滚动且不被键盘盖住。对话页使用现有底部输入区；其他页面不再给每张卡都加“问 Navren”按钮。

用户从对象详情或明确选中行开始提问，输入区显示可移除的引用标签，例如“正在讨论：某项持仓”。标签只表示引用当前对象；关闭标签恢复一般提问。仅浏览或滚动经过对象不能自动建立提问上下文。

用户发送后进入对话页，带回来源视图的返回入口。上下文包含稳定对象引用与必要来源/期间，发送前可看见引用；银行账号、金额文本和私人描述不塞进 URL。

### 8.2 回答结构

默认顺序为“简短结论 → 相关内容组件 → 当前最必要的下一步 → 按需展开的依据”。组件沿用日历、交易、对照、目标关系和确认能力。

一条回复通常突出一个主操作，相关选择按当前问题组织；确认、取消、核查等必要动作不受数量限制。去重后续问题、重复的“查看账户”“发送至聊天”与每条回答下相同推荐按钮。

处理过程显示简短用户状态，如“核对账户”“查找来源”“准备确认”；可展开查看真实依据和必要核验结果。模型/工具细节供顾问/演示视角回看，不能把折叠显示误写成不再核验。

原文和模型输出使用安全 DOM 展示，引用资料始终是证据材料。浏览新闻、切页、拖动热点或选产品比较不自动产生模型请求。

### 8.3 对话历史与一次发送

历史回答和日历保留查询时身份、版本、来源与日期，最新状态另取。模型失败保留用户问题和明确失败状态；重复发送由用户主动选择，不能恢复页面时自动重试。

新跨页问题通过一次性上下文引用/草稿传递。旧 `q/action/graph_context/market_kind/market_id` 入口需要兼容转译；打开旧链接可以预填问题，页面加载、刷新、换模式和浏览器返回不自动发送。用户明确提交的一次问题只消费一次发送意图。

私人引用在服务端按当前会话解析；URL/前端传来的身份、金额或权限不是操作依据。切换工作区、删除记忆或撤销授权后清理失效引用，不能用旧聊天 HTML 继续展示已失效私人卡片。

## 9. 我的：长期安排、关系与可管理记忆

### 9.1 默认结构

顶部简洁身份与设置入口；内容重点依次为正在推进的目标/责任、四域财务关系概览、实际需要核实的少量条件。

目标卡显示名称、期限、已安排状态与有关资金联系；点开进入目标详情。没有结构化目标时提供明确创建入口，不先要求填满个人档案。

图谱保留日常收支、财富结构、目标与责任、偏好与认知四个读取视角。概览用四个可点击区域表达联系，选择后深入，保留明确返回概览入口；不在其上叠加一排资料领域菜单。

节点大小、颜色、连线粗细继续按既定可解释指标表达；选中关系后解释金额、方向、期间、来源和含义。交易明细到对应账户，时间安排到对应日历，用户条件到对应资料对象。图谱不维护第二份金额账本。

画布有键盘、路径/列表替代，颜色和三维旋转不能是唯一理解方式。列表替代按主题分组与搜索，不把全部节点/边变成铺满页面的按钮墙。

### 9.2 Navren了解的我

统一入口呈现本人确认资料、聊天陈述、目标记忆与相关观察，显示已确认、待核实、已过期状态及当前用途。统一展示不等于合并不同事实来源或删除审计依据。

聊天中的风险态度、最大回撤意愿、金融兴趣属于本人陈述；浏览器聊天问卷、手动模拟业务风险配置、具有可核验证据的正式风险测评分别显示实际来源和时间。当前手动选择 R1—R5 属于“模拟业务风险配置”；写入名为 `risk_assessments` 的表、带有测评日期或有效期，都不足以证明完成正式问卷。当前不得显示“已完成正式测评”。

正式测评只在具备对应结果与来源证据时展示；未取得的测评状态、有效性或到期日显示未知，不根据模拟设置推算。聊天确认不能改业务等级，金融兴趣不能变成交易资格。

默认突出实际影响当前安排的少量内容。点击对象后查看来源、用途、修改与删除，原始关联编辑作为高级能力保留；不要求用户主动手工连接所有记忆。资料缺项在具体任务需要时提示，移除首屏填满进度条。

已有银行目标成为结构化目标时，记忆引用同一目标 ID；含糊陈述先留候选，不自动转换。两个疑似同义目标需要本人确认关联/合并，不能凭语义相似覆盖。

### 9.3 授权、删除与设置

记忆授权沿用当前默认及既有 API。手动保存和允许对话读取是两个动作，可“仅保存”；首次启用说明实际保存范围、已接入用途与撤回路径，不宣称所有 Agent 已能读取。

撤销授权立即停止对应读取，使旧上下文失效，并取消或隔离旧请求、清除失效组件；保存的数据是否保留清楚说明。保留的数据可以由用户主动进入“我的”按当前权限管理，不自动恢复到旧对话或旧分析。删除明确目标/记忆及派生关系影响，以服务端回执确认成功；已删除内容不能从旧档案、缓存、图谱或浏览器返回再次补回。删除个人记忆不等于删除银行交易。

目标与日历按第 6 节的关联角色修改；涉及目标截止日时先列出变化及影响，再确认。独立生日/提醒不自动生成财务目标或交易，目标完成也不能由提醒勾选推断。

收藏以“收藏与继续阅读”进入完整列表，回到原报道/周报/产品/方案版本。主题、语言、三种模式、字体、音色、朗读、账号管理和数据授权集中在设置；仍能直接键盘/触摸访问。

## 10. 准备、确认、回执：页面改版必须保留的闭环

复用 BankUI 已有准备、对象校验、确认摘要、必要验证、取消、状态核查和回执。界面不会凭点击对象或建议文字直接执行。

| 状态 | 用户看到 | 可用下一步 |
|---|---|---|
| 仅查看/填写 | 信息或未提交输入 | 修改、返回；不显示已建立订单 |
| 待本人确认 | 实际草案对象、账户、金额、条件、有效状态 | 核对后确认、明确取消 |
| 提交中 | 正在确认该操作 | 防止重复提交；保留操作身份 |
| 状态未知 | 尚未核实执行结果 | 按同一操作 ID 查询状态；锁住重复执行 |
| 已执行/已受理 | 实际回执和后续状态 | 查看关联对象；受理不能冒充到账 |
| 待结算/待审核 | 真实待处理状态 | 核查进度，按已有规则取消 |
| 失败/被拒绝/过期/已取消 | 实际结果及原因 | 返回修改或明确重新准备，不能伪装成功 |

关闭确认视图不改变服务端操作状态：待确认草案仍待确认；提交中、状态未知或已执行的操作保留实际状态。提交中或未知状态继续按同一操作 ID 核查，未取得明确结果前不恢复确认按钮。只有明确取消并取得回执才显示已取消。刷新、换模式、返回或数据更新都不能提交旧草案。

从对话、对象详情和活动记录打开同一草案，通过操作 ID 复用，不能每次再调用 prepare 创建新操作。资金、风险、版本等变化后按现有规则重新核验，不能沿用失效摘要。

商户订阅取消与银行代扣关闭显示不同对象、后果和回执，不能合并成含糊的“取消全部”。银行卡挂失、补卡申请、额度申请、资金预留、预约等继续保留各自语义。


这是前端视图合同草案，不是授权令牌。只保存恢复界面所需元数据，不在 URL/本地存储放完整银行状态、验证码或确认凭据。

视图状态按工作区隔离；返回入口仅允许本应用内登记路径。浏览器可见 URL 使用稳定视图/对象定位参数，私人问题和完整上下文以会话绑定引用传递，不能执行任意 `return_url`。

### 12.2 进入和恢复

真正进入对象/完整子视图创建历史记录，初始化和状态校正才替换历史。当前 `lifecycle.js` 全用 `replaceState` 的方式不能原样搬入新路由。

应用返回和浏览器后退均恢复列表位置、筛选、来源、日期、选中对象及焦点。模式切换保留这些元数据，重新布局但不重发问题。比较选择按工作区保留，失效产品退出选择并解释原因。

比较引用逐项记录来源、对象类型、标识和版本，公开资料与模拟产品不能仅靠裸 ID 恢复或映射。来源发生变化时按第 5.4 节核对实际响应，不能只恢复来源标签。

恢复时先核对身份、隐私版本和对象状态，再恢复私人组件；从浏览器页面缓存返回时先遮蔽私人区域，核对通过后恢复。来源数据或对象版本变化后更新状态，保留定位；不能恢复陈旧的确认按钮。工作区切换或授权变化清理失效私人上下文。

正常返回不静默丢失尚未提交输入。离开含改动的表单提供明确的保留草稿/放弃选择；草稿仅保留非敏感输入，验证码立即清除。交易提交身份始终由原操作 ID 承接。

## 13. 实施职责与当前代码的拆分

当前已核对 `account.html/chat.html/recommend.html/mine.html/copilot.html/index.html`，以及 `lifecycle.js/account.js/calendar_ui.js/bank_ui.js/recommend.js/market_ui.js/mine.js/personal_graph.js/design.js` 的相关路径。此核对证明现有结构，不代表此次方案已在浏览器实现。

| 文件/模块 | 实施职责 |
|---|---|
| `index.html` 与现有 NavrenApp 入口 | 首次引导、回访目标、品牌返回、旧入口转译 |
| 六个页面 HTML 与共享样式 | 四项主导航、角色区分、标题/提问区、子视图宿主 |
| `js/lifecycle.js` | 替换十一分区/个人标签的挂载逻辑；兼容旧 hash 和 activate；移出公开目录/档案的混杂归属 |
| `js/account.js` | 拆成首页、对象清单/详情、转账/计划、流水报告、活动控制器；保留业务事件 |
| `js/calendar_ui.js` | 独立时间视图、类型筛选与来源组合；主视图详情与完整状态恢复 |
| `js/recommend.js` / `js/market_ui.js` | 发现顺序、产品研究与备选方案职责分离；沿用资讯组件 |
| `js/bank_ui.js` / `js/bank_client.js` | 继续复用受限操作与状态核验；按对象 ID 打开，处理销毁/重新挂载 |
| `js/chat.js` | 跨页引用、一次发送、回答层级、组件/重复动作整理 |
| `js/mine.js` / `js/personal_graph.js` | 长期安排、统一资料展示、四域探索、设置与授权失效清理 |
| `js/copilot.js` | 顾问视角、交接回看、演示控制；保持数据授权范围 |
| `js/design.js` / `js/help.js` / `js/i18n.js` | 共享外观、可访问控制、问号、发现等新标签与翻译 |

可以新增一个轻量视图路由/上下文模块、对象注册表和可复用列表/详情组件，名称按仓库约定。维持当前前端技术栈与已完成业务底座；不以换框架代替页面整理。

现有 `account.js` 在事件中渲染全部固定容器，拆分后须让未挂载视图安全跳过并按需挂载；不能仅删 DOM 留旧监听器。进入隐藏视图不重复加载全量资料，离开时取消陈旧请求、观察器和事件。

所有私人响应挂载前同时核对工作区、目标视图、请求代次、所引用对象版本和 `privacy_revision`；身份不一致的结果丢弃或隔离。缺少必要版本字段时补齐最小合同，不能当成匹配。撤销授权、删除或切换身份立即推进失效边界，晚到的图谱、对话、报告等响应不能重新挂回旧内容。缓存恢复同样执行核验。

新目标编辑、对象读取或上下文解析如缺少服务端能力，先建立最小读写合同和验证。操作权限、业务计算、证据链、模型主审流程继续由现有后端控制；此轮页面改版不更换模型、不迁移产品数据库、不自动改变记忆读取范围。

## 14. 排版、模式与异常处理

- 保留 Navren 品牌、主题色与已有配色能力。对象列表、指标与证据使用稳定视觉层级；不让全部区域都套大面板。
- 正文优先约 15—17px，辅助来源约 13—14px，行距约 1.5；关怀模式自然放大。字体数字仅为初值，以真实内容和用户设置校准。
- 可触摸动作区域至少约 44px，关怀约 48px；鼠标悬停不是唯一反馈。200% 缩放与小屏布局允许自然增长。
- 每个子视图只有清楚的一层主标题与一个实际主任务；不重复品牌、页面大标题、栏目标题和解释段落。
- 不同状态用文字/符号和颜色共同表达，收益颜色、新闻主题色、风险状态的含义各自稳定。
- 加载保持当前视图骨架。身份/资金无法核对时业务操作不可用；单个来源失败只影响对应区域，不把全部页面替换成重复 Failed to fetch。
- 失败区说明哪部分未取得，并提供对应重试；有效缓存显示真实日期及缓存身份，不冒充最新。空列表、未知状态和服务失败使用不同文案。
- 图谱、热点和长比较页有独立性能边界，正常纵向滚动、文本选择、键盘和减少动态效果始终可用。页面切换不产生不可中断的长动画。
- 关闭面板返回触发位置，返回子视图恢复合理焦点；不把焦点留在卸载/隐藏区域。

## 15. 实施阶段与集成门槛

1. **登记路径与对象**：冻结现有功能映射、稳定 ID、来源和能力清单；建立旧链接适配及视图状态合同。先证明路径不丢失。
2. **共享导航与页面骨架**：按“对话、账户、发现、我的”建立四项主导航与对话默认入口，保留账户首页及对象/日历/报告主内容区；将工作台与演示控制分离。对象详情先保留已有动作。
3. **发现与产品研究**：迁移资讯顺序、预览、研究列表、比较与备选方案，清理两套重复产品渲染。确认申购与已有持仓路径。
4. **我的与跨页对话**：长期目标、关系概览、资料记忆、设置；统一提问引用和返回，核对授权失效。
5. **异常与模式验证**：真实来源、版本变化、未知执行结果、旧链接、各模式/设备；通过任务录屏后交付。

同文件同时间一个写者；共享导航、样式与路由由一个集成人负责，其他模块按互斥范围实施。每阶段完成具体可运行路径后才能移除旧入口，不用未实现的“即将上线”代替现有功能。

不宣称“顾问真权限”“当前渠道在售”“全模型记忆可读”或“当前账户实时收益”已经具备，除非对应服务与实测证据成立。
