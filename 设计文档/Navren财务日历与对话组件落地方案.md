## 1. 执行目标与完成边界

建立一个贯通账户、生活安排、个人记忆与对话的财务日历。用户既能主动打开日历，也能在向 Navren 提问后收到“简短文字 + 可交互日历概览”，点击日期和事项查看详情，继续追问或准备操作。

本轮必须交付：

1. 每日已记录收支、未来缴费及固定开支、生日等生活事件的日历视图。
2. 理财每日损益、分红、到期及到账事项；有完整数据时计算，缺数据时明确显示不可计算。
3. 外部流水 CSV 导入复用、生活事件 CSV 导入，以及手工/对话创建事件。
4. 月、周、日范围的聊天日历卡片；点击查看明细、来源与最新状态。
5. 周期事件、预算、站内提醒、修改/删除，以及与已有记忆/资金安排的受控关联。
6. 权限、金额、来源、重复记录、历史卡片恢复和失败路径的验收证据。

本轮不建设新的完整日历应用，不增加新顶级导航，也不重新设计整站主题。不接真实银行资金、外部账户自动同步、设备日历自动读取、系统通知或短信。ICS/Excel/PDF/OCR 导入和农历换算留作后续扩展，不能在首版页面声称支持。

财务日历是六项业务的共用数据视图与交互入口，不增加一个固定的“日历 Agent”，也不将日历本身宣传为行业首创。

## 3. 用户使用方式

### 3.1 账户页入口

在账户页增加“财务日历”标签/入口，复用现有账户工作区和数据来源选择器。

- 默认月视图，周一为一周起始日；支持上一期、下一期和返回参考日期。
- 可切换月、周、日及“未来待办”列表。
- 类型筛选：收支、理财、缴费/还款、订阅、生活事件；来源筛选见第 6 节。
- 每个日期格最多显示收支摘要及 2 条重要事项，其余显示“另有 N 项”。
- 每日收支和理财损益用独立行展示；不要把收益重复加到收入。
- 点击日期后，桌面使用侧边详情面板；手机使用底部详情层。
- 点击事项后展示来源、金额/预算、日期、状态、关联关系、提醒和可用操作。

### 3.2 对话内组件

用户问“这周要缴哪些费用”“下个月有哪些花钱的事情”“上周每天收支如何”，Navren 返回对应范围的文字说明和日历卡片。用户问单个事项时可直接返回当天或该事项详情，避免强行展示完整月历。

卡片包括：范围、参考日期、来源、统计覆盖情况、摘要、日期格和“查看完整日历”。点击日期直接展开详情，保留对话位置；点击事项继续追问时携带受校验的事项引用。

“再看下一周”“只看固定开支”等操作查询新的视图。日历中的历史汇总与刷新后的实时详情分别注明时间，不能静默改写旧回答。

### 3.3 对话创建事件

示例：用户说“妈妈 11 月 5 日生日，每年提前一周提醒，礼物预算五百元”。

1. Agent 提取日期、重复周期、关系称呼、预算和提醒规则，调用事件草案工具。
2. 展示确认卡：公历 11 月 5 日、每年重复、提前 7 天、预算 500 元。
3. 用户确认后保存日历事件；创建事件不扣款、不自动建立转账，也不自动开启画像记忆。
4. 用户需要预留资金或预约服务时，单独经过已有业务草案、审核和用户确认链。

日期不明确、公历/农历不明确、金额单位不明确，或“每月月底”等规则有歧义时先澄清。明确输入农历时告知首版尚不支持转换，不得当公历保存。

修改周期事件时明确选择“仅这次”“这次及以后”“整个系列”；删除这次不删除整个生日系列。编辑银行生成的缴费/还款条目时，进入对应业务流程，不能直接改变源记录。

## 4. 数据架构：一个服务，多个来源

新增 `financial_calendar.py`，提供日历聚合、范围查询、日详情和事项详情；新增 `calendar_events.py` 管理用户事件、周期、提醒与草案。文件名可按现有目录惯例调整，但必须保留清晰职责。

日历返回的是统一视图：银行业务事实和现有导入流水保持各自权威来源，只在查询时投影为日历条目。不要复制一套银行账本，也不要把视图数据作为支付事实回写。

建议新增持久化表：

| 表 | 关键字段与职责 |
|---|---|
| `calendar_series` | `id, workspace_id, kind, title, start_on, recurrence_json, amount_minor?, currency?, amount_role, relation_label?, source_type, source_ref?, status, revision, created_at, updated_at`；用户事件系列 |
| `calendar_occurrence_overrides` | `workspace_id, series_id, original_on, override_on?, override_payload?, cancelled, revision`；单次修改/取消，普通实例按查询范围展开 |
| `calendar_event_drafts` | 工作区、请求/草案 ID、动作、目标及目标版本、规范化内容、有效期、状态；等待用户确认，不计入日历金额 |
| `calendar_reminders` | 事件实例、提前天数/时间、站内渠道、启停；按工作区与实例去重 |
| `calendar_reminder_receipts` | 具体提醒实例、已生成/已读状态；刷新和重复访问不会重复创建提醒 |
| `calendar_import_batches` | 工作区、批次、文件指纹、校验/提交状态、结果；不长期保存原始文件内容 |
| `calendar_views` | 工作区、视图 ID、请求范围/筛选、查询时间、来源版本、最小快照；用于聊天卡片引用和历史恢复 |
| `wealth_valuation_points` | 工作区/数据集、产品 ID、估值日期、精确净值、币种、来源、状态和修订；支持导入或明确标注的模拟估值 |

已有表具备等效功能时扩展而非重复建设。关联键和查询必须同时校验工作区；不可仅因 UUID 难猜就认为有权限。迁移必须可在旧数据库上原位运行，不能重置现有账户或订单。

统一条目至少包含：

```text
id / occurrence_id / workspace_binding
kind: transaction | investment_pnl | distribution | maturity | settlement |
      bill | subscription | birthday | life_event
title / date / scheduled_date? / time_precision / timezone
currency? / amount_minor? / cash_delta_minor? / budget_minor?
state: recorded | planned | candidate | awaiting_confirmation |
       completed | cancelled | failed | unknown
source_type / source_ref / evidence_ids / source_revision
series_id? / linked_operation_id? / linked_commitment_ids / linked_memory_ids
editable_fields / allowed_actions / generated_at
```

不是所有字段都适用于所有条目。例如生日没有交易金额，预算放在 `budget_minor`；本金到期不是利润；预留额度不是现金流出。

## 5. 时间、周期与提醒规则

- 所有展示使用 `Asia/Shanghai`；源数据带时区时先正常化。纯日期不能伪造具体时刻。
- 返回 `clock_mode` 和 `as_of`。模拟工作区沿用模拟业务日期；普通实际记录模式使用本地业务时钟。相对日期解析、首页参考日期、提醒和日历统计必须采用同一模式，不能混用浏览器今天与模拟日期。
- 首版周期：单次、每周、每月、每年；展开只覆盖请求范围，不预生成无限记录。
- 每月 29/30/31 日和每年 2 月 29 日提供“当月最后一天”或“跳过该期”的明确策略，确认卡展示实际规则。
- 保留原始应付日期。逾期事项可以另外出现在“待处理”列表，不得把所有逾期款的原始日期移动成今天。
- 首版提醒是站内提醒：打开应用/查询时按参考日期计算，提供提前天数、当天提醒、已读和关闭。没有后台任务/系统权限时不能承诺应用关闭后仍推送。
- 事件预算默认仅展示为用户计划。用户明确纳入资金规划后，进入“用户计划情景”；不得直接扣减账户余额。

## 6. 来源隔离、口径与去重

### 6.1 数据来源

流水视图沿用当前“内置模拟账单 / 本地导入账单”选择。首版不把两者叠加为一个财务总额；可以切换查看，并清楚标注选择的来源。用户生活事件可作为独立覆盖层。

未来银行扣费/还款事项归属于模拟账户，用户导入的历史流水不自动成为它们的结算证明。查看导入账单时，模拟银行事项默认不参与该来源金额汇总；主动打开覆盖层后仍分别显示模拟来源。

投资收益也必须绑定账户/持仓与估值数据集。使用外部流水来源时，不把内置模拟投资收益呈现为用户真实收益。

### 6.2 汇总口径

每种币种单独汇总，并区分：

1. 已记录现金流入、现金流出及净流入；净流入不等于账户余额。
2. 消费/经营收入、消费支出、退款、转账、投资本金变动等类别。
3. 已确认未来待付、周期候选、用户预算；不相加后称为“已支出”。
4. 投资损益与已到账分红；本金申购/赎回、估值变化和现金到账分别记录。

账户内转移在单账户视图可反映现金进出，在全账户视图不计为新增收入或消费。身份、方向或账户范围无法判断时显示“未确定”，不猜测。费用单独标识。

没有记录不代表没有消费。每段结果带覆盖期间与 `complete / partial / unknown` 状态；无法确认覆盖的一天空白或“暂无记录”，不填“收入 0、支出 0、收益 0”。部分覆盖的汇总注明“已记录金额”。

### 6.3 去重

- 同一源记录生成稳定日历 ID：来源命名空间 + 记录 ID + 实例日期。
- 周期事件与同一实例的实际结算建立关联；同时显示时只能一个计入对应口径。
- 使用交易/业务引用映射去重；仅相同金额和日期不足以判定重复。
- 日历预算、已有资金预留和承诺通过 `linked_commitment_ids` 关联，复用已有预算工具的去重机制；生日预算不能与其资金预留扣两遍。
- 人工标记“已完成”只改变生活事件状态，不构造支付记录；必须查到银行回执才能称已支付。

## 7. 理财收益的落地条件

当前存在本金口径数据，不能直接得出每日收益。本轮需要补充精确净值/估值、持仓数量、交易及结算记录、分红与费用，并明确估值日期和来源。

实现一个独立的确定性收益计算模块，使用整数金额与精确小数；不由模型加减，不使用二进制浮点累计金额，也不把业绩比较基准除以天数当实际收益。

首版区分“当日投资损益”“累计投资损益”“已到账分红/已实现收益”和“本金到期/赎回到账”。持仓市值不包括已从持仓中移出的现金分红；统一在统计服务里约定交易金额是否含费，避免重复扣费。

在采用不含现金的持仓市值口径时，日损益按下式核对：

```text
日损益 = 期末持仓市值 - 期初持仓市值
       - 当日申购/买入对价（不含费用）
       + 当日赎回/卖出对价（不含费用）
       + 当日确认的现金分红 - 当日确认的相关费用
```

该式需要完整交易和同一口径的估值；已确认但未到账的对价不能显示为已到账现金。缺少初始成本时不展示“成立以来累计收益”；缺少期初/期末估值时日损益为不可计算。已实现收益需依据明确的成本分配规则计算，不将全部赎回金额当收益。

增加至少两个完整模拟估值样本（含买入/赎回/分红/费用）和一个数据不完整样本，均在隔离测试工作区。原有 `principal_only` 产品保持原口径，数据完整且标记为可估值后才启用收益展示。缺数据的异常样本显示缺失原因，不填零。

首版不展示未经校验的收益率、收益预测或全账户收益排名。先确保金额可对账，再扩展收益率口径。

## 8. 外部数据导入

### 8.1 流水 CSV

复用现有模板和 `/statements/preview`、`/statements/commit` 流程，不另建重复账单导入器。导入成功后更新数据集版本，日历重新查询；保留金额精度、方向未知、时间精度、覆盖范围和来源信息。

### 8.2 生活事件 CSV

新增中文模板与预览：

```text
外部编号,标题,类型,日期,重复周期,月份日期策略,预算金额,币种,提前提醒天数,备注
BIRTH-MOM,妈妈生日,生日,2026-11-05,每年,跳过该期,500.00,CNY,7,礼物预算
RENT,房租,固定开支,2026-11-10,每月,当月最后一天,2500.00,CNY,3,手工计划
```

金额为空表示未知；备注和文件内容均为数据，不能当 Agent 指令。固定开支导入是计划，不证明实际支付。

规则：UTF-8、最大 1.5 MB、每批不超过 1000 个事件；严格解析有效日期、周期、金额、币种和提醒范围。预览十分钟过期并绑定工作区，明确新增/更新/重复/冲突与全部错误；有错误或冲突时整批不提交。

外部编号在同一来源/工作区内唯一；相同编号内容变化显示更新差异，经用户确认后更新，不能静默覆盖。无编号时分配本地 ID，并通过规范化内容指纹识别重复导入。提交幂等且使用事务，失败不出现半批数据。事件更新使日历版本变化。

## 9. 后端接口合同

以下为新增接口；路径可按现有风格调整，但一个日历服务同时服务账户页和聊天。

| 接口 | 用途 |
|---|---|
| `GET /api/finance/calendar?from=YYYY-MM-DD&to=YYYY-MM-DD&view=month&source=simulation` | 范围概览与日聚合，返回受工作区约束的视图 ID |
| `GET /api/finance/calendar/views/{view_id}/days/{date}` | 读取该视图筛选条件下的最新日详情 |
| `GET /api/finance/calendar/items/{item_id}` | 读取事项最新来源和允许操作，来源/实例标识由服务端解析 |
| `POST /api/finance/calendar/events/prepare` | 创建/修改/删除用户事件草案，返回差异与有效期 |
| `POST /api/finance/calendar/events/{draft_id}/confirm` | 用户确认元数据变更；需目标版本一致、CSRF 和幂等 |
| `POST /api/finance/calendar/import/preview` | 生活事件 CSV 预览 |
| `POST /api/finance/calendar/import/commit` | 用户确认提交已校验批次 |
| `GET /api/finance/calendar/reminders` | 站内待提醒列表 |
| `POST /api/finance/calendar/reminders/{id}/read` | 标记已读 |

`from/to` 均包含在范围内，首版单次查询最多 93 个日期；月视图网格含相邻月份时也受此限制。明细分页，单页最多 100 条；禁止静默截断。超过范围明确提示分段查询。

返回至少有：`schema_version, view_id, generated_at, as_of, clock_mode, timezone, source_scope, source_versions, range, summary_by_currency, coverage, days, limitations`。筛选未涉及的来源不参与该结果。

日期条目包含已记录/已确认/候选/预算等独立汇总、收益可计算状态、事项总数和少量预览；详情返回完整分页数据。异常时返回标准业务错误和稳定错误码，页面区分暂无数据、权限失效、版本变化、查询失败。

每次请求由服务端会话确定工作区，不能接受请求体中的任意工作区作为授权。所有写请求复用现有同源/CSRF 检查，所有 GET 无写入业务效果。创建视图等内部缓存行为不得改变账户和事件。

版本至少覆盖：账本、导入数据集、事件、估值、规则；不能只使用银行账本版本判断日历是否最新。事务读取或版本前后核验防止混合快照。

## 10. 聊天组件合同与恢复

最终响应增加 `widgets`，保留原有回复、审核、资金时间轴和确认卡合同。组件描述由服务端日历工具产生，模型只能引用本轮已产生的 `widget_id`，不得提供 HTML、JavaScript、任意 URL 或自行编造日历金额。

示例仅展示结构，不是实际客户数据：

```json
{
  "reply": "下面是你选择范围内的财务日历。已记录流水、未来待付和生活预算分别展示。",
  "widgets": [
    {
      "type": "financial_calendar",
      "schema_version": 1,
      "widget_id": "example-widget-id",
      "view_id": "example-view-id",
      "view": "week",
      "range": {"from": "2026-11-02", "to": "2026-11-08"},
      "source_scope": {"statement_source": "simulation", "include_life_events": true},
      "generated_at": "2026-10-04T20:00:00+08:00",
      "snapshot": {"summary_by_currency": [], "days": [], "coverage": "unknown"}
    }
  ]
}
```

该协议同时贯通非流式 JSON 与流式最终 `navren.result`；不得只给流式进度附卡片而最终结果丢失组件。

前端新增 `js/calendar_ui.js` 和 `js/calendar_client.js`，账户页与聊天调用同一渲染器。复用主题令牌、字体模式和已有弹层基础；不要使用模型 HTML 或为本功能引入大型完整日历框架。

历史消息保存最小结构化组件快照、视图参数、绑定标识与生成时间。刷新后用组件描述重渲染并重新绑定事件；旧消息没有 `widgets` 时保持兼容。生成时快照不静默变更，点击读取最新详情并标记其时间/版本。

视图引用过期/失效时保留可读快照和“重新查询”，不保留可执行按钮。跨工作区或会话变更时隐藏私人快照并禁用详情和操作，必须重新取得授权数据。服务端历史与前端显示需要同时支持组件恢复，不能只修浏览器 `localStorage`。

日历按钮用专用 `data-calendar-action`，只绑定一次；修改 `BankUI.rebind()` 的普通跳转选择器，明确排除日历按钮。所有内容使用安全 DOM 文本和白名单组件。

无论鼠标、键盘或触屏都能打开日期/事项；有日期名称、状态文本、焦点管理、Esc 关闭和返回焦点。状态不能只用红绿色区分。关怀版保留更大字号与简化摘要。

## 11. Agent、审核与确认边界

新增工具建议：

- `calendar_query`：按范围/类型/来源查询，返回事实、证据、日历视图与组件 ID。
- `calendar_day`：查看当前工作区视图下指定日期，不能超出视图范围。
- `calendar_item`：查看事项及其允许操作，返回可继续追问的对象引用。
- `calendar_prepare_event`：仅生成事件元数据草案，不提交变更。

在 `answer_facts` 与 `answer_reviewed` 里增加可选 `widget_ids`，枚举限定为本轮工具实际返回的组件。纯事实查询经确定性合同校验后展示；含解释、建议或业务草案时，组件范围/来源和文字一起进入 GLM 审核。审核失败清除本轮组件和未放行草案，并保留明确失败信息。

增加或扩展项目运行时的日历技能说明，讲清范围解析、来源与状态、收益缺失、事件编辑和确认边界。不要再按固定关键词走第二套日历对话路由。

从事项发起“缴这笔费”“预留生日预算”等请求，需要读取最新事项与银行对象，再走已有准备/审核/用户确认流程。用户事件的预算或收款人备注不能成为交易权限；导入的固定开支不能创建未经核验的银行收款人。

当前业务链每轮至多准备一项金融操作，继续保留；不能因为同一天有三项缴费就自动批量执行。账户或事件版本变化、重复确认、草案过期，继续由后端门禁处理。

记录生日属于用户主动授权的日历事件。关联画像/记忆需遵循已有开关与确认规则；关闭记忆后，用户仍可查看自己主动建立的日历事件，但 Agent 不得读取被禁用的画像资料。亲属数据仅保存必要称呼和事件日期，不扩展采集第三人的身份/账户信息。

## 12. 改动范围与实施顺序

执行者先遵循适用的项目协作规范与当前项目指令，并为实施任务声明负责人和精确写入范围；如另一窗口正在修改共享文件，先协调交接或错开写入，不覆盖未提交内容。

推荐改动：

| 模块 | 工作 |
|---|---|
| 新增日历/事件/收益服务模块 | 聚合、周期、草案、提醒、收益核算 |
| `finance_gateway.py`、数据库迁移 | API、身份隔离、来源版本、原位升级 |
| `finance_capabilities.py`、`agent_runtime/bank_tools.py` | 只读目录、原生工具和受限组件枚举 |
| `agent_runtime/conversation.py`、`server.py` | 最终组件、审核包、失败收束、历史持久化 |
| `js/calendar_ui.js`、`js/calendar_client.js` | 共用视图、详情、安全绑定 |
| `js/api.js`、`js/chat.js`、`js/bank_ui.js` | 组件传递、历史恢复、事件排除、继续追问 |
| `account.html`、`chat.html`、`js/account.js`、主题样式 | 加载组件和入口，保持三种模式一致 |
| 测试、README、验收记录 | 计算/接口/浏览器/真实模型验收 |

按以下顺序完成，不等全部界面画完才接数据：

1. **范围读取与正确口径**：迁移、来源投影、日聚合、稳定 ID、覆盖状态、版本及独立计算测试。
2. **生活事件闭环**：手工创建、周期展开、单次/系列编辑、提醒、CSV 预览与确认；所有步骤使用隔离工作区。
3. **账户与聊天共用组件**：月周日、详情层、真实日历工具、JSON/流式最终结果、历史恢复和继续追问；接真实模型完成一条完整路径。
4. **收益完整化与资金关联**：估值样本、损益核算、到期/到账分离、预算去重、记忆关联及失效草案处理。
5. **整体验收**：异常、权限、已有确认链回归、移动端/关怀版与实际加载版本核对。

前面步骤可以阶段交付，但收益全为占位、历史卡片不能点击、对话未调用日历工具，均不能将本轮标成完成。

## 13. 必须通过的验收

### 数据与业务

- 同一源数据下，日历的已记录金额与原账单查询独立对账；月份边界和退款口径正确。
- 内部转移、未知方向转账、投资本金、收益和费用不混算；不同币种不直接相加。
- 外部账单不改变模拟余额；重复导入不重复累计，冲突整批回滚。
- 无记录/覆盖不足/缺净值显示未知或不完整，而非填零。
- 每月末与闰日规则可复现；改单次不改整系列，逾期事项保留原始日期。
- 同一事项在计划、候选、预算、预留和实际结算之间不重复汇总。
- 收益用独立手算样本验证：纯估值变动、买入、部分赎回、分红、费用、缺期初净值和缺成本。

### 权限与状态

- 工作区 A 的视图/事项/草案/导入批次不能被 B 查看或提交。
- 无 CSRF、过期草案、目标版本变化、重复提交均得到正确结果。
- 导入文字含工具指令或 HTML 时仍按普通数据处理。
- 事件保存、提醒已读、纯日历查询不改变余额/订单；资金操作在用户确认前不执行。
- 记忆关闭后普通日历可用，禁用画像不被日历工具间接读取。

### 真实聊天与界面

- 实际聊天页提问产生真实日历工具调用，文字、组件和详情对应同一范围与来源；不能只用硬编码卡片模拟成功。
- JSON 与流式模式都有卡片；GLM 拒绝、模型超时、日历 API 失败时状态真实且不保留未审核组件。
- 刷新后日期按钮仍打开正确详情，不被重绑成账户跳转；多个卡片之间不串日期或事件。
- 修改/删除事件后，旧卡片保留原快照，最新详情显示新状态；需要变更的待确认操作失效并重新准备。
- 同一条“预算改为三百元”能关联正确事件，经确认后更新；事件名相同但对象不明确时澄清。
- 在 390px 手机宽度无横向溢出；经典/关怀/青春版均可用，键盘能完成日期选择和关闭详情。
- 导入后、刷新后、版本变化和不同工作区下分别核对实际加载的前端资源版本。

建议测试文件按项目惯例新增：`tests/test_financial_calendar.py`、`tests/test_calendar_events.py`、`tests/test_wealth_returns.py`、`tests/test_calendar_integration.py` 和组件/聊天恢复测试。资金计算与权限使用独立预期值，不仅复述实现。

保留已存在测试并运行相关回归。浏览器验收使用真正启动的服务和隔离数据库，不只查 DOM 源码；真实模型验收记录阶段、模型、工具、结果及脱敏错误，不记录密钥或隐藏推理。

## 14. 演示与交付物

在固定、隔离的模拟工作区演示：

1. “上周每天收支如何” → 周卡片 → 点一天查看流水及来源。
2. “下个月要缴什么费用” → 月卡片 → 查看已确认与候选区别。
3. “妈妈 11 月 5 日生日，预算五百元，每年提醒” → 事件确认卡 → 保存 → 日历出现；改预算后重新确认。
4. 导入一份事件 CSV → 预览 → 确认 → 卡片刷新；重复导入不重复出现。
5. 有估值样本的持仓展示可复算损益；本金口径样本显示暂无收益数据。
6. 从事项准备一笔模拟操作 → 用户确认 → 查询回执 → 日历更新；截图和账本证明确认前未执行。
7. 刷新旧聊天 → 原卡片可恢复、可点击；切换工作区后旧私人数据不可继续访问。

完成后交付：

- 可运行代码与兼容旧数据库的迁移；导入模板；更新 README。
- `设计文档/Navren财务日历实施与验收记录.md`：实现范围、未完成项、运行命令、实际前端版本、测试结果和限制。
- `outputs/calendar-acceptance/`：隔离样本、独立金额对账结果、接口/模型结果摘要、电脑和手机截图；只保存最少必要模拟资料。
- 明确列出通过与失败的检查，不用代码改动数或模型一句“成功”替代验收。

本方案交接无需再次讨论布局和主线。执行者自行解决常规实现选择；遇到现有模块冲突、无法确认的数据语义或用户授权缺口时，保留事实边界并说明具体阻塞，不能静默猜测。
