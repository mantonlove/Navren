# 银行服务条件与费用协商

## 工作方法

1. 先明确希望降低哪类费用、愿意接受的条件及明确拒绝的附加要求。本人愿意迁入工资是陈述条件，不证明工资已经迁入；不因优惠替用户购买理财或改变账户设置。
   工资迁入条件按基座返回的同意、拒绝、未确定处理。询问、转述、条件承诺、否认曾同意或相互矛盾的话不能自行当明确同意；未确定只阻止依赖该条件的工资方案，可继续核验独立电子账单方案。不得将另一项服务的同意借作工资同意。
2. 用 `service_offer_rules` 读取合成规则版本、有效期、费用/价值、资格、持续月份、要求和限制。只按返回规则描述可选择条件，不创造优惠、扩大有效期、改变价格或自称代表真实银行报价。需要账户资格背景时才读 `account_summary` 或对应 `customer_records`，不读取无关个人档案。
3. 对每个实际选项说明收益、需要承担的条件、是否附带工资迁入或购买要求、期限以及仍待核验资格；优先尊重用户拒绝理财等明确条件。允许保留原服务、暂不申请或先核实成为结论。费用总额仅引用工具已给数值，不能自行把条件利益当已到账收益。
4. 用 `service_offer_preview` 按本轮原话核验可选方案；不代写条件，固定不披露个人记忆。同轮重复调用复用预览，新轮替代由现有服务处理。该预览不是金融操作或申请提交；金额自由解释仍须正式指标，缺指标时只说明条件与缺项。需要继续时通过 `answer_reviewed` 给出现有工作台的下一步，由本人选择是否披露获准记忆并独立确认申请；不得调用 `prepare_operation` 伪造服务优惠订单。
5. 已申请后的问题先调用 `service_application_status` 读取本人真实回执。`submitted_simulation_pending_eligibility` 仅为已记录申请、资格待核验，不能称优惠获批或费用已减免。查询状态不重新准备预览、提交申请或修改条件。规则、预览到期/替代和回执变化需重新核验，不能沿用上一轮批准文本。

## 输出与回退

输出需求、可比条件、规则来源/有效期、拒绝项及一个下一步。说明“预批准合成规则下的条件申请”与“真实银行报价/核批”区别，不宣称已经谈成、申请成功、资格获批或费用已减免。没有真实报价只提供原型方法和待核实项，不能给出最新银行收费事实。

规则不可用、过期或无符合条件选项时说明原因，不补一个默认优惠。用户没有同意披露个人条件时不向其他角色发送财务记忆；开启对话记忆不等于协商披露授权。借贷、保险和保障问题仍只读实际档案，没有真实贷款审批、投保或理赔能力。分析事实经 `answer_reviewed` 引用本轮证据，规则核验与模型审核都不能替用户确认。
