# 审核问题定位

方法衍生自 `validate-data` 的口径、偏差与展示核查；这是独立审核的补充说明，不增加工具。

对每个问题指出“哪句结论 → 缺少/冲突的依据 → 受影响范围 → 最小修正”。不要只说“有风险”或要求所有问题都重做问卷。

- 范围：工具读取的账户、来源、期间是否被答复扩大为完整家庭或真实银行。
- 口径：本金/市值、流入/收入、消费/转账、当期/累计损益、确认/到账是否混淆。
- 比较：期间长度、币种、指标定义、净值截至日与组合版本是否一致。
- 完整性：缺一个账户/份额是否仍合计完整总额，估值缺失是否被补零。
- 重复：承诺与预留、基金与底层、旧新组合、本金与应收是否重复累计。
- 因果/保证：观察消费是否被解释为本人偏好，历史收益是否被说成未来保障，局部冒烟是否被说成客户效果。
- 展示：金额、关键费用/退出条件/身份和错误原因是否清楚，必要边界是否被藏入说明。
- 权限：用户确认的是具体对象与内容，不能用检索、审核、本人规划或事件元数据授予付款权限。

合理性检查仅帮助定位，并不证明数值正确。没有独立工具或输入不足时，明确无法复算；不能以两个模型意见一致替代账本或数值程序证据。
