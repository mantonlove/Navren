# 财务诊断

方法适配自 `anthropics/claude-for-financial-advisors` 的 `prospect-intake`：保留资料归一、范围界定、重复与缺项检查、原始读取与分析判断分开。上游版本/许可由 `skills/upstream/provenance.json` 登记；不继承外部 CRM、邮箱、连接器或美国账户制度。

## 触发与必要读取

整体财务梳理、投资前诊断、负债或保障缺口分析使用本技能。简单查余额只读 `account_summary`，不强迫用户完成问卷。
读取 `account_summary` 确定账户来源、币种、已结算现金、持仓本金和正式画像。用户仅问当前现金与近期支出压力时，`account_summary`、所选账户的 `budget`、所需期间的 `cashflow` 已足够，默认不再读月报、全量图谱、家庭和保障档案；答复聚焦这些结果与未来收入/未录入支出的覆盖缺口。用户问消费原因或完整财务状况时，再用 `statement_source` 及相关月/年报。负债/保障问题仅查相关 `customer_records` 域；跨目标/图谱关系才读必要 `personal_graph`。用户记忆仅在开启且本题需要时读取。

## 分析顺序

1. 明确本次账户、期间和用途。当前接入银行资料是本机模拟账本，不能称为真实银行同步；导入流水是用户提供的独立账单，不能证明当前可用余额或完整资产。
2. 分开整理现金、投资、应收、负债、已确认义务、候选支出和外部未接入资产。不同币种分列；本金持仓没有完整估值时保持市值未知。
3. 解释收支口径与覆盖月份。退款按来源口径列示，借款不算工资收入、内部转账不重复算消费；部分月份不能外推全年实际总量。未来时间轴 `confirmed_inflow_minor=0` 仅指该期间没有已确认未来入账，不证明没有历史工资、不证明用户无收入，也不证明收入档案缺失；没有读取的月报/贷款/保险字段应说“本次未核实”，只有工具明确 unavailable 才能说“未接入”。缺少未来收入不会使压力更小，不能把缺项当乐观依据。
4. 用 `budget` 查询可安排资金，用 `cashflow` 看已确认/候选事项的时间压力；现金流 `current_available` 尚未扣未来到期事项，不能代替当前预算。预算是未来30天已知到期款口径，压力推演使用用户所需期间，两者分别说明。不自行相减生成账户结论，不把未来工资、信用额度或赎回未到账额作为现有现金。`budget.investable_minor` 以及现金流的 `available` 金额已扣应急底线/生效预留，不能再与应急保留额比较或再扣一次；现金流 `minimum_available` 为零时才触及已设置底线，为负时才出现底线缺口，优先引用工具的 `confirmed_floor_breached`。正的底线外余量不能说成“应急线附近没有余量”。
5. 分开风险意愿、承受能力和正式测评。本人陈述是条件，行为观察是线索；财务能力评估不能更改正式风险等级。目标、家庭责任或保障条款缺失就说明，不猜亲属与责任分担。
6. 按影响程度给出应先核实或处理的问题，再交给目标规划/产品研究。没有已核实必要生活支出、收入稳定性、目标和期间依据时，不能仅凭一个余量定性“缓冲很薄”或“应急金足够”，只能说已知事项下有没有底线缺口、充分性尚待核实。未录入支出可能增加压力，不能确定“实际压力一定高于账面”。单笔大额消费不证明一次性、不证明本人偏好；未经本人确认只列条件。目标的已积累 `saved_minor`、确认分配和真实预留分别说明，不能把目标记录称为已分配现金。诊断不自动生成配置比例、产品购买或保障缺口金额。

## 用户输出

先说当前最影响决策的一两点，再简要说明已知条件、关键缺项和下一步。默认简短回答资金、近期压力和两三项关键缺口，不把全部档案铺开；用户要求详细再展开。只声称本轮工具实际查询过的资料，没查账户不能写“未查到入账”，应说“本次未核实到账”；持仓退出须逐项对应本金与锁定日期，不能把汇总本金套用单一持仓日期。标明来源、期间及“已记录/本人确认/待核实”；分析用 `answer_reviewed`，事实引用本轮证据。缺失不写零，不给没有依据的完整性分数。

## 降级与授权边界

资料缺失时完成已有部分，只询问改变结论的必要条件；不能为填满表格造持仓、成本、收入或家庭状况。附件未解析时明确不能读取其中内容。诊断不保存新画像、不修改账户、不准备付款；转入操作技能须有用户明确的新动作请求。
