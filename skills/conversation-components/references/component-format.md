# 只读轻组件协议

这是客户端的容量和格式合同，不是每轮必读的设计流程。最小语法已放在 SKILL.md；接近字段容量或不确定表格格式时再查这里。以下仅示范当前 schema 允许自由正文时，将成组内容写进 `answer_reviewed.text` 的已知 Markdown 围栏；受控字段、严格引文及金融值槽模式不使用这些围栏，继续原合同。下面只是排版示例，不是用户资料。正文其余部分继续用普通 Markdown。客户端不接受模型的 HTML、CSS、脚本或动作。

## 要点：同一问题的几个条件

```navren-facts 出行条件
日期 | 尚未确定 | 先确认能连续空出的时间。
同行人 | 两人 | 此为示例条件，实际以用户补充为准。
```

每行 `标签 | 值 | 可选说明`。标签不超过32字，值80字，说明140字，最多6行。不要在值后追加操作参数。

## 对比：相同维度看差异

```navren-compare 两种安排方式
维度 | 提前安排 | 临近再定
适用情况 | 日期已经确定 | 日期仍可能变化
先核对 | 退改条件 | 可选余量
```

首行是2至4列表头，随后1至6行，各行列数一致。表头各40字、单元格各120字以内。可使用普通 Markdown 表格的分隔行；不要把原文没有的字段补齐。长表拆成更有意义的小范围或普通解释，不缩字塞满。

## 步骤：需要有顺序的方法

```navren-steps 整理资料
确定范围 | 先说明要解决哪个问题。
核对依据 | 把已有资料与待补充项分开。
形成安排 | 确认条件后再确定下一步。
```

每行 `步骤名 | 说明`，名称40字、说明160字以内，最多6行。这是方法顺序，没有勾选、提交、已完成等办理状态。

## 旁注：一条必要的限定

```navren-note 适用范围
这是一份条件化的整理，缺少的资料需补齐后再判断。
```

旁注正文最多400字。标题放在围栏首行类型后，可省略，最多40字。所有组件只接受纯文本，内容内不要再嵌套 Markdown、围栏或管道符分隔以外的参数。

每个块总长最多2400字；每条回答最多渲染两块。未知类型、超限或格式错误将完整回退为普通代码块，不能靠前端截断、删除条件或省略数字补救。用普通段落可随时替代组件。不要让客户端自行计算比例、收益、合计或状态。
