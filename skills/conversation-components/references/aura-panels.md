# Aura 面板的 Navren 原生协议

这是对用户提供的本地 Aura Panel 机制的适配，当前输出为受限 JSON，不输出 Aura 的 HTML 或 a-* 标签。模型只提供内容，由 Navren 固定组件控制结构、主题和字号。面板放在允许自由 text 的终结正文中，仍经原审核；受控金额、引文和事实槽模式不使用。

先写一两句直接回答及关键限制，再按需要输出一次：

````text
```navren-panel
{"title":"准备安排","summary":"先核对节点，再逐项整理","blocks":[{"type":"timeline","items":[{"at":"周五上午","title":"核对资料","detail":"先确认原始清单，尚未办理。"},{"at":"周五下午","title":"整理提交稿","detail":"条件核对后再准备。"}]},{"type":"checklist","title":"阅读核对","items":[{"text":"时间与对象是否一致"},{"text":"需要的限定条件是否完整"}]}]}
```
````

这里只示范格式，不是用户计划。主回复的结论和关键条件不能依赖展开后才看得到；summary 简要说明里面是什么，不复写标题或夸大执行状态。

## 可用积木

面板对象只有 title、可选 summary、blocks。title 非空≤40字，summary≤120字，blocks 1至3项。每块都有 type，可选 title≤40字；字段均为纯文本，字段内不含控制字符。每块只使用下面所列字段：

| type | 内容字段与边界 |
| --- | --- |
| text | text：非空文字≤600字 |
| metrics | items 1至3项：label≤40，value 为非空字符串≤80；可选 unit≤12、note≤160 |
| timeline | items 1至6项：at≤40、title≤80；可选 detail≤160 |
| checklist | items 1至6项：text≤120；可选 detail≤160、due≤40。没有 done、状态或执行字段 |
| progress | items 1至6项：label≤40、value 为0至100的有限数值；可选 note≤160。value 是已提供的百分比，不从其他数字补算 |
| bars | 可选 unit≤12；items 1至6项：label≤40、value 为0至1e9的有限非负数。只计算绘图几何，不生成合计、占比或新事实 |
| quiz | items 1至5项：question≤120、answer≤300；内容须来自已有资料，不暗示已掌握或已完成 |

整段 JSON 最多6000字，包含标题、摘要和所有内容。除明确可选字段外都必填且非空；可选字符串可省略或传空串。字段与类型必须精确，不填颜色、尺寸、HTML、链接、事件、路径或工具参数。未知字段、超限、非法数值和坏 JSON 整块回退保留原文，不靠删条件补救；格式不适合时直接改用普通文字或已有轻组件。

## 选择与分工

多个可比较数值适合 metrics；日期本身重要才用 timeline；需要查看比例变化且已有百分比才用 progress；只有两三个已知值需直观看差异才用 bars。用户仅问一个数字时不额外做面板；未知较多时只说明改变判断的缺口。

面板默认收起，用户可以展开或收起；清单勾选仅用于当前展示的阅读核对，不写回任务或银行。自测仅展开答案，不自动发送消息、保存成绩或调用模型。文件、追问、确认和业务状态使用已有正式入口。不要为了面板读取无关账户、制造数据或切换终结模式。
