# Navren模拟银行

这是独立模拟银行数据与业务服务。第2版建立一个虚构零售客户的银行完整档案，覆盖国内六类赛题所需数据，以及身份授权、存款、信用卡、贷款、理财和安全记录。使用Python标准库和SQLite，不依赖官方银行API或大模型。

数据结构参考Apache Fineract、IBM公开合成数据结构和Open Banking资源定义。55类补充客户实体与现有账本分表保存；只有7条Fineract官方示例客户属于导入的第三方样例，并存放在独立参考表。演示客户及其金额全部由Navren模拟，不能宣称来自真实银行或IBM完整数据集。来源、固定版本及许可见[第三方来源说明](THIRD_PARTY_NOTICES.md)。

## 启动与验收

在克隆后的 `Navren` 项目目录运行：

```sh
python3 -m simulated_bank serve --port 18766
```

服务只监听 `127.0.0.1`，健康接口为 `http://127.0.0.1:18766/health`。默认数据库保存在本机状态目录，也可用 `--db /绝对路径/bank.sqlite3` 或 `QINGZHOU_SIM_DB` 指定。数据库应始终位于现有静态网站目录之外。

```sh
python3 -m unittest discover -s tests -p test_simulated_bank.py -v
python3 -m simulated_bank.demo --base-url http://127.0.0.1:18766
```

验收脚本通过实际HTTP接口新建独立工作区，验证账单、关闭代扣、授权申购、重复确认、安全拒绝和最终状态；凭证与验证码只保留在进程内存，运行证据不含这些内容。每次新建工作区都会复制一份完整演示数据，不覆盖之前的业务状态。

## 模拟数据

样本固定于2026年10月3日，不会随电脑日期自动漂移。6至9月共101条流水，包括工资、消费、退款、三种周期扣费、重复扣费、大额异常及一条用于测试提示注入的备注。模拟工作区有两个账户、六个产品、三份银行侧代扣协议、两笔期初持仓和独立风险画像。

期初现金合计16,500元，加上账本净变动后现金为24,390元。期初持仓本金8,000元，初始资产总计32,390元。期初现金和期初持仓分别登记，所有后续申购、赎回及结算均可对账。流水收支结余与账户当前余额分别返回。

补充档案还包含2025年1月至2026年5月的136条封存流水、34份账户月结、2,000元模拟信用卡负债和6,000元模拟贷款剩余本金。封存账本最后期末与活动账本期初衔接，全年消费统计可以回溯；信用卡、贷款独立登记，不重复加入活期消费或现金余额。净资产采用本金口径。没有抵押物是该客户的实际模拟状态，覆盖报告明确解释0条记录。

金额使用整数人民币分，例如5,000元写作 `amount_minor: 500000`；浮点数、布尔值、负数及不支持的字段均拒绝。当前仅支持人民币。

## 已实现接口

接口前缀为 `/api/sim-bank`，与现有 `/api/agent` 和主应用的同源 `/api/finance` 分开。

| 接口 | 职责 |
|---|---|
| `POST /workspaces`，请求体 `{}` | 创建工作区并返回一次性可见的用户凭证、Agent凭证和模拟验证码 |
| `GET /capabilities`、`GET /snapshot?month=2026-09` | 查询能力、同版本账户快照、月报、异常、周期扣费及持仓 |
| `GET /transactions?month=2026-09`、`GET /analysis` | 原始流水与月报，消费、退款、转账及投资流转分别计数 |
| `GET /anomalies`、`GET /periodic-charges` | 返回规则版本和关联流水号；固定生活支出与疑似订阅区分 |
| `POST /periodic-charges/{candidate_id}/mark` | 用户确认或忽略候选；只保存本地判断，不改银行代扣或商户合同，Agent凭证拒绝 |
| `GET /products`、`POST /products/compare` | 产品风险、期限、起购与流动性比较；返回画像不匹配理由 |
| `GET /profile`、`POST /profile` | 查询画像；用户凭证明确确认后修改，旧操作确认随版本失效 |
| `GET /mandates`、`GET /holdings`、`GET /orders`、`GET /snapshot` | 查询代扣、持仓、订单；账户快照同时包含银行卡、交易控制、信用账单、挂失事件及申请记录 |
| `POST /operations/prepare` | 为理财、转账、定时转账、AA、订阅、资金预留/释放、服务预约及卡片操作冻结对象、金额、业务版本和五分钟有效期；幂等重放返回同一操作 |
| `POST /operations/{id}/verify` | 用户凭证加模拟验证码，获取绑定该操作、最多两分钟有效的验证凭证 |
| `POST /operations/{id}/confirm` | 用户明确确认；理财操作还需验证凭证；原子执行业务并保存回执 |
| `POST /operations/{id}/cancel`、`GET /operations/{id}` | 取消待确认操作、查询已保存的执行状态 |
| `GET /audit` | 查询权限判断、拒绝、执行及结算事件，不保存凭证或验证码 |
| `GET /customer-archive` | 同一事务读取客户全档案、全部六场景覆盖矩阵、资产负债及资金核验 |
| `GET /data-contract` | 查询55类实体字段类型、关联、来源、空值定义与排除范围 |
| `GET /annual-analysis?year=2025` | 汇总封存与活动流水；2025完整年度，2026只覆盖已记录月份 |

准备操作还支持 `transfer`、`schedule_transfer`、`cancel_scheduled_payment`、`request_split`、`collect_split_payment`、`cancel_subscription`、`reserve_funds`、`release_funds` 和 `book_services`。所有写操作都先生成短时确认卡；转账/收款/预约只改本机模拟账本，不发送消息或访问外部银行、联系人、商户和服务商。转账再次核验收款人状态、单笔/日限额、近期应付款、生效预留及应急金。定时转账只有推进模拟日期到期后才执行，并重新核验限额和流动性；失败会记录原因且不扣款。AA请求只是本地记账，登记收款表示演示者手动模拟到账。取消模拟商户订阅与关闭银行代扣是两个独立操作。资金预留先占用可用额度但不扣款，预约确认时一次扣款、消耗预留并生成预约记录。

卡片交易开关与限额在用户确认后更新本地模拟状态；挂失会关闭该卡全部开关且不可逆。办卡/补卡与提额先提交申请，日期推进后按合成KYC和收入上限规则审核；通过时生成合成卡片或更新合成额度，不构成真实银行授信或发卡。客户端不能传权限等级改变后端判断；交易开关及关闭代扣为黄色确认，其余资金、订阅和卡片写操作要求红色确认与模拟验证码。

## 授权与执行

`session_token`交给用户确认界面，`agent_token`交给Agent工具适配器，两者通过 `Authorization: Bearer <凭证>` 使用。工作区创建还设置HttpOnly、SameSite=Strict的用户Cookie。不可把用户凭证、模拟验证码或验证码返回值加入模型上下文。

Agent凭证只可查询、比较产品、准备操作及取消待确认操作。它无法修改风险画像、调用验证或确认接口，后端直接返回403。模拟验证码是为了演示额外验证流程，不是真实银行身份认证；错误三次会锁定验证60秒。验证凭证绑定具体操作和数据版本，确认后消耗。

确认请求必须包含 `confirmed: true` 与准备阶段返回的 `confirmation_digest`。理财操作还需要 `verification_token`。对象、金额、余额、画像或模拟日期变化后应重新准备，不能复用旧确认。同一操作多次或并发确认只记账一次；幂等键相同而内容不同会报冲突。

申购扣减模拟现金、增加模拟持仓并生成订单与流水。即刻赎回增加现金；延迟赎回先扣减持仓，记录待结算金额，不立即增加现金。关闭代扣只改变本模拟银行协议状态，商户合同保持 `unchanged`，不删除历史消费。

演示者可通过账户页显式确认推进本机模拟日期；CLI也可用于独立服务：

```sh
python3 -m simulated_bank advance-day --workspace <工作区ID> --days 2
```

主应用的 `/api/finance/simulation/advance` 需要用户会话、CSRF和 `confirmed: true`；它不是Agent工具。独立服务可用CLI推进。日期推进会逐日处理到期赎回、已确认定时转账、模拟卡片审核及过期资金预留，并记录审计。到期订单与定时支付均只执行一次；初始90天产品锁定至2026年12月14日，未到期赎回会被拒绝。

## 主应用接入

主应用由 `server.py` 通过 `finance_gateway.py` 绑定同源用户会话，账户页提供操作表单与回执；`finance_agent.py` 只可生成草案，不能调用验证码或确认接口。六类比赛场景的关键本地流程均由用户在独立确认卡中授权，执行后可查询操作、流水、状态和审计。CSV导入只影响账单分析来源，不会改写模拟银行现金、持仓、代扣、卡片或订单。

对比赛展示时应把数据出处、模拟边界和可核验成果直接展示出来。合成客户和业务状态由Navren生成；第三方项目只提供表结构或合成样例参考，不代表机构认可或真实客户数据。`capabilities.enabled`描述已经可执行的模拟流程，`unavailable`保留真实银行、真实资金和外部审批等边界。

## 数据版本与升级

启动时自动运行原位事务迁移，将首版汇总持仓转成金额相等的`legacy_aggregate`批次。原始买入时间不可恢复，所以记录为空，不伪造历史批次。迁移不改已有客户凭证、余额、流水、代扣、订单和审计。已有数据升级前使用SQLite备份API生成`<数据库>.before-v4-<时间>.sqlite3`，含WAL已提交数据；失败回滚并保留备份，成功再次启动不会重复补充记录。v4扩展支付指令、AA、订阅事件、卡片审核及预约任务的状态约束，并保留原有档案行。

工作区记录核心样本与档案生成版本的哈希。新样本只影响以后新建的工作区，不重置旧数据；已有产品ID的条款不可随样本改动而覆盖，应使用新产品ID或明确迁移。未知高版本数据库拒绝降级。后续新增业务仍可能需要加字段或迁移，无法保证任何未来需求都永远不调整数据库。

已购批次保存原始金额、剩余金额、买入日期、独立锁定期和订单；赎回从合格批次按先入顺序扣减，保留批次与赎回订单关联。`holdings`保留兼容汇总，汇总锁定日不能作为整笔持仓可赎回的判断依据。

若选择HTTP适配，现有后端负责同源代理和工作区绑定；本服务拒绝跨站请求且没有通配CORS。现有主服务器监听外网的方式不适合直接暴露模拟凭证，应在接入本模块时落实本机限制和会话归属。用户确认页面收到具体操作卡片后，用用户专用凭证调用验证和确认，最后由Agent重新查询操作、余额与持仓。商户名和账单备注始终作为数据，不作为工具指令。

接入验收顺序：同一工作区读取账单 → 查看异常与周期扣费证据 → 用户关闭模拟代扣 → 查询关闭状态 → 比较模拟产品 → 准备理财操作 → 用户验证与确认 → 查询订单、余额、持仓 → 重复确认不重复扣款 → 改画像后旧确认被拒绝。

## 范围与限制

未接入真实银行、真实资金、真实商户合同取消、真实发卡／授信审批、外部服务预约、价格与收益数据。卡片控制、挂失、审核及申请只改变或记录本地模拟状态。持仓以本金记账，模拟净值固定为1元，未计算费用；按独立批次判断锁定期。赎回结算使用日历日，并未建真实交易日历。周期扣费识别给出预计日期；订阅提醒仍是草案，没有后台真实扣款或发送提醒。

“完整”指这位虚构零售客户和已列明六场景的数据合同，不是任何银行的所有内部表。支付密码、密钥、CVV、完整身份号码，银行资金池、监管报送全库及银行不知道的外部资产不在档案内。不存在的业务对象、未知值与尚未执行的业务分别标记，不能以造满表格代替真实状态。

工作区凭证仅服务于本机模拟隔离，不构成生产身份认证。服务无需任何模型或银行密钥，适合先验证业务状态和权限机制；公共部署和真实金融机构适配需要另外设计。
